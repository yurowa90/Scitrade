# Scitrade 개발자 관점 통합 제안

작성일: 2026-10-05. 이 문서는 플레이 영상 자막 분석에서 얻은 문제를 **Scitrade의 상태·데이터·검증 설계로 옮긴 제안**이다. 원작 게임의 소스 코드나 내부 알고리즘을 확인한 설명이 아니다. 실제 프로그램 코드와 새 경제 계수는 추가하지 않았다.

기존 개발 자료의 `docs/ai/WORKFLOW.md`, `docs/IMPLEMENTATION_PLAN.md`에 있는 단일 경제 엔진, 직원 예약, 거래 원장, 단계별 구현 원칙을 유지한다. 기존 여섯 능력치·직원 ID·성장 규칙을 재정의하지 않는다. 이후 코드 세션에서는 실제 저장소의 최신 지침과 구현 상태를 먼저 대조한다.

## 1. 직원 한 명을 여러 작업 용량으로 세지 않기

| 데이터 | 담을 내용 | 따로 두는 이유 |
|---|---|---|
| 캐릭터 정의 | 종족·외형·기본 능력·설명·콘텐츠 ID | 도감 발견이 실제 고용을 만들지 않음 |
| 고용 상태 | 직원 ID, 채용일, 계약·급여, 현재 성장 상태 | 같은 캐릭터 원안과 실제 직원의 상태를 구분 |
| 자격·직무 적합성 | 이수 과정, 업무 자격, 주·보조 직무 | 능력치가 높아도 필수 자격을 자동 충족하지 않음 |
| 조직 소속 | 부서·상설팀·직책 | 소속 변경과 실제 업무 예약을 구분 |
| 시간표·위치 | 근무·교육·휴식·이동의 예약 구간, 현 위치 | 복수 자격이 실제 가용 시간을 늘리지 않음 |
| 프로젝트 배정 | 계약·작업 ID, 역할, 참여 시간, 확정 여부 | 저장한 편성안과 실행 중인 팀을 구분 |

직원 카드에는 “배치 가능한가”와 “적합한가”를 나눠 표시한다. 자격을 가진 사람이 교육 중이면 해당 시간의 작업에는 배치할 수 없다. 같은 사람이 영업과 법무 자격을 가졌더라도 겹치는 두 작업을 동시에 수행하지 못한다. 장시간 부재와 영구 결원을 구분하면 불필요한 채용도 줄일 수 있다.

근거: [Software Inc. `wecm-YcecSA` 21:48–23:10](https://www.youtube.com/watch?v=wecm-YcecSA&t=1308)에서 복수 역할 때문에 인력 여유를 잘못 판단할 뻔한 해설, [Two Point Hospital `aba_ChvHoDY` 12:00–13:38](https://www.youtube.com/watch?v=aba_ChvHoDY&t=720)에서 교육 중인 직원인지 확인한 뒤 추가 채용하는 해설.

## 2. 계약의 상태와 돈의 상태를 분리하기

계약 흐름은 **견적 작성 → 실행 가능성 검사 → 수주 확정 → 조달·운송 예약 → 출발 → 인도 → 종료**로 둔다. 선적 전 취소, 납기 지연, 고객의 지연 수락은 별도 분기로 기록한다. “인도 완료”를 “대금 수금 완료”와 동일하게 처리하지 않는다. 매출 인식·채권·수금은 연결된 재무 사건으로 관리한다.

견적 화면의 예상치는 승인 시점의 확정값이 아니다. 확정할 때 자금, 필수 자격, 직원 시간, 출발지 재고, 창고 공간, 운송 용량을 **현재 상태로 한 번 더 검사**한다. 두 계약이 같은 여유 자금을 보고 동시에 승인되더라도 실제 예약은 한 번만 가능해야 한다. 일부 예약만 성공한 상태를 남기지 않고 전체 확정 또는 전체 철회로 처리한다.

교육도 같은 예약 체계를 사용한다. 수강자뿐 아니라 사내 강사, 시설, 교육비를 확인하고 확정한다. 교육 취소나 계약 취소 시 예약 해제와 환급은 명령 ID별로 한 번만 반영한다. 고객 소유 화물과 회사가 매입한 재고는 소유자부터 구분한다.

근거: [Software Inc. `XqSQaMBzm2k` 07:28–09:00](https://www.youtube.com/watch?v=XqSQaMBzm2k&t=448)의 수주 후 전문 인력 부족, [Two Point Hospital `nZb5ZgCrYDs` 07:44–09:25](https://www.youtube.com/watch?v=nZb5ZgCrYDs&t=464)의 부족 직무에서 교육 계획을 좁히는 흐름.

## 3. 내부 운송을 회사 매출로 기록하지 않기

원장에는 외부 매입·외부 판매·운송주선 수수료·임금·설비 투자·회사 내부 재고 이동을 구분한다. 내부 이동은 위치와 관리 부서가 바뀌는 사건이며 새로운 외부 매출이 아니다. 부서 성과를 위한 내부 정산을 도입하면 회사 전체 손익 집계에서 제거할 수 있어야 한다.

거래 ID로 계약, 원료 입고, 운송 예약, 인도, 청구, 수금을 연결한다. 회사 장부에서 부서·계약 장부로 내려가면 왜 돈이 줄거나 재고가 이동했는지 추적할 수 있게 한다. 통화와 최소 화폐 단위를 유지하고 환산 시점·환율 출처를 별도 기록한다.

근거: [길드 3 `FHDHmEN5oCA` 2:16:00–2:21:00](https://www.youtube.com/watch?v=FHDHmEN5oCA&t=8160)에서 농장 수익이 다른 사업장의 운송자에게 귀속된 것인지 의심하며 확인하는 해설. 원작의 실제 회계 구현이 그렇다고 확정한 관찰은 아니다.

## 4. 자동화는 실행 계획과 멈춘 이유를 보여 주기

작업 큐는 담당자, 선행 작업, 필요한 자원, 예약 자원, 목적지, 진행 상태, 중단 사유를 가진다. 수동 지시·반복 목록·조건부 자동화의 우선순위를 명시한다. 자동화는 직접 거래와 같은 검사·예약 명령을 사용하게 해 별도의 경제 규칙이 생기지 않도록 한다.

규칙 저장 전 “다음에 무엇을, 누가, 언제, 얼마까지 수행하는가”를 미리 보여 준다. 예산 초과·직원 부재·용량 부족·원료 부족을 다른 중단 사유로 표시하고, 중단 시 이미 예약한 자원이 유지되는지 해제되는지도 알린다. 자동 구매는 생산 목표에 필요한 양, 창고 여유, 예산을 함께 고려한다. 규칙을 수정했을 때 진행 중 운송을 중복 시작하지 않아야 한다.

근거: [Software Inc. `wecm-YcecSA` 30:26–33:42](https://www.youtube.com/watch?v=wecm-YcecSA&t=1826)의 위임 설정 후 잘못 시작한 작업 취소, [길드 3 `uYioZlbwjmY` 2:45:00–2:48:00](https://www.youtube.com/watch?v=uYioZlbwjmY&t=9900)의 과잉 채집·창고 문제 해설. 후자의 정확한 원인은 확인하지 못했다.

## 5. 성장·시너지와 저장 상태의 일관성 지키기

성장 결과는 기존 정의의 원래 능력·레벨·강화에서 다시 계산한다. 화면에 표시한 파생 능력치를 반복 저장·가산해 불러올 때마다 커지게 하지 않는다. 경험치와 완료 보상은 사건 ID로 중복 지급을 막는다. 기존 설계의 업무별 시너지 상한과 시설 잔여 용량 적용 순서를 유지하고 가격·관세·선박 속도·물리적 적재 용량에 새 성장 배율을 붙이지 않는다.

저장에는 상태 버전, 시뮬레이션 시각, 난수 상태, 진행 작업, 예약, 미수금, 처리된 사건 ID가 포함되어야 한다. 불러온 직후 작업 예약과 원장을 대조한다. 표시용 애니메이션을 다시 재생해도 실제 완료 사건을 다시 실행하지 않는다.

근거: [길드 3 `Lv6OwlAGNiQ` 19:34–20:43](https://www.youtube.com/watch?v=Lv6OwlAGNiQ&t=1174)의 흥정 보너스 중첩, [게임개발 스토리 `He_a4LEOIeY` 1:29:39–1:30:47](https://www.youtube.com/watch?v=He_a4LEOIeY&t=5379)의 성장 선택과 급여 증가에 대한 후회. 악용 영상은 현행 버전의 재현 결과가 아니라 검증 시나리오를 고르는 단서다.

## 6. 구현 순서와 의미 있는 검증

| 순서 | 구현할 행동 | 단계 완료를 판단할 사례 |
|---|---|---|
| 1. 실행 가능한 계약 한 건 | 기존 M1의 정상·선적 전 취소·지연 수락을 최소 화면과 연결 | 같은 수주 명령 재전송에도 현금·재고 불변. 인도 후 미수 상태 보존. 취소 예약·환급 한 번 처리 |
| 2. 채용·육성 | 기존 M2a·M2b 순서에 맞춰 영입·교육·성장·조직·팀 편성 추가 | 도감 발견만으로 고용되지 않음. 교육과 근무 중복 거절. 강사 부재 확인. 편성안 저장만으로 보너스 발생하지 않음 |
| 3. 반복 업무 위임 | 직접 검증한 명령을 반복·조건부 규칙으로 실행 | 재고 부족·창고 포화·인원 부재마다 정확한 사유 표시. 미리보기와 실행 결과 연결. 규칙 수정 시 운송 복제 없음 |
| 4. 사업 확장 | 복수 계약·거점·경쟁·정책을 기존 후속 단계에 맞춰 추가 | 두 계약이 같은 자금을 소비하지 않음. 내부 이동으로 회사 매출 증가 없음. 모든 성장 조합에서 용량 제약 유지 |

공통 저장 검증은 “운송 중·교육 중·인도 후 미수 상태”에서 저장하고 불러온 뒤, 중단 없이 진행한 결과와 비교한다. 성장 조합 검증은 실제 허용 조합에 한정하며 과도한 임의 배율을 연구 계수처럼 사용하지 않는다. 이 문서의 사례는 **앞으로 실행할 검증 명세**이며 현재 통과한 테스트가 아니다.

출처 관찰은 같은 묶음의 `guild3.json`, `software_inc.json`, `two_point_hospital.json`, `game_dev_story.json`에 기록되어 있다. 실제 연구 기반 계수와 교육 효과의 타당성 검증은 별도 단계다.

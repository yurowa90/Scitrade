# Scitrade

현대 무역·물류 경영과 동물·신수 직원 수집을 결합한 게임의 개발 자료입니다. 설계 v0.4 · 개발 자료 v0.4.1.

처음 사용하는 코드 세션에서는 `START_HERE.md`부터 읽습니다. 이 묶음은 설계 v0.4를 담은 재생성 배포본입니다.

이 폴더는 **구현할 게임의 명세·참조 조사·구조화 콘텐츠·검증용 데이터**입니다. 현재 브랜치의 실제 구현 범위는 [docs/STATUS.md](docs/STATUS.md)에서 확인합니다. 대항해시대 4의 세계지도·도시·교역 연결과 더 길드 3의 사업장·직원·인물 상호작용을 현대 무역회사에 맞게 재구성합니다.

## v0.4에서 추가한 방향

동물·영물·괴물·신수를 수집해 직원·동료로 영입합니다. 레벨·교육·직무 강화·속성·프로젝트 팀 시너지, 회사의 부서·상설팀·역할을 추가했습니다. 첨부 영상의 둥근 SD 캐릭터·파스텔 배경·카드 도감·반짝임을 시각 방향으로 삼았습니다.

먼저 `docs/CHARACTERS_AND_ORGANIZATION.md`와 `docs/ART_DIRECTION.md`를 읽습니다. 설계 수치는 DESIGN이며 실제 코드와 미술 자산의 진행 상태는 [docs/STATUS.md](docs/STATUS.md)를 기준으로 확인합니다.

## 시제품 실행

M1(거래 한 건)과 M2a 첫 단계(복수 계약·운송 주선·자원 예약)의 엔진과 최소 화면이 있습니다. 화면 위쪽에서 시나리오를 고릅니다. Node.js 22 이상에서:

```bash
npm install
npm run dev        # 화면 (http://localhost:5173)
npm test           # 엔진 테스트
npm run typecheck
python3 tools/validate_data.py   # 자료 검사
```

현재 구현 범위와 검증 기록은 [docs/STATUS.md](docs/STATUS.md)를 봅니다. 엔진 결정은 [docs/DECISIONS.md](docs/DECISIONS.md)의 ‘M1 엔진 구현 결정’과 ‘M2a 첫 단계’에 있습니다.

## 먼저 알아둘 결정

- 중심은 회사 경영과 국제 통상. 직원 채용·배치·위임·성장이 인물 플레이의 중심입니다.
- 도시에서 거래처·직원·현지 인물을 만나고, 문화생활·탐방으로 지역 지식과 관계를 쌓습니다.
- 지역 이해, 특정 인물·조직과의 친밀, 계약 이행에 따른 거래 신뢰를 구분합니다.
- 타사 주식투자는 P1 금융 확장, 자사 IPO는 P2 성장 확장입니다. 초기 게임은 회사 돈을 사용하며 대표 개인 돈과 섞지 않습니다.
- 사회·과학 내용은 계약·사건·직원 보고에 포함합니다. 교과 퀴즈 통과를 거래의 필수 조건으로 삼지 않습니다.
- 한 번에 전부 구현하지 않습니다. **첫 코드 세션 목표는 M1의 거래 한 건**입니다.

## 데이터 확인 명령

Python 3 표준 라이브러리만 사용합니다. 폴더를 이동해도 동작하도록 경로를 계산합니다.

```bash
python3 tools/validate_data.py
```

검증 범위: JSON 구조, ID 중복·교차 참조, 출처·교과 연결, P0/P1 기능 구분, 양수·범위 조건, M1 정상·취소·지연 거래 산수·IPO 예제, ECB 교차환율 재계산, manifest 해시. 거래·운영 인수 사례 17개(M2a 3개 포함)와 캐릭터·조직 인수 사례 8개를 별도로 제공합니다. 25개 가운데 일부만 엔진 테스트에 연결했으며, 연결 현황은 STATUS.md에 있습니다. 이 검사는 M2 시나리오의 경로 산술도 확인합니다. 통과는 **데이터 묶음의 정합성 확인**이며 게임 플레이·실제 경제·교육 효과 검증을 뜻하지 않습니다.

## 첫 코드 세션에 넣을 요청

> 이 폴더의 README.md, AGENTS.md, docs/DECISIONS.md, docs/UI_SPEC.md, docs/FLOWS.md를 먼저 읽고 `python3 tools/validate_data.py`를 실행하라. 이번 작업은 M1로 제한한다. v0.4의 캐릭터 이름·초상을 기존 직원 ID에 연결하되 성장·시너지 기능은 dedicated M2 시나리오까지 비활성화한다. 항구 2곳·의류 1종·직원 1명·노선 1개로 견적 수락→매입→예약→운송→인도→외상대금 회수까지 구현한다. 경제 상태는 UI와 독립된 TypeScript 모듈 하나가 소유한다. 고정 시드, 정수 최소 화폐 단위, 화물·돈·업무 상태를 분리한다. 먼저 정상·지연·취소의 상태표를 검토하고 한 거래의 현금·재고·채권을 검산한다. 동작하는 최소 화면과 정상 경로를 구현한 다음 남은 위험에 맞는 테스트를 추가한다. 주식·IPO·전체 도시 3D·모든 교과 사건을 한 번에 구현하지 않는다. 기존 구현 저장소가 주어지면 현재 코드와 지침을 먼저 읽고 작은 변경 단위로 진행한다. 구현한 기능과 fixture에 의존하는 값을 구분해 보고하라.

## 이후 단계

M1 거래 → M2a 복수 계약·동료 영입·레벨·교육·도시 활동 → M2b 강화·팀 시너지·조직 → M3 통상·공통 사건·경쟁 → M4 실제 자료 보정 → M5 표현·이야기·플레이테스트 → P1 주식·기술·문화 확장 → P2 상장·다년 성장.

도시·문화의 핵심 경험은 M2부터 검증하고 M5에서 표현을 다듬습니다. 단계 완료 기준은 `docs/DECISIONS.md`와 전체 설계를 따릅니다. 날짜별 출시 일정은 아직 확정하지 않았습니다.

## 자산과 출처

원작의 이미지·음원·캐릭터·영상·UI 소스는 이 폴더에 넣지 않았습니다. 공개 링크, 확인한 화면에 대한 자체 관찰 기록, 프로젝트용 가상 데이터를 제공합니다. 그래픽·아이콘·텍스트는 이 게임을 위해 제작합니다. ECB 표본의 출처는 European Central Bank이며 [무료 원자료](https://www.ecb.europa.eu/stats/eurofxref/eurofxref-hist.zip)에서 추출했습니다. 원 관측값 두 열과 프로젝트에서 계산한 교차환율을 구분했으며, [이용 조건](https://www.ecb.europa.eu/services/using-our-site/disclaimer/html/index.en.html)을 데이터에 기록했습니다. 다른 외부 통계 원자료는 수집 단계에서 이용 조건을 확인합니다.

## 1. 용어

- **논리 픽셀:** 그림 파일의 한 픽셀. 픽셀아트에서 사람이 찍는 한 점이다.
- **화면 배율 n:** 논리 픽셀 하나가 화면의 **기기 픽셀** n×n개로 보이는 값. n은 1 이상의 정수다.
- **CSS 크기:** 논리 크기 × n ÷ `devicePixelRatio`. 예를 들어 32×32 스프라이트를 n=3으로 보이면, 배율 100% 화면에서 96 CSS px, 125% 화면에서 76.8 CSS px다.

## 2. 크기

| 대상 | 논리 크기 | 보통 화면 배율 | 색 수 | 배경 |
|---|---|---|---|---|
| 동료 업무 스프라이트 (`ART-CH-WORK`) | 한 칸 32×32. 시트는 4줄(대기·걷기·업무·기쁨) × 4칸 = 128×128 | 2~3 | 불투명 15색 이하 + 투명 | 투명 |
| 동료 초상 (`ART-CH-PORTRAIT`) | 48×48 | 2 | 불투명 15색 이하 + 투명 | 투명 |
| 동료 카드 그림 (`ART-CH-CARD`) | 96×128 (3:4). 위 19줄·아래 19줄은 이름·레벨 표시가 덮는다 | 목록 1~2, 상세 3 | 공용 팔레트 안 | 장면으로 꽉 채움 |
| 배경 (`ART-BG-*`) | 384×216 (16:9) | 화면에 맞는 정수배 (3배 1152×648, 4배 1536×864, 5배 1920×1080) | 공용 팔레트 안 | 장면 |
| 화면 아이콘 (`ART-UI-*`) | 16×16 | 1~2 | 불투명 15색 이하 + 투명 | 투명 |
| 카드 테두리 (`ART-UI-FRAME`) | 24×24 9-분할 그림(모서리 8×8) | 카드와 같음 | 공용 팔레트 안 | 투명 |
| 지도 표시 (`ART-MAP-PORT`·`HUB`·`GATE`·`EVENT`) | 16×16. 화물선(`ART-MAP-SHIP`)은 24×16 | 지도와 같음 | 불투명 15색 이하 + 투명 | 투명 |
| 동아시아 지도 (`ART-MAP-BASE`) | 546×615 (지도 좌표 2단위 = 1 논리 픽셀) | 화면에 맞는 정수배 | 공용 팔레트 중 지도 색 | 자동 생성 |
| 세계지도 (`ART-MAP-WORLD`) | 720×244 (경위도 1°당 2 논리 픽셀) | 정수배, 가로 스크롤 | 공용 팔레트 중 지도 색 | 자동 생성 |

**크기를 이렇게 정한 이유**
- 32×32는 SNES 스프라이트가 쓸 수 있던 크기(8·16·32·64) 가운데 하나다. 2.5~3등신 동물의 얼굴·특징 1~2개·업무 소품 하나를 넣을 수 있는 가장 작은 칸이다.
- 카드는 정체성(종의 특징, 서식지 장면)을 맡는다. 스프라이트가 작아 생기는 종 구별의 한계를 카드가 메운다.
- 384×216은 1080p 화면에 5배로 정확히 맞는다.
- 지도는 화면에서 스프라이트와 비슷한 배율(2~3)로 보이도록 논리 해상도를 정했다. 같은 장면에서 픽셀 크기가 서로 다르면(믹셀) 픽셀아트의 일관성이 깨진다.

**‘16비트풍’의 뜻:** 실제 SNES는 256색을 한 화면에 쓰고, 스프라이트 하나는 16색 팔레트(투명 1색 포함) 하나를 썼다. 이 프로젝트의 공용 32색은 그보다 엄격하다. 역사적 재현이 아니라, AI 초안의 색을 하나로 묶기 위한 선택이다. 스프라이트별 ‘15색 + 투명’ 제한은 SNES의 규율을 빌린 것이다.

## 3. 팔레트

- 파일: `src/assets/palette.json`. 지금은 **초안**(`DRAFT`)이다. 그림 일괄 제작을 시작할 때 사람이 확정한다.
- 구성: 8개 색 줄기 × 4단계(어두움 → 밝음) = 32색.
  - 잉크·남색(외곽선·글자 주변), 바다, 청록, 초록, 흙·모래, 따뜻한 빨강·주황, 분홍·보라, 밝은 중성색.
  - 화면의 기존 색(크림 `#fbf6ec`, 남색 `#1f2a44`, 경고 `#b5532a`, 금색 `#c9a24a`)을 팔레트에 넣었다. 순백은 넣지 않았다. 크림과 밝기 차이가 3밖에 나지 않아 한 칸을 낭비하기 때문이다. 가장 밝은 강조색은 크림이다.
- 단계마다 밝기(CIELAB L*)가 7 이상 차이 나게 했다. 같은 줄기의 이웃 색이 화면에서 뭉개지지 않게 하려는 것이다.
- 다른 사람이 만든 공개 팔레트는 쓰지 않는다. 라이선스 확인 부담을 없애고 기존 화면 색과 맞추기 위해서다.
- 편집기용 내보내기(`.gpl`, `.hex`)는 `tools/art/palette.py`가 만든다.

## 4. 파일 형식

- **PNG, 무손실.** 손실 압축(JPEG, 손실 WebP)은 팔레트 밖 중간색을 만들어 픽셀아트를 망가뜨린다. 지금의 위성 지도는 손실 WebP지만, 픽셀 지도는 PNG로 바꾼다.
- **알파는 0 또는 255만.** 반투명 가장자리(안티앨리어싱)는 쓰지 않는다.
- **모든 불투명 픽셀은 팔레트 색이어야 한다.**
- 스프라이트 시트는 칸이 겹치지 않는 격자다. 칸 크기와 줄 순서는 `src/assets/manifest.json`의 `character_slots`를 따른다.

## 5. 화면에 그리는 방법

- **보간 끄기:** 픽셀 그림에는 `image-rendering: pixelated`를 쓴다. 브라우저가 확대하며 색을 섞지 않게 한다(MDN, ‘Crisp pixel art look’).
- **정수 배율:** 정수가 아닌 배율로 확대하면 어떤 논리 픽셀은 3칸, 어떤 것은 4칸이 되어 그림이 떨린다.
  - 배율은 **기기 픽셀 기준**으로 정한다. n = 내림(쓸 수 있는 CSS 폭 × `devicePixelRatio` ÷ 논리 폭), 최소 1.
  - CSS 크기는 n × 논리 크기 ÷ `devicePixelRatio`다.
  - 윈도 노트북의 125%·150% 배율처럼 `devicePixelRatio`가 정수가 아닌 화면에서도 기기 픽셀 기준이면 고르게 보인다.
  - 브라우저 확대·축소로 `devicePixelRatio`가 바뀌면 다시 계산한다.
- **남는 공간:** 정수 배율로 맞추고 남는 폭은 여백으로 둔다. 논리 폭이 화면보다 넓으면 n=1로 두고 가로 스크롤한다.
- **글자:** 이름·수치·설명은 픽셀 그림 위에 일반 글꼴(IBM Plex Sans KR, Gowun Dodum)로 쓴다. 그림 안에 글자를 찍지 않는다.
- **움직임:** 스프라이트는 칸을 순서대로 바꾸는 방식(CSS `steps()` 또는 스크립트)으로 움직인다. 기본 칸 시간은 180ms다. ‘움직임 줄이기’ 설정에서는 첫 칸만 보인다.

## 6. 지도

- 지도는 위성 합성 영상과 지형 높이 지도에서 `scripts/build_map.py --style pixel`로 자동 생성한다. 해안선은 실제 지리를 따른다.
- 사진 색을 줄이기만 하면 픽셀아트가 아니라 거친 사진이 된다. 그래서 지형을 몇 가지 분류(깊은 바다·얕은 바다·해안·저지대·숲·건조지·산지·눈과 얼음)로 나눈다. 외톨이 픽셀은 주변 다수 분류로 정리하고, 분류마다 팔레트 색 2~3단계로 음영을 준다.
- 해협·운하(`data/world.json`의 관문)는 해상도가 낮아 육지로 막힐 수 있다. 생성 때 관문 좌표에 바다 픽셀 통로를 낸다. 실제 운송 시간·경로는 지도와 무관하게 `routes.json`만 쓴다.
- 거점·항로·배·나침반은 지금은 코드로 그린 벡터 표시를 유지한다. 그림 일괄 제작 때 같은 배율의 픽셀 그림으로 바꾼다(`ASSET_BACKLOG.md` 3절).

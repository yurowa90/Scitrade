## 1. 용어

- **논리 픽셀:** 그림 파일의 한 픽셀. 픽셀아트에서 사람이 찍는 한 점이다.
- **화면 배율 n:** 논리 픽셀 하나가 화면의 **기기 픽셀** n×n개로 보이는 값. n은 1 이상의 정수다.
- **CSS 크기:** 논리 크기 × n ÷ `devicePixelRatio`. 예를 들어 32×32 스프라이트를 n=3으로 보이면, 배율 100% 화면에서 96 CSS px, 125% 화면에서 76.8 CSS px다.

## 2. 크기

| 동료 업무 스프라이트 (`ART-CH-WORK`) | 한 칸 32×32. 시트는 4줄(대기·걷기·업무·기쁨) × 4칸 = 128×128 | 2~3 | 불투명 15색 이하 + 투명 | 투명 |

| 세계지도 (`ART-MAP-WORLD`) | 720×244 (경위도 1°당 2 논리 픽셀) | 틀 폭 이상이 되는 가장 작은 정수배, 같은 3 CSS px 상한. 가로 스크롤 | 공용 팔레트 중 16색 (상한 20) | 자동 생성 |

**크기를 이렇게 정한 이유**
- 32×32는 SNES 스프라이트가 쓸 수 있던 크기(8·16·32·64) 가운데 하나다. 2.5~3등신 동물의 얼굴·특징 1~2개·업무 소품 하나를 넣을 수 있는 가장 작은 칸이다.
- 카드는 정체성(종의 특징, 서식지 장면)을 맡는다. 스프라이트가 작아 생기는 종 구별의 한계를 카드가 메운다.
- 384×216은 1080p 화면에 5배로 정확히 맞는다.
- 지도는 화면에서 스프라이트와 비슷한 배율(2~3)로 보이도록 논리 해상도를 정했다. 같은 장면에서 픽셀 크기가 서로 다르면(믹셀) 픽셀아트의 일관성이 깨진다. 다만 휴대폰처럼 좁은 화면에서는 세계지도 논리 픽셀이 1 CSS px까지 작아진다(6절).

**‘16비트풍’의 뜻:** 실제 SNES는 256색을 한 화면에 쓰고, 스프라이트 하나는 16색 팔레트(투명 1색 포함) 하나를 썼다. 이 프로젝트의 공용 32색은 그보다 엄격하다. 역사적 재현이 아니라, AI 초안의 색을 하나로 묶기 위한 선택이다. 스프라이트별 ‘15색 + 투명’ 제한은 SNES의 규율을 빌린 것이다.

## 3. 팔레트

- 파일: `src/assets/palette.json`. 지금은 **초안**(`DRAFT`)이다. 그림 일괄 제작을 시작할 때 사람이 확정한다.
- 구성: 8개 색 줄기 × 4단계(어두움 → 밝음) = 32색.
  - 잉크·남색(외곽선·글자 주변), 바다, 청록, 초록, 흙·모래, 따뜻한 빨강·주황, 분홍·보라, 밝은 중성색.
  - 화면의 기존 색(크림 `#fbf6ec`, 남색 `#1f2a44`, 경고 `#b5532a`, 금색 `#c9a24a`)을 팔레트에 넣었다. 순백은 넣지 않았다. 크림과 밝기 차이가 3밖에 나지 않아 한 칸을 낭비하기 때문이다. 가장 밝은 강조색은 크림이다.
- 단계마다 밝기(CIELAB L*)가 7 이상 차이 나게 했다. 같은 줄기의 이웃 색이 화면에서 뭉개지지 않게 하려는 것이다.
- 다른 사람이 만든 공개 팔레트는 쓰지 않는다. 라이선스 확인 부담을 없애고 기존 화면 색과 맞추기 위해서다.
- 편집기용 내보내기(`.gpl`, `.hex`)는 `tools/art/palette.py`가 만든다. 저장 위치는 `docs/art/palette/scitrade-32.gpl`·`.hex`다.
- 지도는 이 팔레트로 칠한다. 팔레트를 바꾸면 지도를 다시 생성한다(6절).

## 4. 파일 형식

- **PNG, 무손실.** 손실 압축(JPEG, 손실 WebP)은 팔레트 밖 중간색을 만들어 픽셀아트를 망가뜨린다. 지도도 2026-10-06(TASK-0007)부터 PNG다. 이전 위성 지도(손실 WebP)는 지웠다.
- **PNG 세부 조건:** 브라우저가 팔레트 색을 그대로 그리도록, 다음은 검사기가 거절한다.
  - 8비트를 넘는 비트 깊이, 움직이는 PNG(APNG).
  - sRGB가 아닌 색 정보: sRGB 감마(0.45455)가 아닌 `gAMA`, sRGB/D65가 아닌 `cHRM`, `(1,13,0,1)`이 아닌 `cICP`, HDR 청크(`mDCV`·`cLLI`와 초안 이름 `mDCv`·`cLLi`), 표본 색 변환이 sRGB와 1단계 넘게 다른 `iCCP`.
  - 색 청크(`gAMA`·`cHRM`·`cICP`·`iCCP`·`sRGB`)가 두 번 이상 나오는 파일. 브라우저는 첫 번째 청크를 쓰므로, 중복을 허용하면 검사와 화면이 다른 청크를 볼 수 있다.
  - 1·2·4비트 팔레트와 회색조는 허용한다.
- **알파는 0 또는 255만.** 반투명 가장자리(안티앨리어싱)는 쓰지 않는다.
- **모든 불투명 픽셀은 팔레트 색이어야 한다.**
- 스프라이트 시트는 칸이 겹치지 않는 격자다. 칸 크기와 줄 순서는 `src/assets/manifest.json`의 `character_slots`를 따른다.

## 5. 화면에 그리는 방법

- **보간 끄기:** 픽셀 그림에는 `image-rendering: pixelated`를 쓴다. 브라우저가 확대하며 색을 섞지 않게 한다(MDN, ‘Crisp pixel art look’).
- **정수 배율:** 정수가 아닌 배율로 확대하면 어떤 논리 픽셀은 3칸, 어떤 것은 4칸이 되어 그림이 떨린다.
  - 배율은 **기기 픽셀 기준**으로 정한다. 스프라이트·카드·배경은 n = 내림(쓸 수 있는 CSS 폭 × `devicePixelRatio` ÷ 논리 폭), 최소 1(`src/ui/pixel.ts`의 `fitPixelBox`). 지도는 6절 규칙을 쓴다.
  - CSS 크기는 n × 논리 크기 ÷ `devicePixelRatio`다.
  - 윈도 노트북의 125%·150% 배율처럼 `devicePixelRatio`가 정수가 아닌 화면에서도 기기 픽셀 기준이면 고르게 보인다.
  - 브라우저 확대·축소로 `devicePixelRatio`가 바뀌면 다시 계산한다.
- **남는 공간 (스프라이트·카드·배경):** 정수 배율로 맞추고 남는 폭은 여백으로 둔다. 논리 폭이 화면보다 넓으면 n=1로 두고 가로 스크롤한다.
- 지도는 틀을 채우는 별도 규칙을 쓴다(6절 ‘화면 배율’).
- **글자:** 이름·수치·설명은 픽셀 그림 위에 일반 글꼴(IBM Plex Sans KR, Gowun Dodum)로 쓴다. 그림 안에 글자를 찍지 않는다.
- **움직임:** 스프라이트는 칸을 순서대로 바꾸는 방식(CSS `steps()` 또는 스크립트)으로 움직인다. 기본 칸 시간은 180ms다. ‘움직임 줄이기’ 설정에서는 첫 칸만 보인다.

**육지 판정**
- 논리 픽셀 하나를 7×7 부분 칸으로 나누고, 각 부분 칸 중심이 다각형 안인지 짝-홀 규칙으로 판정한다. 구멍은 그 다각형에만 적용한다.
- 육지 표본이 절반 이상이면 육지다.

**지형과 색**
- 사진 색을 줄이기만 하면 픽셀아트가 아니라 거친 사진이 된다. 그래서 지형을 분류하고, 분류마다 팔레트 색 2~3단계로 음영을 준다.
- 외톨이 픽셀은 분류 안 최빈값으로 정리한다. 음영은 북서쪽 광원의 언덕 음영 3단계다.

| 분류 | 색 (`palette.json` 이름) |
|---|---|
| 바다 (해안에서 먼 순서로 3단계) | `sea-1`·`sea-2`·`sea-3` |
| 해안선 (육지 쪽 한 칸) | `teal-4` |
| 저지대 / 숲 | `green-2~4` / `green-1~3` |
| 건조지 | `earth-2~4` |
| 산지 | `ink-4`(그림자)·`light-1`·`light-2` — 회색 바위 |
| 눈·얼음 | `light-3`·`light-4` |

- 산지·눈·건조지·바다는 색을 서로 공유하지 않는다. 남색(`ink-1~3`)은 깊은 바다로 읽히므로 산지에 쓰지 않는다(2026-10-06 Claude 확인: 산지를 남색으로 칠하자 티베트 고원·안데스가 호수처럼 보였다).
- 지도당 색은 20개 이하다. 지금 두 지도는 각각 16색이다.

**해협·운하 통로**
- `data/world.json`의 관문(해협·운하)은 해상도가 낮아 육지로 막힐 수 있다.
- 관문마다 양쪽 바다가 그 관문 주변 창 안에서 이미 4-연결되어 있으면 **깎지 않는다**.
- 끊겼을 때만 바다로 바꿀 칸을 고른다.
  - 비용 순서: 바꾸는 육지 칸 수 → 원본 육지 비율의 합(물에 가까운 길 우선) → 길이.
  - 한 관문에서 6칸까지만 바꾼다.
  - 새 바다 칸 하나 이상이 관문 표시 좌표에서 1 논리 픽셀 이내여야 한다. 어기면 생성이 실패한다.
- 지금 결과: 동아시아는 바꾼 칸이 없다. 세계는 바브엘만데브 1, 수에즈 6, 파나마 1, 지브롤터 1, 보스포루스 1, 다르다넬스 3칸이다.
- 실제 운송 시간·경로는 지도와 무관하게 `routes.json`만 쓴다.

**호수 정리**
- 정리는 통로를 낸 **뒤에** 한다. 대상은 Natural Earth 호수에서 온 물뿐이다. 바다와 이어진 물은 바꾸지 않는다.
- 호수는 원본 면적(7×7 표본 합)으로 판단한다. 1.5칸 미만인 호수만 육지로 바꾼다.
- 예외: 세계지도의 타이호(면적 0.88칸)는 상하이 주변 지리를 위해 남긴다.
- 큰 호수는 화면에서 한 칸이어도 남는다. 그래서 한 칸짜리 호수가 일부 있다(세계 32, 동아시아 25).

**화면 배율** (`src/ui/map.ts`의 `planMapViewport`)
- 공통 상한: 논리 픽셀 하나가 **3 CSS px를 넘지 않는다**(n ≤ 내림(3 × `devicePixelRatio`)).
  - 이유: 넓은 화면에서 지도 픽셀이 동료 스프라이트의 보통 배율(2~3)보다 훨씬 커지면 한 화면의 픽셀 크기가 어긋난다(믹셀).
- ‘이번 항로’ 보기:
  - 항로 상자에 사방 12 논리 픽셀 여백을 더한 영역을 16:10 틀에 담는 가장 큰 n을 쓴다.
  - 남는 폭은 보이는 지도 범위를 넓혀 채운다. 범위는 지도 안으로 자르고 가운데 놓는다. 그래도 남으면 틀의 바다색 여백이다.
  - 폭 맞춤(2026-10-10, TASK-0025): 그 여백(양옆 빈 띠의 합)이 16 CSS px 이상이고 한 단계 큰 n이 틀 폭에 들어가면, 세로를 늘려(정사각형까지, 지도 높이 이하) 그 n을 쓴다. 기본은 16:10이고 세로는 이때만 늘어난다.
- ‘전 세계’ 보기: n = 최소(상한, 최대(올림(`devicePixelRatio`), 올림(틀 폭 × `devicePixelRatio` ÷ 720))).
  - 지도가 틀보다 넓어지므로 가로로 스크롤한다. 틀은 키보드 초점을 받고(`tabindex`), 영역 이름(`role="region"`, `aria-label`)이 있다.
- 이름표·휘장은 일반 벡터라 **지도 표시 폭**에 비례해 커진다. 틀 폭 946 CSS px일 때의 지도 표시 폭에서 멈춘다. 세계지도는 틀보다 넓게 그려 스크롤하므로 틀 폭이 아니라 지도 표시 폭을 기준으로 한다(2026-10-06 Claude 수정). 폭 맞춤 뒤 946 틀의 계획도 같은 규칙을 거치므로, 줌 67~80%에서 상한이 약 943~945 CSS px로 다른 배율과 같아졌다.
- ‘이번 항로’ 보기의 이름표 글자와 리본 상자는 화면 **11 CSS px 하한**을 쓴다(`LABEL_FLOOR_PX`). 휘장·나침반·배·폭풍·항로선·경위선은 하한 없이 이름표 배율 그대로다. 좁은 화면에서 리본이 커져 자리가 없으면 예정 거점 리본부터 빠진다.
- 다시 그릴 때 페이지가 튀지 않도록, 보기 모드별 측정값을 기억하고 지도만 다시 그린다.
- 거점·항로·배·나침반은 지금은 코드로 그린 벡터 표시를 유지한다. 그림 일괄 제작 때 같은 배율의 픽셀 그림으로 바꾼다(`ASSET_BACKLOG.md` 3절).

## 7. 검사

- `tools/art/check_pixel_asset.py`가 등록 전 그림을 검사한다:
  - 크기, 칸 격자, 알파 0/255, 팔레트 밖 색, 색 수 상한(스프라이트 15색).
  - PNG 세부 조건(4절).
- `tools/art/pixelize.py`는 AI 초안을 논리 해상도로 줄인다.
  - 칸마다 팔레트 색으로 먼저 바꾼 뒤 가장 많은 색을 고른다.
  - 외톨이 정리: 이웃 8칸 가운데 5칸 이상이 같은 색이면 그 색으로 바꾼다.
  - 결과는 초안이다. 사람이 보정한다.
- 지도 생성 시험(`scripts/test_build_map.py`)은 다음을 확인한다. 원본 재생성 시험은 원본 폴더(`SCITRADE_MAP_SOURCES`, 없으면 저장소 옆 `map/`)가 있을 때만 돈다.
  - 거점의 해안 거리, 육지·바다 기준점.
  - 전체·관문 주변 바다 연결, 통로의 관문 거리.
  - 지킬 호수 목록, 분류별 색 집합이 겹치지 않는지.
  - 같은 원본으로 다시 만들면 바이트가 같은지(sha256). 매니페스트의 출력 해시가 저장소의 PNG와 같은지(원본 없이도 확인).
- 화면 측정은 실제 기기 배율로 한다. Chromium을 `--force-device-scale-factor=<배율>`로 띄운다. 에뮬레이션 배율(`deviceScaleFactor`)은 실제와 다른 이음매·흐림을 만든다.
- 사람의 눈으로 보는 점검표는 [PROMPTS.md](PROMPTS.md) 7절에 있다. ‘1배 크기에서 누구인지 알아볼 수 있다’가 가장 중요하다.

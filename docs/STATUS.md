# 프로젝트 상태

이 파일은 두 AI와 이후 개발 세션이 함께 사용하는 현재 상태 기록이다. 계획은 `docs/IMPLEMENTATION_PLAN.md`, 설계 결정은 `docs/DECISIONS.md`, 검증 범위는 `docs/VALIDATION.md`를 함께 읽는다.

## 현재 범위

- 자료 묶음: v0.4.1. 게임 설계 기준: v0.4.
- 현재 요청: M1 거래 한 건 구현 (2026-10-04, Claude 코드 세션).
- 게임 구현: M1 내부 검증용 시제품. UI와 분리된 TypeScript 엔진(`src/engine`)과 최소 화면(`src/ui`). 공개 테스트용 MVP가 아님.
- 다음 구현 단위: M2a 착수 전 사람 플레이테스트로 M1 화면 확인, 이후 복수 거래·직원·저장 상태 확장.
- 이 계획의 존재를 게임 구현 착수나 완료로 해석하지 않는다. 다음 세션에서는 사용자가 요청한 작업 범위를 먼저 확인한다.

## 두 AI가 상태를 갱신하는 규칙

1. 작업을 시작할 때 이 파일과 `AGENTS.md`, 대상 단계의 계획, 현재 코드·변경 사항을 읽는다. 다른 세션의 완료 설명만으로 상태를 바꾸지 않는다.
2. 실제로 착수한 단위만 `진행 중`으로 표시하고 작업 범위·관련 파일을 기록한다. 담당자나 일정은 확인된 정보만 적는다.
3. `검증 완료`는 실행한 명령·관찰 결과·대상 버전을 근거로 기록한다. 자료 검사, 엔진 테스트, 화면 확인, 플레이테스트를 구분한다.
4. 단계 완료 기준을 충족한 범위만 `완료`로 바꾸고, 미구현 기능·남은 실패·미검증 항목을 함께 남긴다. 문서 작성이나 테스트 명세 추가만으로 구현 완료로 바꾸지 않는다.
5. 인계에는 변경한 내용, 실행한 검증, 다음의 가장 작은 작업을 적는다. 다른 AI의 동시 변경을 덮어쓰지 말고 충돌을 확인한다.
6. 설계 변경은 `docs/DECISIONS.md`와 관련 데이터·스키마·인수 명세에 함께 반영한다. 가상값과 실제 자료의 구분 및 출처·버전은 보존한다.

| 검증 | 명령·방법 | 결과 |

연결한 인수 명세: P0-ACC-01, P0-ACC-02, P0-ACC-13, P0-ACC-14는 실행 테스트로 연결했다. P0-TIME-01(M2)은 M1 시나리오의 저장·재현·마감 재전송 테스트로 일부만 확인했으며 해당 사례의 고정 수치 그대로는 실행하지 않았다. 도시·주식·IPO·캐릭터 인수 명세는 해당 단계가 아니므로 실행하지 않았다.

## 현재 인계

M1 구현 범위와 엔진 결정은 `docs/DECISIONS.md`의 ‘M1 엔진 구현 결정’에 있다. 처음 데이터에 없던 값(수출 준비 2pt, 취소 정산, 1회 감액, 지연 공지일 5일 등)은 2026-10-04 사용자 검토 후 `data/scenarios.json`의 `contract_terms`·`port_restriction`으로 옮겼고 엔진은 이 데이터를 읽는다. 동료 레퍼런스 화면 4장의 채택·제외 판단은 `docs/ART_DIRECTION.md`에 있다.

남은 위험과 미결정:
- 지급 불이행 유예기간이 확정되지 않아 경영 실패 판정은 구현하지 않았다. 현금 부족은 미지급 의무로만 기록한다.
- 지연 감액은 지연 일수와 무관한 1회 50 USD로 정했다(사용자 검토). 일수 비례가 필요하면 `late_delivery.basis`를 확장한다.
- 출항 후 취소, 대체편 예약, 납기 협상은 화면에서 비활성화했다 (M3 사건 시스템).
- 캐릭터는 이름·속성·모티프 문장만 표시하는 자리표시자다. 능력·레벨·시너지는 계산하지 않는다.
- 웹 글꼴은 Google Fonts에서 불러온다. 연결되지 않는 환경에서는 시스템 글꼴로 대체된다.

그림: 마지막에 일괄 제작한다(사용자 결정). 그 전까지 자리표시자로 개발하고, 필요한 그림·모션은 `docs/art/ASSET_BACKLOG.md`에 쌓는다. 제작 시에는 `docs/art/PROMPTS.md` 절차로 만들고 `src/assets/manifest.json`에 등록해 교체한다.

다음의 가장 작은 작업: 사람이 화면으로 세 경로를 진행해 보고 이해하기 어려운 지점을 기록한 뒤, M2a의 복수 계약·직원 예약·저장 상태 명세를 고정한다.

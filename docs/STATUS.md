- 현재 요청 (2026-10-05, Claude 코드 세션): 사용자가 “계속”을 지시했다. Claude 총괄·검수 → Codex(Astra·Sol) 구현 체계로 M2a를 진행 중이다. 그림·지도는 픽셀아트로 바꾸기로 했다(사용자 결정). 영입(M2a-2)과 경험치·레벨·훈련 엔진(M2a-3)은 개발 브랜치에 반영했다.

## 두 AI가 상태를 갱신하는 규칙

1. 작업을 시작할 때 이 파일과 `AGENTS.md`, 대상 단계의 계획, 현재 코드·변경 사항을 읽는다. 다른 세션의 완료 설명만으로 상태를 바꾸지 않는다.
2. 실제로 착수한 단위만 `진행 중`으로 표시하고 작업 범위·관련 파일을 기록한다. 담당자나 일정은 확인된 정보만 적는다.
3. `검증 완료`는 실행한 명령·관찰 결과·대상 버전을 근거로 기록한다. 자료 검사, 엔진 테스트, 화면 확인, 플레이테스트를 구분한다.
4. 단계 완료 기준을 충족한 범위만 `완료`로 바꾸고, 미구현 기능·남은 실패·미검증 항목을 함께 남긴다. 문서 작성이나 테스트 명세 추가만으로 구현 완료로 바꾸지 않는다.
5. 인계에는 변경한 내용, 실행한 검증, 다음의 가장 작은 작업을 적는다. 다른 AI의 동시 변경을 덮어쓰지 말고 충돌을 확인한다.
6. 설계 변경은 `docs/DECISIONS.md`와 관련 데이터·스키마·인수 명세에 함께 반영한다. 가상값과 실제 자료의 구분 및 출처·버전은 보존한다.

## 현재 인계

M1 구현 범위와 엔진 결정은 `docs/DECISIONS.md`의 ‘M1 엔진 구현 결정’에 있다. 처음 데이터에 없던 값(수출 준비 2pt, 취소 정산, 1회 감액, 지연 공지일 5일 등)은 2026-10-04 사용자 검토 후 `data/scenarios.json`의 `contract_terms`·`port_restriction`으로 옮겼고 엔진은 이 데이터를 읽는다. 동료 레퍼런스 화면 4장의 채택·제외 판단은 `docs/ART_DIRECTION.md`에 있다.

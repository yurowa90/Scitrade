TASK-0001 구현은 완료 조건을 충족했다. 다만 검수에서 아래 항목이 유지되었다. 이 항목들을 고쳐 테스트가 실제 규칙을 증명하게 하고, 경계 사례를 막는다. **기존 기대값과 이미 통과한 동작은 바꾸지 않는다.**

## 고칠 것

1. **[major] 같은 후보에게 의뢰를 두 번 시작하는 테스트가 단계 검사를 증명하지 못한다** (`m2a-recruit.test.ts` 97행 부근).
   - 지금은 두 번째 의뢰가 ‘직원이 바쁨’ 규칙에 먼저 걸려 거절된다. 그래서 단계 검사(`stage !== 'DISCOVERED'`)를 지워도 테스트가 통과한다.
   - 두 번째 의뢰는 **다른 대기 직원**으로 보낸다. 거절 이유가 단계 검사 문구인지 확인한다.
   - 의뢰가 끝난 뒤(`INTERVIEW_READY`)와 고용 뒤(`HIRED`)에도 의뢰를 다시 시작할 수 없음을 확인한다.
2. **[minor] 면담 전 고용 거절이 `UNDISCOVERED`에서만 시험된다.**
   - `DISCOVERED`와 `QUEST_RUNNING`에서도 `HIRE_CANDIDATE`가 거절되는지 확인한다.
   - 거절 뒤 장부·상태가 그대로인지 확인한다.
3. **[minor] 일급이 0인 후보를 고용하면 `LedgerError`가 난다.**
   - 계약금이 0이면 장부 기록 없이 고용한다. 이때도 다음 날부터 근무한다.
   - 0원 후보는 테스트용 설정(시나리오 사본)으로 만들어 시험한다. 데이터 파일은 바꾸지 않는다.
4. **[minor] 판본 1 → 2 → 3 이관이 실제 판본 1 형태로 시험되지 않는다.**
   - 지금의 판본 1 테스트 픽스처에는 이미 판본 3 필드(`availableFromDay`, `subjectId`, `recruitment`)가 들어 있다.
   - 이 필드와 판본 2 필드(`serviceOfferId`, `ownerPartyId`)를 **지운** 진짜 판본 1 형태로 저장 문자열을 만든다.
   - 그 문자열이 판본 3으로 이관되는지 확인한다. 경제 값(장부 요약·화물 수량·일정)이 이관 전과 같은지, 영입 명령이 정해진 이유로 거절되는지도 확인한다.
   - 판본 2 형태(판본 3 필드 없음)도 같은 방식으로 한 번 더 시험한다.
5. **[minor] 계약금 자금 검사를 경계값에서 시험하지 않는다.**
   - 사용 가능 원화가 계약금과 **정확히 같으면** 고용된다.
   - 1원 모자라면 거절된다.
6. **[nit] 검사기가 영입 블록의 필수 키가 없을 때 예외로 멈춘다**(`tools/validate_data.py` 242행 부근).
   - 키가 없으면 검사 실패 메시지(`check(...)`)로 보고하고 다음 검사를 계속한다.
   - 자료 사본으로 변형 시험을 한다. 지난번 11종과 같은 방식이다.
7. **[nit] 문서·데이터의 오래된 숫자와 문구**
   - `README.md`, `START_HERE.md`의 인수 명세 개수를 현재 값(핵심 18 + 캐릭터 8 = 26)으로 고친다.
   - `data/scenarios.json`의 M2 시나리오 설명(`scope_note` 등)에 ‘고용은 다음 단계’ 같은 문구가 남아 있으면, 영입이 이 시나리오에 들어갔다고 고친다.
   - 이 문구 수정으로 검산 값을 바꾸지 않는다.

8. **[minor, 검수 중 재현] 거절된 영입 명령이 상태에 흔적을 남길 수 있다.**
   - 문제: `startRecruitmentTask`는 업무를 `s.tasks`에 먼저 넣은 뒤 `assignTask`를 부른다. 그래서 `assignTask`가 거절하면 명령은 REJECTED인데 대기(QUEUED) 업무가 남는다.
   - 지금은 앞 단계 검사가 막고 있어 일어나지 않는다. 하지만 검수자 3명이 단계 검사를 약간 느슨하게 바꾸자 같은 ID(`RECRUIT-EMP04`)의 업무가 중복으로 남는 것을 재현했다.
   - 고칠 것:
     - 거절된 명령은 상태를 전혀 바꾸지 않게 한다. 예: 업무를 만들고 배정 검사를 모두 통과한 뒤에만 넣는다.
     - 불변 조건에 ‘업무 ID는 유일하다’를 더한다.
     - 거절 뒤 업무 수가 그대로인지 확인하는 테스트를 더한다.

## A. 지도 크기: 틀을 채우는 정수 배율 (major)

배율은 정수로 유지하되, 남는 공간을 여백으로 두지 말고 **보이는 영역을 바꿔서** 틀을 채운다.

1. **순수 함수 `planMapViewport(...)`**
   - 입력: 지도 크기, `unitsPerPixel`, 항로 상자, 쓸 수 있는 CSS 폭 W, `devicePixelRatio`, 보기 모드.
   - 출력: `{ vb, n, cssWidth, cssHeight }`.
   - **‘이번 항로’(동아시아):**
     - 항로 상자에 최소 여백(논리 12픽셀씩)을 더한 영역이 들어가는 가장 큰 정수 n을 고른다. 가로·세로를 모두 확인한다. 보기 비율은 지금처럼 16:10이다.
     - 그 n에서 보이는 논리 폭 L = 내림(W × dpr ÷ n), 논리 높이 = 반올림(L × 10 ÷ 16).
     - 보기 영역은 항로 중심에 놓고 지도 안으로 자른다. 지도 끝에 닿을 때만 여백이 생긴다.
     - CSS 폭 = n × L ÷ dpr. 틀 폭과의 차이는 n ÷ dpr CSS px 미만이어야 한다.
   - **‘전 세계’:**
     - n = 최대(올림(dpr), 올림(W × dpr ÷ 720)).
     - 그러면 세계지도는 틀보다 넓거나 같고, 예전처럼 최소 720 CSS px다. 가로 스크롤을 쓴다.
     - 처음 스크롤 위치는 이번 시나리오 거점의 가운데다. 다시 그릴 때는 사용자의 스크롤 위치를 비율로 유지한다.
2. **이름표 크기:** 거점 이름표·휘장·나침반의 화면 크기는 TASK-0007 이전(위성 지도, 폭 100%)보다 작아지지 않아야 한다.
   - 지금의 `k = vb.w / 620` 계산은 보기 영역이 틀 폭에 맞으면 예전과 같은 화면 크기가 된다.
   - 다른 방식을 쓰면 그 근거를 보고서에 적는다.
3. **다시 그리기:**
   - 보기 영역은 틀 폭에 따라 달라진다. 따라서 폭이나 dpr이 바뀌어 n 또는 L이 달라지면 **지도 부분만** 다시 그린다. 화면 전체는 다시 그리지 않는다.
   - 감시 콜백 안에서 바로 크기를 바꾸지 말고 `requestAnimationFrame`으로 미루고, 여러 번 온 요청은 하나로 합친다. 지금은 ResizeObserver loop 오류 이벤트가 난다(minor).
   - 첫 그리기는 기본 폭으로 하고 측정 뒤 한 번 고친다. 깜박임을 줄이는 방법이 있으면 쓴다.
4. **기기 픽셀 경계:**
   - 배율 1.25·1.5에서 한 줄에 한 번 정도 1기기 픽셀 어긋남이 측정되었다. 요소의 화면 위치가 기기 픽셀 경계에 있지 않기 때문으로 보인다.
   - 크기를 정한 뒤 요소의 왼쪽·위 위치를 기기 픽셀 경계에 맞춘다. 예: 소수 나머지만큼 `transform`이나 여백을 조정한다.
   - Claude가 브라우저에서 측정으로 확인한다. Chromium에서 불가능하면 이유를 보고한다.
5. **SVG 밖 바탕 대안(`MAP_BASE_OUTSIDE_SVG`)이 틀렸다** (major).
   - 문제: 안쪽 SVG도 `data-pixel-*`를 가져서, 바깥 상자의 소수 폭을 다시 읽다가 한 단계 작은 n이 된다.
   - 고칠 것:
     - 대안 모드에서는 안쪽 SVG에서 `data-pixel-*`를 빼고, `width/height: 100%`로 바깥 상자를 따르게 한다.
     - 상수 대신 `renderWorldMap`의 선택 인자로 켤 수 있게 해서 테스트한다.
6. **기존 그림 요소:** 카드 그림의 정수 배율(`card.ts`)은 지금 동작을 유지한다. 지도 방식 변경이 카드에 영향을 주지 않게 한다.

2. 다음이 모두 만족된다.
   - 범위 안 모든 거점이 해안에서 1 논리 픽셀 이내다.
   - B-1의 기준점이 모두 맞다.
   - B-2의 연결 쌍이 모두 같은 바다 성분이다.
   - 두 지도는 다시 만들면 같은 sha256이다.
3. 다음 변형을 각각 넣어 테스트가 실패하는 것을 확인하고 보고서에 적는다. 확인한 뒤에는 원래 코드로 되돌린다.
   - `planMapViewport`의 n을 내림 대신 1로 고정.
   - 세계 n의 최소 `ceil(dpr)` 제거.
   - 팔레트 중복 검사 제거.
   - `despeckle`을 옛 정의로.
   - 수에즈 통로 제거.
   - 높이 지도 BOX 확대로 되돌림.
4. 머리말의 검증 다섯 개와 파이썬 테스트 두 묶음이 통과한다.

브라우저 측정(배율 1·1.25·1.5·2·3, 폭 1440·1024·390)은 Claude가 검수 때 한다.

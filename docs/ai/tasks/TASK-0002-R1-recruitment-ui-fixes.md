## 고칠 것

**접근성**
1. 장소마다·후보마다 반복되는 조사·의뢰·면담·고용 버튼과 담당 직원 선택의 접근 이름이 모두 같다.
   - 장소 이름이나 후보 이름을 넣은 `aria-label`을 단다(예: ‘항만 물류단지 현장 조사’, ‘현돌 영입 의뢰 담당 직원’).
2. 면담 버튼은 펼침 상태(`aria-expanded`)와 대상(`aria-controls`)을 알린다. 열리는 면담 블록은 이름 있는 영역(`role="region"`과 `aria-labelledby`)으로 만든다.
3. 조사·의뢰·면담·고용 버튼을 누르면 다시 그린 뒤 초점이 `<body>`로 빠진다. 초점 복원을 고친다.
   - 같은 버튼이 남아 있으면 그 버튼으로 돌린다.
   - 버튼이 사라졌으면 같은 장소·후보 블록의 제목이나 대기 명령 목록으로 돌린다.
   - 운영표 행, 배정 버튼, 대기 명령 빼기 버튼도 다른 요소로 잘못 돌아가지 않게 한다.
4. 후보 카드의 `aria-label`에 상태를 넣는다(예: ‘바름 후보 카드, 발견’). 고용 직원 카드와 같은 방식이다.

**상태**

5. 불러오기·가져오기·처음부터·시나리오 전환 때 다음 화면 상태를 비운다.
   - 대상: 영입 담당 선택, 열린 면담 후보.
   - 이유: 지난 선택이 엔진이 정한 기본값을 덮어쓰고, 없는 후보의 면담이 남는다.
6. 표시 보완:
   - 의뢰 pt는 하드코딩하지 말고 설정의 `questWorkUnits`를 쓴다.
   - 캠페인 마지막 날 면담처럼 남은 급여 기간이 0일이면 ‘남은 기간 없음’으로 적는다.
   - 계획 선택지에 내부 ID 대신 이름을 쓴다.
   - 영입이 없는 시나리오(M1)에서는 ‘후보’ 필터를 숨긴다.
7. `recruitment.ts`의 HTML 이스케이프 함수를 하나로 합친다. `main.ts`의 기존 `esc`와 같은 규칙을 쓰고, 데이터에서 온 문자열은 모두 이스케이프한다(이름·종·단서·장소·이유·업무 대상 ID 포함).

**테스트** (`src/ui/recruitment.test.ts`)

8. 미발견 후보 숨김을 전수 확인한다.
   - 4명 모두의 이름·종·단서 문장이 패널·카드·운영표의 HTML 어디에도 없어야 한다. 속성값과 `aria-label`도 포함한다.
   - 발견한 2명만 나타나야 한다.
9. 패널 버튼과 엔진 판정의 연결을 시험한다.
   - 엔진이 허용하면 버튼이 켜지고, 거절하면 꺼진 채 이유가 보여야 한다.
   - 대상: 고용(면담 전·자금 부족), 조사(바쁜 직원·이미 조사), 의뢰(발견 전).
   - ‘항상 꺼진 버튼’이나 ‘항상 켜진 버튼’으로 바꾸면 실패해야 한다.
10. 공개 조건 테스트에 ‘예약만 하고 배정은 안 함’ 경우(숨김)를 더한다.
11. 면담 테스트는 데이터 객체만 보지 말고 그려진 HTML의 다음 값을 확인한다: 계약금, 남은 급여, 기간 표시, 원화 사용 가능액, 비교 줄의 건수.
    - 날짜를 바꿔 쓴 상태 말고, 실제로 5일까지 진행한 상태에서 시험한다.
12. 다음 날 같은 상태 확인을 `crewEntries`를 거쳐서 한다. 고용 직원이 후보 카드로 그려지지 않아야 한다.

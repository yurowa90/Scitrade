## 지켜야 할 것

- 커밋·푸시·브랜치 전환을 하지 않는다. git으로 파일을 되돌리거나 stash하지 않는다.
- **접속 규칙**
  - 웹 조사는 Codex의 웹 검색·열기 도구로만 한다. 셸에서 `curl`·`wget`으로 내려받지 않는다.
  - `chainportal.co.kr`에는 접속하지 않는다.
  - robots.txt가 막는 사이트는 열지 않는다. 그 사이트의 사본(웹 아카이브 포함)도 열지 않는다.
    - 웹 도구가 robots 때문에 거절하면 접속 기록에 ‘robots 차단’으로 적는다. 도구가 열어 준 페이지는 허용된 것으로 본다.
    - 사본(`web.archive.org`)을 열기 전에는 원 사이트의 `/robots.txt`를 먼저 연다. 그 경로에 AI 크롤러(`GPTBot`, `OAI-SearchBot`, `ChatGPT-User`, `*`)의 `Disallow`가 걸리면 사본도 열지 않는다. 확인 결과를 접속 기록에 적는다.
  - 로그인·회원가입·결제가 필요한 본문은 읽지 않는다. 유료벽은 공개된 부분만 읽는다.
  - 기관·선사에 이메일·전화·문의 양식으로 묻지 않는다.
  - 접속 오류(403, 시간 초과, Cache miss, 삭제된 페이지)만 같은 기관의 다른 공식 URL이나 `web.archive.org` 사본으로 다시 시도한다. 사본을 썼으면 사본 URL과 사본 날짜를 적는다. 접속 실패는 원 사이트의 삭제 판정이 아니다(TASK-0003 결과 10행).
- **근거 규칙**
  - 검색 결과 요약만 보고 ‘일치’로 판정하지 않는다. 본문을 열지 못했으면 ‘확인 불가’다.
  - **등급·부속서·법정 지정 행**(`iucn_status`, `cites_appendix`, 국내 지정)은 1차 원문으로만 ‘일치’·‘불일치’를 판정한다. 1차를 못 열고 2차만 있으면 ‘확인 불가(1차 미열람)’로 두고 2차 값은 주에 적는다.
  - **설명 행**(분포·생태·복원 연도·개체 수·이야기 전제·항만 비교 등)은 2차 자료로도 판정할 수 있다. 그때 출처 종류 칸에 ‘2차’라고 적는다.
  - 원문에서 읽지 못한 값을 추정해 채우지 않는다. 수정안도 원문에 있는 값만 쓴다.
  - 원문 인용은 한 행에 하나, 25단어(한국어 원문은 60자) 이내다. 긴 본문을 옮기지 않는다.
  - 열람일은 작업 환경의 날짜(`date +%F`)로 적는다.
  - 출처 종류는 둘로 나눈다.
    - **1차:** 평가·지정·발표한 기관의 원문. 예: IUCN 적색목록 평가(조류는 적색목록 조류 평가 기관인 BirdLife International의 DataZone), CITES 부속서·Species+, 국가유산청 국가유산포털, 국가법령정보센터의 법령 별표·고시, 환경부·국립생물자원관·해양수산부·국립수산과학원·국립공원공단 발표, 항만 당국·선사가 공표한 자료, 학술지 논문.
    - **2차:** 언론, 백과, 위키, 다른 기관의 요약.
- **글 규칙**
  - 보고서 안 근거 칸에는 실제 회사·선사·단체 이름을 써도 된다.
  - 화면이나 도감에 보일 문장의 **수정안**(`story_clue`, `note_ko`, `national_protection_ko`, `hub_note_ko`, `connects_ko`, `event_hook_ko`)에는 실제 회사·선사·민간 단체 이름을 넣지 않는다. 공공기관·국제기구 이름도 넣지 않는다. 그런 이름은 근거 칸에만 둔다.
    - 지정·등급의 이름은 기관 이름이 아니므로 써도 된다. 예: 천연기념물, 멸종위기 야생생물 I급, 해양보호생물, 위기(EN), 취약(VU), CITES 부속서 I.
    - 실제 선박 이름도 넣지 않는다.
  - 수정안은 사실이 틀렸을 때만 쓴다. 문체 다듬기는 하지 않는다. 길이는 지금 문장의 ±20% 안이다.
  - 보고서는 한국어로 쓴다.
- 시험 파일을 만들지 않는다.

### 0. 공통 표 형식

절 A~D는 아래 열을 가진 표로 쓴다. 행 ID는 이 지시서의 것을 그대로 쓴다. 한 주장에 근거가 둘 이상 필요하면 `A-25a`, `A-25b`처럼 행을 나눈다. 이미 글자가 붙은 C·D 행은 `D-03b-1`, `D-03b-2`처럼 나눈다.

| 행 | 대상(파일·ID·필드) | 우리 값 | 확인한 URL | 열람일 | 원문 근거(인용, 쪽·절·표) | 판정 | 출처 종류 | 제안 확인 수준 | 수정안 | 교차 확인용 URL |
|---|---|---|---|---|---|---|---|---|---|---|

- **판정**은 아래 셋 가운데 하나다. 시간이 모자라 못 한 행만 넷째 값 ‘미실시’를 쓴다.
  - **일치:** 원문 값과 시점·범위가 같다. ‘약’은 원문 값을 유효숫자 두 자리로 반올림한 범위까지 일치로 본다.
  - **불일치:** 원문 값이 다르다. 원문 값과 수정안을 적는다.
  - **확인 불가:** 원문을 열지 못했거나, 원문에 해당 내용이 없다. 이유를 적는다.
  - 판정 칸은 ‘일치’, ‘불일치’, ‘확인 불가’, ‘미실시’ 가운데 하나로 시작한다. 이유는 괄호나 주에 쓴다(예: ‘확인 불가(1차 미열람)’). Claude가 낱말로 개수를 센다.
  - 행은 `| A-01 |`처럼 표 줄 맨 앞 칸에 행 ID를 두고 시작한다.
- **제안 확인 수준**은 대상 파일의 기존 값 체계를 쓴다.
  - `characters.json`의 `conservation.check_level`(자유 글): ‘1차 자료로 확인(기관, 평가·고시 연도, 열람일)’, ‘2차 자료로 확인’, ‘작성자 지식 기반, 출처 대조 필요’ 가운데 하나에 근거를 붙인다.
  - `sources.json`의 `verification_status`: 기존 값만 쓴다. `CONTENT_READ`, `PRIMARY_SOURCE_CROSS_CHECKED`, `SECONDARY_SOURCES_CROSS_CHECKED`, `SELECTED_SECTIONS_READ`(유료벽 등으로 공개된 일부만 읽음), `WEB_SEARCH_SUMMARY_ONLY`. 앞의 셋의 뜻은 `docs/DECISIONS.md` 373~376행이다. 원문을 못 열었으면 지금 값을 그대로 두자고 적는다.
  - `world.json` 관문 `check_level`: 스키마가 받는 값은 `author_knowledge`, `web_search_summary`뿐이다. 근거가 그보다 강하면 새 값 이름(예: `source_content_read`)을 제안하고 ‘질문’에 적는다. 스키마는 고치지 않는다.
- **교차 확인용 URL:** Claude가 같은 사실을 다른 경로로 확인할 수 있는 URL이다. 같은 기관의 다른 페이지, 다른 1차 기관, 공개 사본 순으로 고른다. Claude 환경에서는 `lloydslist.com`이 403이고(`data/sources.json` `LL-100P-2026`의 `cross_check_2026_10_05.method_ko`) `maersk.com`이 막힌다(`PYEONGTAEK-route-basis.md` 84행). 이 두 곳의 행에는 다른 경로를 꼭 하나 적는다. 없으면 ‘없음’이라고 쓴다.

### F. 새 출처 제안

A~E에서 새로 쓰자고 할 출처를 `sources.json` 항목 모양의 JSON 조각으로 적는다. 자료 파일에는 넣지 않는다.

```json
{
  "id": "IUCN-2017-NEOPHOCAENA",
  "title": "…",
  "url": "https://…",
  "kind": "conservation_reference",
  "verification_status": "CONTENT_READ",
  "scope_ko": "이 출처가 뒷받침하는 사실만 적는다. 뒷받침하지 않는 것도 적는다.",
  "checked_on": "YYYY-MM-DD",
  "redistribution": "links_and_project_notes_only",
  "local_path": null
}
```

- ID는 대문자와 하이픈으로 `<발행처 약어>-<연도 또는 판>-<주제>` 꼴이다. 위 예시 ID는 모양만 보인 것이다. 기존 74개 ID와 겹치지 않게 한다(`python3 -c "import json;print([s['id'] for s in json.load(open('data/sources.json'))['items']])"`로 확인).
- `kind`는 기존 값을 먼저 쓴다(예: `conservation_reference`, `scientific_assessment`, `port_authority_statistics`, `port_authority_release`, `carrier_schedule`, `government_statistics`, `official_release`, `official_statistics`, `academic_reference`, `industry_ranking`, `trade_press`, `index_report`, `industry_report`). 전체 목록은 `python3 -c "import json;print(sorted({s['kind'] for s in json.load(open('data/sources.json'))['items']}))"`로 본다. 맞는 값이 없을 때만 새 값을 제안한다.
- `verification_status`는 열어서 본문을 읽은 것만 `CONTENT_READ`다.
- 조각마다 어느 행(A-xx, D-xx 등)의 근거인지 적는다.

### G. 검증

0. **시작할 때** 결과 파일을 만들기 전에 두 가지를 기록한다.
   - `git status --short` 출력. 비어 있어야 한다. 비어 있지 않으면 그 줄을 보고서에 적고, 아래 3번에서 제외한다.
   - `python3 tools/build_package.py --manifest-only`를 돌린 뒤 `python3 tools/validate_data.py`의 PASS 줄 건수. 이것을 ‘시작 건수’라 부른다. 참고로 `d0d4afd`에서는 24,681건, `4a90d77`에서는 24,721건이다.
1. 결과 보고를 다 쓴 뒤 `bash tools/ai/review_checks.sh <시작 커밋>`을 돌린다. 8종이 모두 통과해야 한다. 결과를 보고서 ‘실행한 검증과 결과’에 적는다.
   - 자료 검사는 PASS다. 결과 파일 하나가 `MANIFEST.json`에 더해지면 검사가 2건 늘어난다. 그래서 ‘시작 건수 + 2’가 되어야 한다(`d0d4afd`에서 결과 파일을 더해 재 보니 24,683건이었다).
   - vitest·빌드·파이썬 시험은 시작 커밋과 같은 개수다. 코드가 바뀌지 않았으므로 `d0d4afd` 병합 기록과 같아야 한다: vitest 27개 파일·803개 시험, 파이썬 21·21(3개 건너뜀)·20개. 건너뜀 수는 지도 원본 폴더가 있으면 달라질 수 있다. 다르면 그대로 적는다. 코드·자료를 고쳐서 맞추지 않는다.
   - npm 단계가 환경 문제로 실패하면 실패 출력을 붙여 보고한다.
2. 검증 결과를 보고서에 적으면 보고서 해시가 바뀐다. 그래서 마지막에 `python3 tools/build_package.py --manifest-only`와 `python3 tools/validate_data.py`를 한 번 더 돌린다. 이 두 줄의 결과는 보고서에 다시 적지 않아도 된다.

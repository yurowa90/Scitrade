# TASK-0032 M2a-5 직접 무역 물량 배수·판매 마진 조정(Q13-2 나)과 J1~J7 재측정

- codex_model: `gpt-6-astra`
- reasoning_effort: `high`
- 선행 작업: TASK-0031(+R1) 병합 기록 뒤 개발 브랜치 `a9303af`(이 지시서를 올린 커밋). 치환되지 않았으면 `git log -1 --format=%h -- docs/ai/tasks/TASK-0032-m2a5-trade-lots.md`의 해시를 쓰고 결과 보고 첫 줄에 적는다. 이 지시서는 개발 브랜치 `a9303af`(TASK-0031 병합 기록) 위에서 썼다.
- 결정 근거: Q13 가(물량 배수 확대), Q13-2 나(2026-10-12 사용자 결정, 물량 {1~5} + 마진 ×1.3). 측정 근거는 `docs/ai/design/m2a5-review/QUESTIONS3.md`다.
  - 물량 배수만 키우면 직접 무역 비중이 최대 17.6%에 그쳤다. 늘어난 것은 자금 거절이었다.
  - {1~5}와 k = 1.25를 함께 쓰면 25.29%였다. 하한에 너무 붙어 있어서 k = 1.3으로 여유를 둔다.
- **바꾸는 값은 두 가지뿐이다(`data/market_rules.json`).**
  1. `trade.max_lots_choices`: `[1, 2, 3]` → `[1, 2, 3, 4, 5]`.
  2. 판매(`side: SELL`) 행의 `base_price.amount`: `매입가 + 1.3 × (지금 판매가 − 매입가)`. 매입가는 같은 상품의 `BUY` 행이다. 계산 결과는 0.01 USD 단위로 반올림(half-up)하고, 계산값과 반올림값을 결과 보고 표에 적는다.
     - 세션 A 손계산(확인용, 자료와 다르면 자료가 사실이다): 의류 매입 10.00 → 하이퐁 14.00 → **15.20**, 상하이 13.50 → **14.55**. 화장품 매입 40.00 → 하이퐁 49.00 → **51.70**, 상하이 50.00 → **53.00**.
  - 매입가·지수·추첨 규칙·정책·판정식은 고치지 않는다. `max_lots_choices`는 묶음·상품마다 한 번 뽑으므로(`src/engine/market.ts`의 `pick(m.trade.maxLotsChoices)`) 목록 길이가 바뀌어도 추첨 횟수는 같다. 같은 시드에서 다른 추첨이 그대로인지 확인해 보고한다(묶음 1의 22개 추첨값을 바꾸기 전후로 비교).

## 목표

1. 두 값을 자료에 반영하고, 영향받는 시험 기대값을 손계산으로 다시 정한다.
2. 세 조건(기준·cap30·flat200) 20시드로 D03을 다시 재고 J1~J7을 판정한다.

## 구현 지시

### 1. 자료

- 위 두 값만 바꾼다. 스키마(`schemas/**`)에 목록 길이·최댓값 제약이 있으면 그 제약만 맞춘다.
- `python3 tools/validate_data.py`의 산술 검사가 판매가에 기대면 검사 기대값도 같은 식으로 맞춘다. 검사기 코드는 고치지 않는다. 고쳐야 하면 ‘질문’에 적고 멈춘다.

### 2. 시험 기대값

- 시세표·묶음 행·견적 가격·`maxQuantity`에 기대는 인수 사례(`tests/acceptance_cases.json`)와 시험의 기대값을 손계산으로 다시 정한다. 바뀐 칸마다 이전→새 값과 계산식을 결과 보고에 적는다.
- 시험 대상 함수나 같은 식으로 기대값을 만들지 않는다(TASK-0027 R1 규칙).
- 규칙 1 시나리오는 `operations`가 없어 이 값을 읽지 않는다. 규칙 1 골든·기본 `run` 400회가 바이트로 같아야 한다.

### 3. D03 재측정

- TASK-0031과 같은 세 명령으로 20시드씩 잰다. 결과 파일은 `docs/ai/tasks/results/TASK-0032-d03.md`, `-cap30.md`, `-flat200.md`.
- 결과 보고에 적을 것:
  - TASK-0031 대비 J1~J7 판정 변화. J7 비중(직접 무역·작업 포함·일반)은 조건별로 적는다.
  - 기준 회사 USD 순자산 중앙값과 직접 무역 계약 수, **손실 난 직접 무역 계약 비율**(사용자 요청 항목. 지금 규칙에서는 0%가 예상된다. 0이 아니면 사례를 적는다).
  - 직접 무역 수락 거절 사유(자금·보관·준비·선복) 중앙값과 평균 수락 묶음 수(묶음 단위).
  - 고용 표 ③·④에서 화살표가 바뀐 칸, J6 일치율의 조건별·투자별 변화.

### 4. 표본 밖 J6 확인(TASK-0031 R1 검수 권고)

- 병목 표 정의(묶음 0 제외, 보관 칸 최고 점유)는 시드 1001~1020의 관찰로 골랐다. 그래서 새 시드 1021~1040으로 **기준 조건만** d03을 한 번 더 재고, J6 일치율을 따로 보고한다.
- 실행기에 d03 전용 인수 `--seed-base N`을 더한다. 시드 목록은 `N, N+1, …, N+19`이고, 기본값은 지금처럼 `SIM_SEEDS`(1001~1020)다. 기본 명령의 출력은 바이트로 같아야 한다(기본 `run` 400회 `cmp` 0).
- 결과 파일은 `docs/ai/tasks/results/TASK-0032-d03-oos.md`다. J1~J7 판정을 모두 적되, 확인 대상은 J6다. 80% 이상이면 정의를 확정한다. 아래면 수치만 적고 해석하지 않는다(세션 A가 판단한다).

## 세션 A 확인 기록(확정 때)

- 병목 표 정의는 TASK-0031(+R1)로 확정됐다(보관 칸 최고 점유, 묶음 0 제외). 마진이 오르면 직접 무역 계약이 늘어 창고 점유가 바뀌고 J6 칸 예측도 바뀐다. 그래서 재측정 보고에 J6 변화를 꼭 넣는다.
- 판매가 손계산 네 값은 `data/market_rules.json`의 지금 값(의류 매입 10.0, 하이퐁 14.0, 상하이 13.5; 화장품 매입 40.0, 하이퐁 49.0, 상하이 50.0)에서 계산했다.
- `schemas/market_rules.schema.json`의 `max_lots_choices`는 정수 배열이라는 제약만 있다. 스키마는 고칠 필요가 없을 것이다.
- `pick`은 `Math.floor(draw() × 목록 길이)`로 한 번만 뽑는다(`src/engine/market.ts:23`). 그래서 목록 길이가 바뀌어도 추첨 수는 같고, 같은 추첨값이 다른 배수로 바뀔 뿐이다.

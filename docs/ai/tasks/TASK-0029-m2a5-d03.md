## 보충 규정 (반박 검토 반영, 앞 절과 다르면 이 절이 우선)

**회귀·시험 함정**
- 규칙 1 실행의 지표에는 `operations` 키를 **넣지 않는다**(조건부 전개 `...(ops ? { operations: ops } : {})`). `undefined` 값으로 두지 않는다. `compare.ts:20-26`의 `flatten`이 `undefined`·boolean에서 예외를 던지고, `sim.test.ts`의 비교 시험은 직렬화 전 객체를 쓴다. `metrics.operations` 안에도 boolean을 넣지 않는다(`outcome`처럼 문자열이나 0/1 숫자).
- 소스 검사: 기존 `sim.test.ts`는 고정 파일 6개만 읽고 금지어를 `SCENARIO_IDS`에서 만든다. `m2a5-sim.test.ts`에 같은 검사를 `src/engine/sim/*.ts` 전체(시험 파일 제외)와 `ALL_SCENARIO_IDS`·자료 ID로 다시 만든다. 변형 4는 이 시험으로 잡는다.
- 측정값에 기대는 단언 금지: 시험은 ‘조건을 만족하는 첫 시드’를 찾아 쓰고, 그 시드를 인수 명세 17에 적는다(예: `IDLE`이 71일에 실패하는 시드, `MAX_CONTRIBUTION`이 완료하는 시드). 어떤 시드도 조건을 만족하지 않으면 값을 고치지 말고 ‘질문’에 적는다.
- ‘늦은 편을 예약하지 않음’은 예약 단계에서 단언한다: `MAX_CONTRIBUTION`이 낸 `BOOK_SAILING`·수락 계획의 출항편마다 `도착일 + 통관일 ≤ 납기`. `LATE_OK`는 그 조건을 어기는 예약이 1건 이상 있는 시드를 찾는다.
- `d03` 시험은 정책 묶음을 주입해(예: 정책 3개·시드 1개) 표 제목과 J1~J7 줄이 나오는지만 본다. 전체 묶음을 vitest에서 돌리지 않는다.

**판정 정의**
- ↑·↓: 시드 수 N에 대해 ↑ = 중앙 ≥ +300·이득 시드 ≥ 0.75N·실패 ≤ 0.05N(내림), ↓ = 중앙 ≤ −300·이득 시드 ≤ 0.25N. N = 20이면 명세 17.2와 같다. N < 10이면 화살표를 쓰지 않는다.
- 칸 기준: 표 ①(기준)은 같은 시드의 `MAX_CONTRIBUTION`(환전 앞 7일·투자·고용 없음) 대비, 표 ②(투자만)는 같은 수락의 `inv:none` 대비, 표 ③·④(고용)는 같은 수락·같은 투자의 고용 없음 대비, `scout:early` 칸은 같은 고용·투자의 `scout` 없는 칸 대비다.
- 변형 이름: `{수락 정책}` 뒤에 `~fx:react`, `~inv:{S|E|SE|SE22}`, `~hire:{2pt|3pt}@{일}[+{…}]`, `~scout:early` 순서로 붙인다. `inv:none`과 기본 환전은 이름에 쓰지 않는다(같은 실행이 두 이름으로 돌지 않게). 수락 정책은 보통 `MAX_CONTRIBUTION`, 적극 `LATE_OK`다. `scout:early`는 보통에만 붙인다. `fx:react`는 **진단**이다(J3에서 뺀다).
- J3·표 ⑥의 1위 후보: 진단(`fx:react`, 두 명 고용)과 `IDLE`·`NO_FX`를 뺀 모든 변형(보통·적극, 투자·고용·scout 포함). 실패한 실행도 USD 순자산 그대로 넣는다.
- J6: ‘계획 고용일 아침 상태’는 **같은 수락·같은 투자의 고용 없는 실행**의 그날 아침(명령 전) 상태다. 시드 중앙값 계산은 정렬 뒤 가운데 두 값의 평균을 쓰고, 0.5 이상이면 예측 ↑, 0.5 미만이면 예측 ↓다. 이용률은 그 실행의 날마다 `handlingLog`의 `usedPt ÷ capacityPt`와 마감 보관량 ÷ 보관 한도이고, ‘이용률 높은 시드’는 고용일부터 캠페인 끝까지 둘 중 하나가 90% 이상인 날이 절반 이상인 시드다. 창고 대기는 `handlingLog.waits`의 업무-일 합이다.
- 감액 변형(cap30·flat200)의 줄인 묶음으로 계산할 수 없는 판정(J2b, J3, J5)은 ‘해당 없음’으로 적는다. flat200은 `lateDeliveryBasis = 'FLAT_ONCE'`, `lateDeliveryPriceReductionMinor = 20000`, `lateDeliveryCapBasisPoints = null`이다.

**정책 세부**
- ‘출항편 전에 끝남’은 `readyDay ≤ 출항일`이다(`quotePreview`와 같다).
- 영입 차단(`blocked`)은 H−3일부터 실제 고용일까지다. 그 동안 실행기의 `ASSIGN_TASK`도 그 직원에게 새 업무를 주지 않는다. 고용 명령이 7일 동안 계속 거절되면 그 실행의 영입을 포기하고 지표에 실제 고용일 null을 남긴다.
- 하루 명령 순서: `RESPOND_TO_DELAY`(지금 정책 그대로) → 환전 → 투자 → 영입 → 다시 예약 → 대기 업무 배정 → 견적 수락.
- 환전 식의 ‘원화 현금’은 `fundsPosition(state, config, 'KRW').available`(현금 − 미지급)이다. 쓸 수 있는 USD는 `fundsPosition(…, 'USD').available`이다.

**실행 시간**
- `src/engine/sim/run.mjs`에 `--workers N`(Node `worker_threads`, 기본 1)을 더해도 된다. 실행 순서와 출력은 워커 수와 무관하게 같아야 한다(실행 키로 정렬). 결정성 시험에 `--workers 1`과 `2`의 출력 바이트 비교를 넣는다.
- 고용 없는 기준 실행은 한 번만 돌리고 J6·칸 기준에 다시 쓴다(같은 키의 실행을 두 번 돌리지 않는다).
- 시드를 나눠 돌렸으면 `d03 --tables-from a.json,b.json [--late …]`으로 합쳐 표를 만든다(같은 실행 키가 겹치면 오류). 기준 실행이 3시간을 넘을 것 같으면 `--seeds 10`까지 돌리고 나머지는 ‘미측정’으로 적는다. 결과 보고에 실행 수·걸린 시간·워커 수를 적는다.

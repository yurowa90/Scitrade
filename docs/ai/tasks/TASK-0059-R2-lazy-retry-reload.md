# TASK-0059-R2 지연 불러오기 재시도 상한과 새로 고침 안내

- codex_model: `gpt-6.1-sol`
- reasoning_effort: `high`
- 선행: 개발 브랜치에 들어갈 `claude/m2a5-engine` `58c4cd5`(TASK-0059 R1 검수 병합 뒤, 이하 `<BASE>`). `codex/TASK-0059` `6bb8921`과 `src/`가 같다(`58c4cd5`는 검수 기록·측정 자료·`MANIFEST.json`이 더 있다). 기준 비교(`review_checks.sh`)는 `<BASE>`로 한다.
- 이번 작업은 `<BASE>`의 구현을 이어서 고친다. 원 지시서 `docs/ai/tasks/TASK-0059-code-split.md`의 원칙·손대지 않을 파일·지켜야 할 것은 이 문서가 바꾼 곳 말고 그대로다. 원 지시서 3절 ‘다음 시도에서 다시 `import()`한다’와 경고 문장은 이 문서가 바꾼다.
- 근거: 세션 B의 Chromium 오프라인 흉내 측정(2026-10-13)과 허브 판단.

## 무엇이 틀렸나

- 미리 받기가 끝나기 전에 연결이 끊겨 `import('./ops-screens')`(또는 `./culture-panel`)가 한 번 실패하면, 연결을 되살린 뒤 같은 주소의 `import()`는 **네트워크 요청 없이** 계속 실패한다.
  - 브라우저의 모듈 맵이 실패를 문서가 살아 있는 동안 기억하기 때문이다(HTML 명세의 module map 동작). Chromium 141에서 확인했다. 주소에 `?retry=1`을 붙이면 성공한다.
- 그래서 `lazyScreen`(`src/ui/lazy.ts`)이 실패한 약속을 버려도 재시도는 소용이 없다. 경고 문장의 ‘다시 눌러 주세요’도 사실이 아니다.
- jsdom 시험(`code-split.test.ts`의 흉내 import)은 이것을 잡지 못한다. 흉내가 두 번째 호출에서 성공하기 때문이다.
- 미리 받기 뒤에 끊긴 경우, 경고·상태 보존·`select` 되돌림은 세션 B 측정에서 정상이었다. 이 동작은 그대로 둔다.

## 허브 결정과 이유

- 주소를 바꿔 재시도하는 방식(쿼리 붙이기, 청크 주소를 오류 문장에서 꺼내기)은 쓰지 않는다.
  - Safari 오류 문장(‘Importing a module script failed.’)에는 주소가 없다. 알파 기기는 iPad다.
  - `vite.config.ts`·`index.html`은 손대지 않는 범위다. 오류 문장 파싱은 브라우저마다 다르고 깨지기 쉽다.
- 대신 **재시도는 한 번 남기고**, 그래도 실패하면 같은 문서 안에서는 더 시도하지 않고 새로 고침을 안내한다. 브라우저가 재요청을 허용하면 재시도로 그대로 성공하고, 허용하지 않으면 새로 고침 안내가 안전망이다.

## 구현 지시

### 1. `lazyScreen`의 시도 상한

- 한 화면 묶음마다 `loader` 호출은 **문서 하나에 최대 2번**이다(첫 시도 + 재시도 1번). 미리 받기의 시도도 1번으로 센다.
- 2번째도 실패하면 그 묶음은 ‘이 문서에서 불러올 수 없음’ 상태가 된다. 그 뒤 `ensure()`는 `loader`를 부르지 않고 바로 거절한다. 거절 오류는 다른 실패와 구별할 수 있어야 한다(예: 오류 클래스나 `exhausted` 같은 속성). 이름은 Codex가 정한다.
- 성공 뒤와 진행 중 공유 동작(같은 약속을 함께 기다림)은 지금과 같다.
- 도움말 주석(`lazy.ts` 1행)을 새 동작에 맞게 고친다. 모듈 맵이 실패를 기억한다는 이유를 한 줄로 적는다.

### 2. 경고 두 단계

- **재시도가 남아 있을 때의 실패**(첫 실패): 지금 경고를 쓴다. 다만 문장은 사실에 맞게 ‘화면 일부를 불러오지 못했습니다. 인터넷 연결을 확인하고 다시 눌러 주세요.’ 그대로 둔다(한 번은 실제로 다시 시도한다).
- **더 시도할 수 없을 때의 실패**(상한에 닿은 실패, 그리고 그 뒤 모든 진입):
  - 경고 문장: ‘화면 일부를 불러오지 못했습니다. 연결을 확인한 뒤 저장하고 새로 고침해 주세요.’
  - 알림 띠 안에 ‘새로 고침’ 단추를 둔다. 기존 알림 단추(`flash.action`, 지금은 `'culture-result'`)와 같은 방식으로 새 값을 더한다. 단추는 `location.reload()`를 부른다.
  - 저장하지 않은 진행이 있으면 기존 `beforeunload` 확인(`main.ts`의 `hasUnsavedWork`)이 새로 고침 전에 묻는다. 새 확인 창을 따로 만들지 않는다.
- **저장된 상태 불러오기(`load`)가 상한에 닿아 실패한 경우만** 문장을 바꾼다: ‘화면 일부를 불러오지 못했습니다. 새로 고침한 뒤 ‘불러오기’를 다시 눌러 주세요. 저장된 상태는 그대로 있습니다.’
  - 이유: 이 경우 ‘저장하고’를 따르면 불러오려던 저장 칸을 지금 화면 상태로 덮어쓴다. 파일 가져오기(`import`)는 파일이 따로 있으므로 일반 문장을 쓴다.
- 두 경우 모두 상태 보존(시나리오·오늘 할 일·패널 닫힘)과 시나리오 `select` 되돌림은 지금과 같다.
- 미리 받기의 실패는 지금처럼 조용히 둔다(콘솔 경고 하나). 미리 받기가 상한에 닿게 만들 수는 없다(1번뿐이므로). 다만 미리 받기가 실패했다면 진입점의 첫 시도는 재시도에 해당하므로, 그 시도마저 실패하면 바로 새로 고침 안내가 나온다. 이것이 의도다.

### 3. 시험(`src/ui/code-split.test.ts`)

기존 시험의 흉내(`failures`)는 그대로 두고, ‘모듈 맵 기억’ 흉내를 하나 더한다: 한 번 실패한 묶음은 그 뒤 모든 호출을 즉시 거절한다.

| 시험 | 확인할 것 |
|---|---|
| 재시도 성공 | 첫 진입 실패(기존 흉내) 뒤 재진입이 성공한다. `loader` 호출 2번. 기존 문화 패널 재시도 시험이 이미 덮으면 그대로 둔다 |
| 모듈 맵 기억: 시나리오 고르기 | 규칙 2 고르기를 두 번 한다. 첫 번째는 ‘다시 눌러 주세요’ 경고, 두 번째는 새로 고침 안내와 ‘새로 고침’ 단추. 세 번째 고르기는 `loader` 호출 수를 늘리지 않는다(2번 그대로). 세 번 모두 시나리오·`select` 값·오늘 할 일이 그대로 |
| 모듈 맵 기억: 문화 패널 | 같은 확인을 문화 패널 탭으로. 패널은 닫힌 채다 |
| 미리 받기 실패 뒤 | 미리 받기를 실패시킨 뒤 첫 진입이 실패하면 곧바로 새로 고침 안내가 나온다. `loader` 호출 2번 |
| 불러오기 문장 | 규칙 2 저장을 `load`로 불러오다 상한에 닿으면 ‘불러오기’ 문장이 나오고, 저장 칸의 값이 바뀌지 않는다. 같은 조건의 `import`는 일반 문장 |
| 새로 고침 단추 | 단추를 누르면 `location.reload`가 한 번 불린다(흉내) |

- 시험에 자료 ID·조정 상수를 새로 쓰지 않는다(TASK-0027 R1). 시나리오 ID 상수는 기존 시험 파일에 있는 것을 다시 쓴다.

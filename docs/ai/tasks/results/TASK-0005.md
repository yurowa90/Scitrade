## 설계 판단 (지시서에 없던 결정과 이유)

### A

- `initialUiState()`는 배열·객체·Set을 호출마다 새로 만든다. 성공한 새 게임·시나리오 전환·불러오기·파일 가져오기가 `resetUi()` 하나로 화면과 지도 기억을 비운다. 실패는 기존 상태·대기 명령·선택을 보존한다.
- 하루 확정뿐 아니라 다음 날 열기까지 성공한 뒤 상태를 교체한다. 엔진 예외는 한국어 상태 알림으로 돌려주며 엔진 규칙은 수정하지 않았다.
- 취소 안내는 `planState(CANCEL_CONTRACT)`가 새로 만든 `PREPAID_FREIGHT` 정산 분개에서 환급과 취소비를 읽는다. 화면에서 운임 차액을 계산하지 않는다.
- 0원 계약금은 엔진의 계약금 자금 거절과 실제 미지급 의무가 함께 있을 때만 원인 설명을 덧붙인다. 엔진 이유는 그대로 보존한다.
- 기존 이스케이프 시험은 임의 장소 ID 자체의 표시를 기대했다. 업무 대상 API를 쓰면 잘못된 장소 ID는 이름을 찾을 수 없으므로, 시험 설정에 그 장소와 위험 이름을 추가했다. 기존 기대값과 단언은 유지했다.

### B

- 실제 카드 경로는 설정을 전달해 `levelProgress`를 사용한다. 설정을 받지 않는 기존 카드 호출은 기존 엔진 시험 호환을 유지한다. M1 실제 화면에는 성장 상세·경험치·훈련을 추가하지 않는다.
- 훈련 후 다음 레벨까지 문구는 엔진이 반환한 경험치 증가량을 임시 사본에 적용하고 다시 `levelProgress`로 읽는다. 예상 레벨·능력·자금·기간·거절 판정은 `trainingPreview`, 급여 지급 가능일은 `payrollRunwayDay`에서 받는다.
- 한 번에 여러 레벨을 지나면 각 문턱을 엔진 함수로 읽어 각각 알린다. 능력 증가량은 진행 전 값 대비 누적 변화다(레벨 2 +2/+1, 레벨 3 +4/+2).
- 완료 알림은 새 보상 키를 읽어 하루 진행 직후 한 번만 상태 영역에 삽입한다. 재그리기 때 재삽입하지 않도록 알림 대기값을 소비하며 저장에는 넣지 않는다. 엔진 기록에는 기존 레벨 달성 로그가 남는다.
- 교육 상태는 `crewStatusKo`의 기호·글자를 공통으로 사용한다. 카드의 기존 픽셀 그림 요소와 지도 측정·배율·스크롤 콜백은 유지했다.

    - [nit] 각주의 일급, 대기 중 급여 줄 전체 숨김.
- **Claude 결정:** 훈련 블록에 처리량 문장을 일반 글자로 넣는다. 판단 지점에 단서를 두는 신호 원리(Mayer)를 따른다. T5가 측정하는 것은 ‘단서를 읽고 판단에 쓰는가’로 한정된다.
- **처리:** TASK-0005-R2(사용성 시험 준비)로 이어 간다.

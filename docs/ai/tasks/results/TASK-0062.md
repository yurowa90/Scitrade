## 설계 판단 (지시서에 없던 결정과 이유)

- 프로필의 snake_case 자료를 기존 엔진 관례에 맞춰 camelCase로 변환했다. 다섯 묶음을 모두 복사하며, 이번 위험 실행은 `fx`만 읽는다.
- 손익은 로컬 흐름 목록으로 계산한다. `realized`는 계약 현금 분개와 원래 의무 ID로 연결한 `SETTLE-` 분개, 남은 흐름에서 독립 계산한다. 단계 2·5·7은 별도 기대 흐름의 순차 대체 차이다. 같은 평가 환율의 USD 비용을 묶어 반올림하고 판매는 따로 환산한다. `residual`은 정의대로 남은 차이를 반환한다.
- 관세 시점 계산은 각 호출처에 남겼다. 여섯 호출처의 인수는 통과형 첩자로 직접 검사하며, 보고서의 0단계와 도착 전 예상 호출을 구분한다.
- 시험 구동기는 명령으로 환전·수락·직원 배정·예약을 실행한다. 미지급 사례만 지시된 시점에 짝 분개와 의무를 넣었다. rules-2 90일 커서 시험에는 주선 수입과 필요 원화 환전을 사용했다. R0/R1 시험에서 실행기·정책·d03은 호출하지 않았다.
- **상태 칸을 추가하지 않았다.** 계약·화물·청구서·시세 행·RNG·저장 형식 6의 구조가 같다. 새 값은 설정 또는 저장하지 않는 읽기 반환값이다.

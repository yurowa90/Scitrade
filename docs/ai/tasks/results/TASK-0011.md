## 설계 판단 (지시서에 없던 결정과 이유)

- TASK-0010의 CultureConfig·기록 필드 이름을 그대로 썼다. `completedTaskId`·`verifiedDay`는 도시에서 읽은 `countryCode`와 함께 저장한다.
- 문화 불변 조건은 `culture-invariants.ts`로 분리해 기존 장부·고용 검사와 함께 호출한다. 새 저장 판본이나 저장 필드는 필요하지 않았다.
- `culturePreview`는 기존 훈련 미리 보기와 같은 `previews.ts`에 두었다. `cultureBook`·`counterpartyRecord`는 `culture.ts`에서 내보낸다. 순환 의존을 더하지 않는다.
- 읽기 반환 구조: `cultureBook`은 `reports`(보고 문장 포함), `employees[{employeeId, experiences}]`, `relations[{employeeId, contactId, events}]`다. 고용 직원×활동 인물의 모든 쌍을 포함한다. 전체 반환값을 복제해 화면이 반환값을 수정해도 상태가 바뀌지 않는다.
- `waitingTasks`의 원소는 `{task, reservedDepartureDay}`다. 배정되지 않은 QUEUED 업무만 포함하고 활성 BOOKED 예약이 없으면 출항일은 null이다. `busyUntilDay`는 활동 마지막 날을 포함한다.
- 거절 미리 보기에도 훈련과 같이 ‘조건을 갖춰 실행했을 때’의 비용 차감 비교값을 제공한다. 급여 통화와 다른 비용은 급여 여유에서 차감하지 않는다.
- `counterpartyRecord`의 `inProgress/onTime/late/cancelled`는 미인도 진행·납기 안 인도·지연 인도·취소 건수다. 인도 후 수금 대기도 이미 확인된 납기 실적으로 센다. 회사·직원·인물 관계와 합산하지 않으며 저장하지 않는다.
- `CultureContactDef.nameKo`는 요구대로 `title_ko` 전체다. 지정 완료 로그의 ‘윤서·하람’은 현재 P0의 ‘역할 이름’ 제목에서 마지막 이름을 사용한다. 보고서 문장 내용으로 엔진 규칙을 정하지 않는다.
- 완료 기록과 보상은 tasks 순서다. 완료 로그 뒤에 첫 XP를 지급해 기존 업무처럼 레벨 달성 로그가 뒤에 남는다.
- **기존 시험 전제와 실제 요구의 차이:** TASK-0010의 `save-v5.test.ts`는 실제 M2 설정도 `culture: null`이라고 가정했다. M2 활성화 후 4개가 실패했다. 기대값·오류 문자열을 바꾸지 않고 비활성 시험에 `{...config, culture: null}`을 명시하고 불러오기에도 그 설정을 전달했다. 실제 M2 활성화·정상 저장은 신규 시험으로 검사한다. 이 변경은 경제 기대값 수정이 아니라 비활성 시험의 입력 전제 명시다.

### 설계 판단 (지시서에 없던 결정과 이유)

- X1·X2는 유효한 기록 옆에 올바른 키의 위조 기록을 추가한다. X3는 EMP02의 XP·지급 여부·지급액을 함께 추가한다. X4는 원래 비용을 보존하고 별도 분개를 정상 `post`하여 현금도 줄인다. X5는 기존 DONE 업무 옆에 새 RUNNING 업무와 그 날짜의 비용을 추가한다. X8은 기록 날짜도 함께 맞춰 완료일 계산 오류만 남긴다. X1~X8은 `cultureProblems`가 **해당 오류 하나만** 반환함을 별도로 단언한다.
- 기존 경험·관계의 동일 키 복제는 구조상 키 유일성과 완료 업무별 기록 개수 검사에 동시에 걸린다. 비용 중복은 일반 장부 ID 검사와, 일반 TASK-DONE/훈련비 재사용은 일반 경험치/훈련 검사와 겹친다. 이 중복 방어를 약화하지 않고, 목표 오류의 `toThrow(/…/)`를 반드시 요구했다. 아래 삭제 시험은 다른 오류가 남아도 해당 시험이 실패함을 확인한다.
- 첫 XP 중복 별칭은 문화 규칙보다 일반 지급 키 형식(`invariants.ts`)의 검사 대상이다. 기존 사례를 지우지 않고 별도 시험으로 옮겨 `SaveError`와 `/경험치 지급 기록 오류/`를 모두 요구했다.
- 실제 자료의 다섯 필드 변조는 2일차에 시작한 1일 활동을 1일차에 시작한 것처럼 `task.id`, `task.startedDay`, `fee.id`, `fee.day`, `ledger.postedIds`를 바꾼다. 비용 연결·장부 합계는 유효하지만 진행량 0과 경과일 1이 어긋나 불러오기에서 거절된다. 별도로 합성 2일 활동은 진행량 1→0 한 필드만 바꾼다.
- 불러오기 하한은 PENDING_OPEN·AWAITING_INPUT·ENDED 세 단계에서 확인했다. 하루 마감 상한은 실제 `commitDay` 검사와, 날짜를 올리기 직전 상태의 직접 불변 조건 검사로 확인했다.
- 비용 제한은 로더의 `reporting_currency`(반환되는 `payrollCurrency`)와 검사기에 전달한 같은 설정을 사용한다. 엔진에 설정을 직접 주입하는 기존 USD 합성 예약 시험은 유지했다.
- 기존 검사기는 JSON Schema의 `minItems`·`uniqueItems`를 해석하지 않았다. 스키마 변경이 저장소 검증에서도 효력을 갖도록 해당 두 키워드 지원과 회귀 시험을 추가했다.
- 역사 지시서를 시험 실행 중 읽는 의존성을 제거했다. 옮긴 12문장은 별도 일회성 원문 비교에서도 기존 지시서·현재 자료와 모두 일치했다.

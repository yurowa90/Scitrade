## 설계 판단 (지시서에 없던 결정과 이유)

- **선복 줄은 잔여 값 대신 사용량 / 한도를 표시했다.** 현재 `warehouseSummary(...).sailings`에는 `usedLiters`, `capacityLiters`, `usedGrams`, `capacityGrams`만 있고 잔여 칸이 없다. 지시서의 ‘화면에서 다시 계산하지 않는다’·‘표에 없는 값이 필요하면 만들지 말고 질문에 적는다’를 따라 차감 계산을 추가하지 않았다. 이 부분은 지시 1의 잔여 자리 표시를 완전히 충족하지 못한다. 질문 절에 확인 사항을 남겼다.
- 최근 4묶음 수요는 묶음마다 ‘공개일 견적 pt / 받은 pt’로 표시했다. 화면에서 네 묶음 합계를 다시 만들지 않는다. 보관·무게 단위 표시만 L→m³·g→kg로 변환한다.
- 투자 미리보기는 확정 `state`에 대기열과 후보를 한 번씩 적용한다. 확장은 효력일로 읽고, 선복 기간은 계획 상태의 계약 기록에서 읽는다. 거절 단추는 유지하며 엔진 문장을 그대로 표시한다. 이미 확장·계약한 경우에는 상태 글로 바꾼다.
- `operationsTopbar(view, config, state, pending)`는 기존 두 인자 호출도 허용한다. main은 확정 상태와 대기열을 명시적으로 넘긴다. 정상 단계·빈 대기열에서는 `commitDay`를 호출하지 않고, 예외 시 예상 줄을 생략한다.
- ‘환전을 빼면 경영 실패 예상’ 반례에서는 먼저 선복 명령을 넣고 환전을 빼서 비어 있지 않은 대기열을 유지했다. 대기열이 완전히 비면 지시 8대로 예상 줄 자체가 없다.
- `planState(view, [...pending, cmd])`는 중복 ID를 `DUPLICATE`로 거절하지만 후보 명령은 적용될 수 있다. 따라서 숫자 비교만으로 변형 6을 놓칠 수 있어, 실제 환전 대기열을 만든 뒤 계획 호출의 출발 상태가 확정 상태인지도 spy로 검증한다. 엔진의 중복 ID 규칙은 바꾸지 않았다.
- 저장 파일에는 UI 상태가 없으므로 `exchangeUsdMinor` 제거·`exchangeLots` 직접 초기화에 저장 이관이 필요 없다.
- 새 표는 고정 열 폭과 줄바꿈을 사용하고, 투자 단추는 기본 `button`으로 키보드 동작을 유지한다. 색 대신 ‘← 가장 좁음’·예정·거절 문장을 표시한다.

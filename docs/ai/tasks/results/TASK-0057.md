## 설계 판단 (지시서에 없던 결정과 이유)

1. `recruitmentPanel`과 `interviewBlock` 끝에 선택 인자 `state = s`를 추가했다. 기존 호출은 유지하고 실제 화면에서만 확정 `state`를 전달한다. 기존 면담의 원화 사용 가능액·고용 계획은 계속 `view`로 읽으며 새 목록만 `hiringOutlook(state)`로 읽는다.
2. 제약 이름은 `warehouse.ts`의 `constraintLabel`로 공유했다. 배열의 모든 병목을 `·`로 잇는다. 선복은 공개 `findSailing`과 기존 `routeLabel`로 표시한다.
3. 지급·실패·결산 보강은 읽기 전용 `money-alerts.ts`로 나눴다. 환전 기록이 4건을 넘으면 `details`로 접는다. 결산의 고정비와 환전 기록에는 통화 합계를 만들지 않았다.
4. 단계 직전 값은 `main.ts` 모듈 변수에만 둔다. `nextAnnouncement` 결과 뒤에 단계 변경을 이어 붙이며 같은 단계 재렌더·다음 날에는 반복하지 않는다. 공통 `resetUi`가 재시작·불러오기·시나리오 변경의 값을 초기화한다.
5. 주선 유효기간 읽기를 `visibleForwardingOffers`로 분리했다. 종료 분기로 견적판 전체를 숨기는 시험과 별도로, 실제 실패 기록에 남은 OPEN 견적의 기간 거름을 검증한다. 상태의 phase나 견적 칸을 고쳐 시험하지 않는다.
6. 기존 `restart`는 시나리오 기본 시드로 시작했다. 실패 화면의 ‘같은 시드’ 문구를 지키기 위해 실패 때만 공개 `restartWithSameSeed`를 쓴다. 기본 시드와 다른 저장의 실패도 재시작 전체 HTML이 같은 시드 첫 화면과 같음을 시험했다. 확인 창과 규칙 1·규칙 2 완료의 기존 재시작은 유지했다.
7. 종료 보고의 미지급 안내는 KRW뿐 아니라 USD 미지급도 포함한다. 실제 선복 요금 USD 미지급·원화 미지급 0 상태로 확인했다.

1. **면담:** `hiringOutlook(state)`를 쓰고, 고용이 대기열에 있으면 줄을 쓰지 않는다. 제약 이름은 `constraintLabel`을 같이 쓴다. 환전액은 `× lotUsdMinor`로 계산하고, 일급은 KRW, 기여이익은 USD로 통화를 붙인다.
2. **지급 알림:** 확정 상태에서 경고·위험일 때만 나온다. 회복 행동은 `lotsToSurvive`가 0이면 ‘오늘 마감에는 실패하지 않습니다’로 쓰고, `lotsToClearAll`을 먼저 보인다. USD 미지급이면 다음 수금과 원화 비용을 쓴다. ‘환전 칸으로’는 `exchange-h`(이제 `tabindex="-1"`)로 간다.
3. **실패 화면:** 제목은 `failure.day`를 쓰고, 원인 문장은 따로 만들었다. 통화별 줄에 합계가 없다. 두 목록과 단추가 있다.
4·5. **결산·원화 보고:**
   - 고정비 표는 0인 행을 빼고, 모든 행이 0인 통화는 ‘고정비 없음’으로 쓴다. 환전 기록이 4건을 넘으면 접는다.
   - 통화 간 이체 행과 미지급 행 이름 변경은 규칙 2에서만 한다.
6. **선복 줄:** ‘노선 이름 + 출항일 편’으로 바꿨다.
7. **끝난 캠페인(SF-1·SF-3·F3):** 막대의 종료 분기, 환전 칸·견적판 숨김, 주선 유효기간 거름(`visibleForwardingOffers`)이 들어갔다. 변형 9~11이 잡힌다.

## 설계 판단 (지시서에 없던 결정과 이유)

- 뺄 수 있는 항목도 모두 구현했다. 기존 사례의 값·기존 출처의 값(허용된 DESIGN-V03 경로 제외)·TS 시험·교과 연결 자료는 유지했다.
- `linked_count`로 문자열 경로의 연결 수를 공통 계산하고, `string_values`는 사전 키를 제외한 문자열 값만 수집한다. 출처 ID가 단순히 키에 있거나 다른 출처의 설명에 나오는 것을 쓰임으로 세지 않는다.
- 잘못된 경로 형식은 파일을 읽지 않고 지정 오류로 수집한다. 시험 이름이 문자열 목록이 아니면 개별 제목 검사를 건너뛰어 예외 대신 지정 오류를 남긴다. 잘못된 사람 기록 객체도 필드 오류로 처리한다.
- 날짜는 지시한 YYYY-MM-DD 형식만 검사한다. 달력상 실제 날짜 여부, 사람의 신원·실제 검수 여부를 자동으로 인증하지 않는다. `human_review_records`는 비어 있고 `engine_test_pass_claim`은 false다.
- `strip_comments`는 지시된 간단한 정규식 규칙이다. TS 구문 분석기가 아니므로 문자열 안의 `/* … */`도 지워질 수 있고, 여러 줄 템플릿 안의 줄 첫 `//`도 주석과 구별하지 못한다. 코드 뒤의 인라인 `//`, 문자열 안의 호출처럼 보이는 문장을 전부 해석하지 않는다. 역방향 제목 규칙은 이스케이프가 든 문자열과 `$`가 든 백틱 제목도 제외한다. 연결 대상으로 정한 제목에서는 누락이 없었다.
- 현재 시험 제목은 표와 모두 같아서 대체 제목을 쓰지 않았다. 의도적으로 제외한 템플릿 제목은 `src/engine/acceptance-p0-time.test.ts:61`, `:73`, `:83`, `:92`의 `${timing}` 제목이다. 이들은 사례 ID가 있는 describe와 저장 시점 대응 설명으로 연결했다. `:101`의 it.todo는 별도 할 일 제목 검사로 확인한다.

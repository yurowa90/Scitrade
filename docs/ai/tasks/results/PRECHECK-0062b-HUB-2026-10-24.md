# TASK-0062b 허브 사전 검수 (초안 a8839fa, 2026-10-24)

- 방식: 세 관점(범위·명세·변형 시험)이 지적하고 관점마다 반박 검증 1회. 검증자는 사본에서 90회를 다시 돌려 도달 여부와 해시 변화를 확인했다.
- 처리: 고칠 곳 12개가 모두 지시서 본문이지만, R0 18회를 더하면 8절 대조값과 시제품 수치가 바뀐다. 그래서 허브가 직접 고치지 않고 세션 A에 개정 1을 요청한다.

## 1. 요약

- 검수 관점은 cover, spec, mut 세 가지다. 검증자가 real=true로 판정한 결함은 12건이다. 겹치는 것을 합치면 실제 결함은 9가지다.
- 중대 결함은 세 가지다.
  - R0 제외 근거가 틀렸다. R0 실행의 `metrics.risk`는 어떤 골든도 해시하지 않는다.
  - 변형 5는 공시일 탐침을 따로 검증하지 못한다. 기대 결과도 판정 기준이 아니다.
  - 변형 9는 구조상 반드시 0이 나온다. 그래서 아무것도 증명하지 못한다.
- 기각은 1건이다.

## 4. 결론


1. 75행: 'R0는 rules-2 그대로이고 0062a가 덮는다' → 'R0의 상태는 0062a가 덮지만 R0의 `run.metrics.risk`는 덮이지 않는다. 그래서 R0 18회를 묶음에 넣는다.'
2. 59-62행과 2절: 실행 집합에 R0 × {NO_FX, MAX_CONTRIBUTION} × (가)(나)(다) × 2001~2003, 18회를 더한다. 다섯째 인수는 'R0'다. 묶음 줄 수를 90 → 108로 고친다. R0 줄에서 탐침을 어떻게 다루는지 적는다.
3. 105행: riskLevel 허용 값 R1·R2·R3 → R0·R1·R2·R3.
4. 89-91행: 공시일 탐침에 '열려 있는 forwarding 제안마다 `quotePreview(opened, cfg, { offerId })`'를 더한다.
5. 94-96행: 지문을 원문 지문과 로더 지문으로 나누고 메시지를 가른다. 나누지 않으면 TASK-0067 주의 문구를 더한다.
6. 131행(시험 5): 예 'R0 또는 FOCUS' → 'R3·FOCUS·2001'. 실행 전 거부를 단언하는 조건을 더한다. R0 형식 거부는 7·8번 옆으로 옮긴다.
7. 135행(시험 9): '표준 오류에 `…회, 워커` 줄이 없음'을 더한다.
8. 143행: cancel > 0, `quotePreview` 호출 > 0, `contractRiskReport` 호출 > 0, probeHash가 빈 sha256이 아님을 단언하게 한다.
9. 199행(변형 1): '`fx.stepBp`를 `fx.stepBp - 1`로' → '29행의 두 `fx.stepBp`를 모두 `(fx.stepBp - 1)`로'. 기대 결과는 해시 종류별로 다른 줄 수를 적는 꼴로 바꾼다.
10. 201행·207행(변형 2·9): 변형 9의 대상을 rules-2 실행도 지나가는 공유 코드의 rules-3 분기로 바꾼다(`preview`의 `if (risk)` 분기나 engine.ts:1146). 그 함수가 rules-2 실행에서도 불린다는 근거를 적게 한다.
11. 203행(변형 5): 대상 칸을 `referenceEstimate.saleKrw` 또는 `surchargeMaxBp`로 정한다. FORWARDING 칸 대상을 하나 더 둔다. 기대 결과는 'runHash·stateHash는 모든 줄에서 같고, probeHash가 다른 줄이 1개 이상'으로 한다. 공시일 탐침을 끄고 다시 확인하는 단계를 더한다. 위치 표기는 'readers.ts:33 `quotePreview`가 부르는 `preview()`의 rules-3 분기'로 바로잡는다.
12. 211-216행: 범위 보고에 ⑤ 'rules-3 분기 도달표'를 더한다. 도달 횟수가 0인 행에는 지키는 단위 시험을 적는다. TASK-0067 지시서에도 그 시험을 바꾸지 말라는 조건을 넘긴다.

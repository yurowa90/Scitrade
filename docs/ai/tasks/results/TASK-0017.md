## 설계 판단

- 동점은 안정 정렬로 원래 후보 순서를 보존한다. 직접 무역 쌍 다음 운송 주선, 출항편 다음 직원 순서이며 ID 정렬은 없다.
- 유효기간이 지난 견적은 미리 보기·계획 검사 전에 제거한다. 결정적 정책의 계획 탐색·유지 작업은 첫 성공에서 멈추고, 무작위 정책만 가능한 조합 전체를 검사한다. `fits`는 지시대로 앞서 고른 모든 명령을 포함해 `planCommands`를 호출한다.
- 비교 첫 줄의 실행 수를 전달하려고 `CompareResult`에 `comparedRuns`를 추가했다. 원래 제시된 필드만으로는 `formatCompare(result)`가 공통 실행 수를 알 수 없다. 판정은 지정된 실행 집합·명령 수·지표만 쓴다.
- 누락된 경로와 값이 `null`인 경로를 구분해서 차이를 찾는다. 표시값은 지시대로 양쪽 모두 `null`이 될 수 있다. 메타 배열은 원소 경로까지 비교한다. 중복 실행 키는 조용히 덮어쓰지 않고 오류로 거절한다.
- `runSuite`의 빈 목록·중복 입력과 안전한 정수가 아닌 시드를 거절한다. 명령줄도 중복 옵션·빠진 값·소수 시드 수를 거절한다.
- 요약에서 인도가 없는 실행은 `해당 없음`으로 표시하고, 같은 묶음에 유효 비율과 빈 분모가 함께 있으면 두 정보를 모두 표시한다.
- 시험 사이에서 같은 원본 시뮬레이션 결과를 재사용한다. 결정성 시험의 두 묶음과 이름 변경 설정의 실행은 독립적으로 수행하며 지시된 시드 수를 줄이지 않았다.
- TASK-0016 병합 시 합칠 계산 후보를 주석에 표시했다. 아직 없는 함수는 import하지 않았다.

## 사용법

```bash
npm run sim -- run --out /tmp/scitrade-sim-a.json

```

다른 커밋과 비교할 때는 작업 트리를 바꾸지 않고 사본을 만든다. `<기준커밋>`을 원하는 커밋으로 바꾸고, `/tmp/scitrade-sim-other`는 비어 있는 새 경로를 사용한다. 사본의 기존 의존성이 현재 잠금 파일과 호환되는 경우 현재 의존성을 연결한다.

```bash
mkdir -p /tmp/scitrade-sim-other
git archive <기준커밋> | tar -x -C /tmp/scitrade-sim-other
cp -r src/engine/sim /tmp/scitrade-sim-other/src/engine/sim
ln -s "$PWD/node_modules" /tmp/scitrade-sim-other/node_modules
node /tmp/scitrade-sim-other/src/engine/sim/run.mjs run --out /tmp/scitrade-sim-other.json
npm run sim -- compare /tmp/scitrade-sim-other.json /tmp/scitrade-sim-a.json
rm -r -- /tmp/scitrade-sim-other
```

사본의 `package.json`을 바꿀 필요가 없다. JSON에는 측정 시간을 넣지 않고 실행 시간은 표준 오류에만 출력한다. 비교는 같으면 0, 다르면 1, 입력·실행 오류이면 2다.

## 범위 밖 발견

- 새로 발견한 엔진 예외나 기존 시험 실패는 없다.
- 기존 견적은 초반에 모두 만료된다. 현재 정책으로 미배정 업무·출항 불참 후 다시 예약하는 경로는 전체 400회에서도 지나가지 않는다. 정책에 처리 분기는 있으나 실제 자료에서 적용되었다고 주장하지 않는다.
- 영입·훈련·현지 활동 명령, 재고 회전·공급자 집중도·시설 지표, 지급 불이행에 따른 실패 비율은 지시대로 제외했다. 해당 경제·자료가 확장될 때 정책과 지표를 더할 필요가 있다.
- TASK-0016 병합 후 정시 인도율·순자산 계산 통합은 Claude의 후속 검수 범위다.
- 기존 화면 빌드의 큰 묶음 경고와 그림 도구 시험의 Pillow 폐기 예정 API 경고는 변경하지 않았다. 둘 다 검증 실패는 아니다.

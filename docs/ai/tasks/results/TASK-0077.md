- 새 화면 코드는 `ops-screens.ts`가 재수출하는 지연 파일에 모았다. main에서 읽기 함수를 새로 정적 import하지 않았다.
- main의 조건 분기·이벤트 본문을 줄이려고 조건별 명령 속성, 문구, 날짜 정리, change 처리를 지연 함수로 위임했다.
- `toggle`은 main에서 `addEventListener('toggle', ..., true)`로 캡처하고 `data-p11-key`를 저장한다. DOM의 open을 다시 읽는 방식은 쓰지 않았다.
- 대화상자를 app의 직접 자식으로 두고 바깥 형제의 inert를 복원하도록 작성했다. `situation.ts`는 가져오지 않았다. 실제 브라우저 초점·넘침 검증 전이다.
- 타임라인은 읽기 값인 lockDays를 meter의 value로 넘긴다. 별도 기간 비율 계산을 만들지 않았다.
- `AnyScenarioId`는 현재 `ALL_SCENARIO_IDS`에서 파생되어 새 ID를 포함하지 않는다. 첫 구현의 제목 Record 타입에서 TS7053을 확인했고, 허용 파일인 main의 제목 표 타입만 `typeof LOADABLE_SCENARIO_IDS[number]`로 바꾸어 해결했다. 시나리오 모듈은 고치지 않았다.
- 허브 개정 2에 따라 제목은 `scenarioTitle`로 읽는다. `loadScenario` 30회 측정(C21)은 폐기된 요구라 실행하지 않았다.

### 첫 화면 예산: 멈춤 근거

BASE를 `git archive HEAD`로 .git 없는 `/tmp/task0077-base`에 풀었다. 같은 archive로 만든 `/tmp/task0077-after`에 작업 파일만 덮어 썼다. 의존성은 기존 node_modules를 링크했고 패키지를 설치하지 않았다. 두 사본의 빌드 표시는 모두 dev다.

1. BASE: `npm run build`, `node tools/check_bundle_size.mjs dist`.
2. 화면 몫: 작업 뒤 사본에서 main의 제목 표와 select만 ALL_SCENARIO_IDS로 되돌려 위 명령 실행.
3. select 몫: 같은 사본에 작업 뒤 main 원문을 복원하여 위 명령 재실행.

모든 수치는 `check_bundle_size.mjs`와 같은 gzip level 9다. Vite의 요약 gzip 숫자와 섞지 않았다.

| 첫 화면 gzip | 132,034 B | 134,580 B | 134,562 B | **+2,546 B** | −18 B |
| index gzip | 97,081 B | 86,610 B | 86,592 B | −10,471 B | −18 B |
| CSS gzip | 7,289 B | 7,440 B | 7,440 B | +151 B | 0 B |

화면 몫은 300 B보다 **2,246 B 많다**. index 감소만 보면 안 된다. 새 operations 청크가 modulepreload로 첫 화면에 포함되어, 첫 화면 JS 합계는 +2,395 B, CSS는 +151 B다. 전체 저장소의 140,000 B 한도 검사는 통과하지만 이번 작업의 별도 예산은 실패다. 이 결과를 확인한 즉시 추가 기능 구현을 중단했다. CSS 지연화·엔진 분리·빌드 설정 변경은 하지 않았다.

새 공유 청크의 발생은 확인했지만 이를 없애는 구조 변경이나 원인별 대조 실험은 진행하지 않았다. 5.2 허용 목록 밖의 첫 화면 함수를 새 파일에서 호출한 것은 없다. 실제 새 값 import는 `cityName`, `goodOf`, `offerDef`, `formatMoney`, `esc`, `liveRegionText`, 지연 `creditTermOptions`, 기존 경로 11 읽기 함수와 줄 이름이다. initialUiState는 typeof 타입 참조에만 쓴다.

전체 빌드에서 문자열 `조건 비교`, `자금 부족으로 못 받은 견적`은 index와 operations 공유 청크에 없고 ops-screens에만 있음을 확인했다. ops-screens는 여전히 나중에 받는다.

## 설계 판단 (지시서에 없던 결정과 이유)

- 기존 소스 검사(`m2a5-sim.test.ts`)는 모든 비시험 TS 파일의 자료 ID 리터럴을 금지한다. 이번 지시서의 FOCUS 고정 상수 예외와 함께 지키기 위해 ID는 `sim/policy-constants.json` 한 곳에 명시하고 `FOCUS_GOOD_ID`가 읽게 했다. 문자열을 쪼개거나 기존 금지 시험을 바꾸지 않았다. 값은 시나리오의 첫 품목과 무관하게 고정된다.
- 기존 `runD03({ policyIds: [] })`는 시뮬레이션 없는 표 고정물 생성에도 쓰인다. 최초 추가했던 빈 정책 목록 검사는 제거해 기존 동작을 보존했다.

- `simulate`의 기존 관찰 콜백을 보존하고 마지막 선택 인수로 위험 층을 추가했다. 옵션이 없으면 위험 보고서를 호출하지 않는다.
- `SimIo.marketRulesSha256`은 기존 호출부 호환을 위해 선택 인수지만, 위험 실행에서는 올바른 소문자 SHA-256 문자열이 없으면 오류다. 파일은 Node 경계에서만 읽는다.
- 계약 분류는 한국어 값 `열린/완료/취소`로 냈다. 열린 계약이 아닌데 완료·취소도 아니면 묵시적으로 분류하지 않고 오류를 낸다.
- 진단 T는 지시서 문장의 ‘기준 회사의 도착한 onTime 계약’을 분모로 쓴다. F·손실 판정은 명시된 직접 무역 집합을 쓴다. B는 정책별 실행 집합이다.
- 손실 비율의 사분위는 정렬 후 아래·위 절반의 중앙값이다(홀수면 가운데 원소는 양쪽에서 제외). 분모가 0인 시드는 이 진단 요약에서 제외한다. 판정 기준에는 사분위를 쓰지 않는다.
- 손실 주원인 음수 칸이 같으면 지시서에 열거된 칸 순서를 유지한다. 음수 칸이 없으면 별도 ‘음수 칸 없음’으로 센다.
- J3 등 전체 묶음 판정에는 필요한 실행 키를 검사한다. 작은 확인 출력의 `실행 없음`·`근거 부족`은 정상적으로 실패 표기한다. (가) R0의 두 출력에서 읽는 판정 구분은 지시서 그대로다.
- 옛 USD J7도 위험 출력에서 판정할 때는 분수 중앙을 BigInt로 비교한다. 위험 옵션 없는 옛 출력의 경로와 문구는 유지했다.
- 규칙 밖 엔진 결함은 발견하지 않았다. 판정값이나 고정 상수는 확인 실행 결과에 맞춰 바꾸지 않았다.

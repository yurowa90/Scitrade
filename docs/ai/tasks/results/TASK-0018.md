## 설계 판단 (지시서에 없던 결정과 이유)

- Tab 시각 초기값을 `-Infinity`로 두었다. 첫 Tab 전에는 시각이 0인 시험 환경에서도 포인터·코드 초점을 복원하지 않는다.
- 건너뛰기 숨김은 `.skip-links:not(:focus-within)`에 적용했다. 숨긴 상태의 단추만 `min-height: 0`으로 덮고, 초점을 받아 나타난 단추는 기존 터치 44px 규칙을 받는다.
- 고용 미리 보기 ID 충돌도 새 시험에서 확인했다. 이미 처리된 ID에는 지시대로 `-`를 붙여 원본 상태가 바뀌지 않은 사본을 계산한다.
- 지급 가능일 함수는 지시대로 `growth.ts`에 추가했다. 문화 화면의 같은 문구 함수는 범위 밖이므로 합치지 않았다.
- `cultureResultFresh` 필드를 남겼다. 새 알림 추적 값은 모듈 변수이고 초기 화면 상태 필드와 기존 초점 복원은 유지했다.

## Tab 순서 표 (정적)

## 범위 밖 발견

- `src/ui/map.ts:125`: 지도 이름표는 `1장 ${c.availability.stage} 단계에서 열림`으로 M3를 보여 준다. 지도 파일을 수정하지 않았다.
- `src/engine/engine.ts:145`: 공지 근거에 ‘시나리오에 고정된 가상 항만 공지(DESIGN). 실제 기상 자료가 아니며, M1에서는 예보와 실제 제한이 같습니다.’가 남는다. 엔진 문장을 수정하지 않았다.
- `data/scenarios.json:71`: 가정에 ‘수출 준비 2pt는 EMP01의 하루 처리량과 같아…’가 있어 M1 가정 목록에 내부 직원 ID가 보인다. 자료를 수정하지 않았다.
- 지급 가능일 글자 함수는 `growth.ts`의 `payrollRunwayKo`와 `culture.ts:191`의 지역 함수에 중복된다. 금지 파일인 문화 화면은 읽기만 했다.
- 한 열 배치와 DOM Tab 순서의 두 차이는 위 표와 같다. 배치 변경 B53 범위로 남긴다.
- 실제 Chromium·WebKit·iOS beforeunload·화면 읽기 프로그램의 발화는 확인하지 않았다. Shift+Tab 보정 효과(0±8px), 읽던 자리 유지, 터치 행 높이·가로 넘침 등은 Claude의 실제 배율 브라우저 검수가 남는다.
- 빌드 청크 크기 경고는 이번 범위 밖이다.

## 질문

기본값으로 모두 구현했다. 구현을 진행하기 위한 질문은 없음. Claude는 운영표의 터치 행 높이, 한 열의 Tab 순서 차이, Shift+Tab 복원의 실제 브라우저 효과를 확인해야 한다. 고용 뒤 지급 가능일이 ‘없음’일 때 추가 경고 문단은 넣지 않았다(지시서 기본값).

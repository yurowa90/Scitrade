## 설계 판단 (지시서에 없던 결정과 이유)

1. A-2는 **(가) 기존 필드 보존**을 선택했다. 기존 M1 검산과 범위 밖 UI가 `preDepartureFreightRefundMinor`를 참조하므로 호환 필드는 보존하고, 실제 정산만 예약별 계산으로 바꿨다. `note_ko`는 M1·M2 시나리오 객체에 두고 설명에서 `contract_terms.pre_departure_cancellation.freight_refund`를 명시했다. 취소 조건 객체의 스키마는 임의 필드를 허용하지 않고, (가)에서는 스키마 수정이 범위 밖이기 때문이다. 기존 `notes_ko`의 취소 설명도 바로잡았다.
2. 취소비가 선급 운임보다 크면 분개 전에 일반 `Error`로 `자료 오류 — 취소비(...)가 선급운임(...)보다 큽니다.`를 알린다. 정상 게임 규칙 거절이나 기존 고정 합계 `EngineError`와 구분하며 입력 상태는 보존된다.
3. 저장 판본을 바꾸지 않았다. `deserializeSave`는 이미 이관 후 모양·불변 조건을 검사했으므로 순서는 유지하고 회귀 테스트를 강화했다. 판본 1~3 정상 이관은 기존 테스트로 확인한다.
4. 난수 커서는 추첨 횟수이므로 음수도 잘못된 값으로 거절한다. 정수 금액·수량·일자의 기존 모양 검사는 유지했다.
5. 없는 직원의 훈련 미리보기는 실제 명령의 거절 이유를 유지하고 `xpGain: 0`, `levelAfter: null`, `statsAfter: null`을 반환한다. 정의는 있지만 상태에 없는 직원도 같다.
6. 현재 테스트 파일에는 시드별 무작위 저장 왕복 테스트가 없어 8개 고정 시드 × 20일 × 하루 3개 명령을 추가했다. 매일 시작·마감 저장 복원과 저장 없는 진행의 전체 상태·명령 결과를 비교한다.

## 범위 밖 발견

- `src/ui/main.ts:368`의 취소 안내가 여전히 `preDepartureFreightRefundMinor`(ROUTE01 예시 150 USD)를 표시한다. ROUTE02의 실제 환급은 이번 수정으로 130 USD이므로 UI 안내와 다를 수 있다. UI는 명시된 제외 범위여서 수정하지 않았다. 후속 UI 작업에서는 해당 예약의 `prepaidFreightMinor - preDepartureCancellationFeeMinor`를 표시해야 한다.
- 지시서에 언급된 기존 무작위 저장 왕복은 현재 저장소 테스트에서 찾지 못했다. 위의 고정 시드 왕복 테스트를 추가했다. 기존 판본 1~3 정상 이관 테스트는 존재하며 통과했다.

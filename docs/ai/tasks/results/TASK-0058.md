## 설계 판단 (지시서에 없던 결정과 이유)

- 시세표에 `tabindex="0"`을 명시했다. Safari에서도 키보드로 가로 스크롤할 수 있게 한다. 넘침이 없는 폭에서도 Tab 순서에 한 번 들어간다.
- 투자 details는 재그리기 전 DOM의 `open` 값을 UI 변수에 보관한다. 대기 투자 ID·예정/체결 투자 내용이 바뀌면 자동 펼침을 다시 적용한다. 평소에는 사용자의 열기·닫기를 유지한다. 기존 main에는 일반 details 상태 보존 방식이 없었다. 투자 성공 뒤 단추가 표시로 바뀌면 기존 대안 초점 경로를 유지한다. 단추가 남는 환전 성공 및 투자 거절에서는 단추 아래 끝이 알림 띠 위 8px에 들어오도록 필요한 거리만 굴린다(72px 예약 포함).
- 환전 보정 문장은 queue와 환전 change에서 먼저 계산한다. 다른 명령이 환전 가용액을 줄일 때도 queue 알림에 붙인다. render는 기존 알림 결정 순서를 유지한다. KRW→USD 보정은 남은 원화라고 적는다.
- 다가오는 선복 요금은 `upcomingPayments(view, config, config.campaignDays)`에서 날짜가 있는 SPACE_FEE 행만 합산한다. 기본 인자 범위는 오늘부터 6일 뒤까지여서 캠페인 전체의 고정 지출을 보여 주려면 종료일 인자가 필요하다. 편당 요금·출항 횟수를 화면에서 다시 계산하지 않는다.
- `reportPanel`의 환전 권유는 선행 TASK-0057에서 이미 `exchangeAdvice` 변수 하나로 묶여 있었다. 그 변수를 그대로 쓰면서 `fxLotKo`를 적용했다. TASK-0057의 종료 분기는 보존했다.
- 일정의 실제 `ScheduleItem.kind`는 운임·관세 모두 `PAYMENT`다. FREIGHT·DUTY는 key와 원본 지급 행의 종류다. 시험은 코드 계약에 맞춰 kind=PAYMENT, 날짜·문장·금액을 전체 비교한다. 금액 -20000·-5000은 지시서가 지정한 규칙 1 기대값이다.
- 공용 최소 DOM 파일은 허용 범위 밖이다. 새 시험 파일에서 시세표의 `scrollLeft`와 투자 details의 `open`만 보강해 실제 main의 재그리기·열 전환 수신기를 실행했다. 실제 Chromium 위치와 낭독기는 세션 B의 별도 확인 대상이다.
- 기존 해시·기준 문자열은 바꾸지 않았다. 규칙 2 첫 화면 해시 시험에는 새 `market-scroll` id·tabindex만 제외하는 정규화를 추가했다.

## 설계 판단 (지시서에 없던 결정과 이유)

- 장소 제목·종·단서는 기존 JSON에서 읽는다. 엔진 정의에 없는 표시용 콘텐츠를 위해 엔진 타입이나 규칙을 변경하지 않았다.
- 면담에서 요구한 계약금·남은 급여의 곱셈은 읽기 전용 화면 함수가 엔진 정의·오늘 날짜에서 도출한다. 계산 결과는 상태나 저장 파일에 넣지 않는다. 사용 가능 원화는 `fundsPosition`, 위험 개수는 `contractProgress`, 실제 고용 허용 여부는 기존 `tryCommand` → `planCommands`에서 가져온다.
- 담당 선택의 기본값은 엔진이 허용하는 첫 고용 직원이다. 플레이어가 직접 선택한 직원은 다른 업무를 시작해도 유지하며 버튼 옆에 엔진 거절 이유를 표시한다.
- 카드와 운영표는 `crewEntries`의 동일한 목록을 사용한다. 미발견 후보는 제외하고, 고용 당일은 ‘고용됨 — 다음 날부터 근무’를 표시한다. 실제 근무 목록·배정·인원 수는 TASK-0001의 `employedDefs`를 유지하여 다음 날부터 포함한다.
- 공개 판정은 `processedCommands`의 오늘까지 APPLIED 배정·예약 기록을 각각 확인한다. 화면이 이미 사용하는 `planState` 사본에도 대기 명령의 기록이 생기므로 같은 날 즉시 공개된다. 대기 명령을 빼면 다시 판정한다. 일괄 수락 명령만으로는 공개되지 않는다.
- 실제 TASK-0001 코드에는 새 명령 세 종류의 `commandLabel`이 이미 있었다. 이를 유지하고 조사 장소의 내부 ID를 한국어 제목으로 개선했다.

브라우저 확인은 지시대로 실행하지 않았다. 아래 기능 판정은 화면 함수 테스트와 코드 연결 확인의 근거이며, 실제 클릭과 390px 가로 넘침 측정은 Claude 검수 대상이다.

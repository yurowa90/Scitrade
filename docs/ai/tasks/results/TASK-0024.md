새로 보이는 글은 `오늘 할 일 N건`, 접근 이름은 `오늘 할 일 N건 보기`다. 다른 학생용 문장을 바꾸지 않았다. N은 ui.pending.length이며 오늘 할 일 목록의 줄 수다.

| 반례 | 처리와 근거 |
|---|---|
| 수락을 뺀 뒤 실행할 수 없는 배정만 남음 | 목록 bad 한 줄·1건. 새 시험 8에서 HTML 전체 문자열과 목록 줄 수 확인 |
| 90일 종료 | endDay가 pending을 비우고 종료 뒤 queue가 명령을 거절하므로 0건. 단추는 종료 안내·결산 보기가 있는 queue-h로 이동. 이번 새 시험에는 별도 종료 시험을 추가하지 않음 |
| 하루 시작, pending 없음 | 0건. 시험 8·9에서 전체 단추 HTML 확인 |
| accept-plan 수락·배정·예약 묶음 | queue에 들어가는 하나의 명령을 한 목록 줄로 그려 1건. 기존 accept-plan 코드 그대로 사용 |

지시서의 한글 낱말 검사 출력:

```text
0a1,2
> 건
> 건 보기
1a4
> 오늘 할 일
```

`>` 줄은 건·건 보기·오늘 할 일 셋뿐이고 `<` 줄은 없다. 주석을 제외한 추가 문구와 기존 문구 보존이 조건과 일치한다.

## 범위 밖 발견

- 면담 제목 h4에는 tabindex=-1이 없다. 이 작업은 Esc 뒤 면담 단추로 초점을 돌려주므로 제목에 focus를 호출하지 않으며 이번 목표에는 필요하지 않았다. 펼침 띠에서는 제목의 위치만 읽는다. recruitment.ts는 변경하지 않았다.
- 한 열의 자원 제목 이동은 이번 열 규칙 대상 밖이다. 임시 시험에서 설정의 견적 만료일 상태를 가져와 현지 패널을 열고, 자원 제목에 pointerdown을 보낸 뒤 하루를 진행했다. bounds로 300 → -2,150.9px(차이 -2,450.9px)을 흉내 내면 scrollBy가 없어 보정되지 않았다. 시험 틀은 CSS 레이아웃을 계산하지 않아 실제 이동 크기·견적 소멸에 따른 원인을 재현할 수는 없다. 이 값은 지시서의 Claude 실측이며, 흉내 시험은 한 열에서 오른쪽 보정을 하지 않는 사실만 확인한다. 임시 시험은 제거했다.
- 세로 태블릿 768~840px의 statusbar 줄바꿈은 flex-wrap 및 새 단추 폭 때문에 남는다. 지시서의 사전 실측은 경계가 715px 미만 → 842px 미만, 768×1024 높이가 79 → 135.1px, 700px 이하가 102.7 → 148.3px다. 이번 작업에서는 브라우저로 재지 않았으며 가로 일곱 프로필 높이도 Claude 확인이 남는다.
- map-integration.test.ts의 pixel 모듈은 vi.mock으로 대체되어 실제 applyPixelScale은 호출되지 않는다. matchMedia 추가로 새로 실행되는 것은 main.ts의 한 열 판정·change 등록이다. pixel.ts 82행 이후 감시자 연결·해상도 감시가 새로 실행된다는 지시서 설명과 다르다. 지도 연결 시험은 흉내 추가 한 줄 외에 바꾸지 않았으며 자동 검사에서 통과했다.

## 질문

기본값을 바꿀 필수 질문은 없다. 후속 검수 의견은 두 가지다.

- Esc 대상을 일정 펼침·details로 넓히는 것은 닫힘 상태와 초점 복귀 규칙을 별도 설계할 때 다루는 편이 좋다. 이번에는 지정된 네 칸만 닫는다.
- 세로 태블릿 막대를 줄여야 한다면 건수 단추의 세로 화면 표현과 금액 칸 배치를 함께 검토할 수 있다. 이번 가로 기기 범위에서는 받아들인 대가를 유지했다.

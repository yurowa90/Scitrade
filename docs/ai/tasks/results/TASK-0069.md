## 설계 판단 (지시서에 없던 결정과 이유)

- 원화 변환은 기존 `withRiskLevel`에 맡기고, SELL 가산에 사용할 BUY는 변환 전 입력 `config.operations.market.rows`에서 읽는다. 같은 품목의 BUY 개수를 검사하므로 누락·중복을 조용히 덮지 않는다.
- 기존 `divHalfAway(SELL₀ × 100 + BUY × 5k, 100)`로 합계를 한 번 반올림한다. 음수 k에서도 가산분을 먼저 반올림하지 않는다. 손 고정물의 `100 − 0.5 = 99.5 → 100`이 이 차이를 검사한다.
- `structuredClone(credit)` 뒤 사본의 `saleMarginK`만 삭제한다. 입력 설정과 입력 외상 프로필을 바꾸지 않는다. k=0뿐 아니라 ±k에서도 SELL만 되돌린 전체 설정이 손 계산 k=0 설정과 엄격히 같다.
- BUY 누락·중복은 k=0에서도 거절한다. 잘못된 짝을 k=0일 때만 통과시키지 않으며, 현재 자료의 항등에는 영향이 없다.
- 지시서의 `run.mjs run`은 `SIM_SEEDS` 1001~1020 고정이며 `--seed-base`를 받지 않는다. ‘시험 시드 2001 이상’을 우선하여 실행기 파일을 수정하지 않고, Vite `runnerImport`로 기존 `runSuite({ seeds: [2001, …, 2020] })`와 `serializeSimOutput`을 직접 호출했다. 기본 시나리오·정책 묶음은 그대로 400회이며, 위험 메타도 없다. 대체 방법을 질문한 뒤 독립 검증을 진행했으며 응답이 없어 이 가정으로 실행했다. **지정 CLI 문자열 자체를 실행했다고 주장하지 않는다.** 기존 골든·기존 시험의 고정 시드는 수정하지 않았다.

## 범위 밖 발견

- `run.mjs run`의 시드 옵션 충돌은 위 설계 판단에 기록했다. 실행기에는 손대지 않았다.
- 지시서대로 `check_profile_v2.py` 기대 V2와 판정표 고정 sha 정오는 허브의 병합 후 작업으로 남겼다. 이번 작업에서 해당 파일을 수정하거나 측정 시드로 실행하지 않았다.
- 현재 자료 BUY는 모두 20센트의 배수다. 비배수 BUY가 나중에 자료에 들어올 때 한도 검증기와 엔진의 반올림 단계가 달라질 수 있다는 H31-4의 한계는 그대로다. 나머지 고정물은 엔진 반올림 시험에만 썼다.
- 그 밖에 중단이 필요한 생산 코드·자료 결함은 발견하지 않았다.

## 질문

비위험 400회 명령 대체는 검수에서 확인할 사항이다. 새 기능 구현에 필요한 미확정 사항은 없다.

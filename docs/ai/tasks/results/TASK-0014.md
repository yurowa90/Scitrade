## 설계 판단 (지시서에 없던 결정과 이유)

- `.topbar`는 `display: contents`인 의미적 header로 남기고, `.masthead`와 `.statusbar`만 상자를 갖게 했다. 상태 막대의 sticky 범위가 짧은 header 상자에 제한되지 않으며 기존 화면 시험의 header 조회도 유지된다.
- 확인 문구는 아래쪽 고정 `role="status"` 알림으로 표시한다. 오늘 할 일의 동일 문장은 유지하고 그 문장의 상태 역할은 고정 알림으로 옮겨 중복 안내를 피했다. 알림은 포인터 이벤트를 가로채지 않는다.
- 클릭 출처는 `try/finally` 안에서만 기억한다. Safari처럼 버튼이 activeElement가 되지 않는 경우도 클릭한 대상을 기준으로 처리한다. 수락 시 중간 초점 복원을 생략하고 새 계약 제목으로 한 번만 이동한다.
- 배정·예약·영입의 이전 조작 칸 크기를 측정해 예정 표시 칸에 유지한다. `overflow-anchor: none`도 적용해 전체 재그리기의 자동 앵커 이동을 막는다. 이 크기는 UI 표시용이며 경제 상태·저장에는 들어가지 않는다.
- 코드와 지시서 설명의 차이: 대기 명령을 반영한 `view`에서는 배정된 업무가 더 이상 QUEUED가 아니고 예약된 계약에는 booking이 이미 생긴다. 기존 내부의 ‘배정 예정’·‘예약 예정’ 분기는 이 때문에 도달하지 않았다. 대기 명령 여부로도 표시 분기에 진입하도록 고쳤다.
- 키보드 대안은 해당 조작의 상태 표시, 대상 카드 제목 순으로 찾는다. 가운데가 고정 막대에 가려지거나 화면 밖이면 보이는 하루 진행으로 옮긴다. 캠페인 종료로 그 버튼이 비활성이면 상태 막대 자체로 옮긴다. 모두 `preventScroll`을 쓴다.
- 카드·운영표 선택 후 기존 성장 상세 버튼을 화면 안으로 가져오고 그 버튼에 초점을 둔다. 상세 배치는 유지하며 같은 동료를 다시 골라도 선택을 풀지 않는다.
- 불러오기뿐 아니라 파일 가져오기에도 같은 진행 보호 확인을 적용했다. 시나리오 확인을 거절하면 select 값도 현재 시나리오로 되돌린다.
- 기존 흐름 시험은 `click()`에서 가짜 시간을 501ms 진행한 뒤 다음 조작을 한다. 연속 클릭 시험은 시간을 진행하지 않는 `clickNow()`와 499ms·1ms 경계를 직접 검사한다.
- 기존 훈련 비활성 클릭 시험은 3일 훈련을 하루 진행해 실제 진행 중인 비활성 버튼을 검사하도록 바꿨다. 대기 중 버튼은 예정 표시로 대체됐기 때문이다. 훈련 비용·기간·처리량·원화 지급 가능일·거절 이유 단언은 유지했다.

### 브라우저 측정

**미실행.** 디스크 공간을 확인하고 기존 Playwright·Chromium으로 실행을 시도했으나 샌드박스에서 다음 오류가 났다. 패키지를 설치하거나 권한을 변경하지 않았다.

- 개발 서버: `listen EPERM: operation not permitted 127.0.0.1:5173`.
- Playwright Chromium: `browserType.launch: Target page, context or browser has been closed`, Chromium 로그 `setsockopt: Operation not permitted (1)`.

따라서 iPhone 13·Galaxy S24·Pixel 7, iPad Mini·gen 7 세로/가로, Galaxy Tab S9, 노트북 1280×800·1366×657의 실제 고정 높이, 최초 견적 위치, 수락 후 0~60px 간격, 배정·예약 후 40px 이하 변화, 2일 편 전체 노출, 320~1440px 가로 넘침은 **통과로 판정하지 않았다**. Claude의 Chromium 재측정·최종 실제 배율 확인이 필요하다. DOM 시험의 스크롤 요청 없음과 픽셀 단위의 실제 스크롤 변화는 구분한다.

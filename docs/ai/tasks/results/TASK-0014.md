## 설계 판단 (지시서에 없던 결정과 이유)

- `.topbar`는 `display: contents`인 의미적 header로 남기고, `.masthead`와 `.statusbar`만 상자를 갖게 했다. 상태 막대의 sticky 범위가 짧은 header 상자에 제한되지 않으며 기존 화면 시험의 header 조회도 유지된다.
- 확인 문구는 아래쪽 고정 `role="status"` 알림으로 표시한다. 오늘 할 일의 동일 문장은 유지하고 그 문장의 상태 역할은 고정 알림으로 옮겨 중복 안내를 피했다. 알림은 포인터 이벤트를 가로채지 않는다.
- 클릭 출처는 `try/finally` 안에서만 기억한다. Safari처럼 버튼이 activeElement가 되지 않는 경우도 클릭한 대상을 기준으로 처리한다. 수락 시 중간 초점 복원을 생략하고 새 계약 제목으로 한 번만 이동한다.
- 배정·예약·영입의 이전 조작 칸 크기를 측정해 예정 표시 칸에 유지한다. `overflow-anchor: none`도 적용해 전체 재그리기의 자동 앵커 이동을 막는다. 이 크기는 UI 표시용이며 경제 상태·저장에는 들어가지 않는다.
- 코드와 지시서 설명의 차이: 대기 명령을 반영한 `view`에서는 배정된 업무가 더 이상 QUEUED가 아니고 예약된 계약에는 booking이 이미 생긴다. 기존 내부의 ‘배정 예정’·‘예약 예정’ 분기는 이 때문에 도달하지 않았다. 대기 명령 여부로도 표시 분기에 진입하도록 고쳤다.
- 키보드 대안은 해당 조작의 상태 표시, 대상 카드 제목 순으로 찾는다. 가운데가 고정 막대에 가려지거나 화면 밖이면 보이는 하루 진행으로 옮긴다. 캠페인 종료로 그 버튼이 비활성이면 상태 막대 자체로 옮긴다. 모두 `preventScroll`을 쓴다.
- 카드·운영표 선택 후 기존 성장 상세 버튼을 화면 안으로 가져오고 그 버튼에 초점을 둔다. 상세 배치는 유지하며 같은 동료를 다시 골라도 선택을 풀지 않는다.
- 불러오기뿐 아니라 파일 가져오기에도 같은 진행 보호 확인을 적용했다. 시나리오 확인을 거절하면 select 값도 현재 시나리오로 되돌린다.
- 기존 흐름 시험은 `click()`에서 가짜 시간을 501ms 진행한 뒤 다음 조작을 한다. 연속 클릭 시험은 시간을 진행하지 않는 `clickNow()`와 499ms·1ms 경계를 직접 검사한다.
- 기존 훈련 비활성 클릭 시험은 3일 훈련을 하루 진행해 실제 진행 중인 비활성 버튼을 검사하도록 바꿨다. 대기 중 버튼은 예정 표시로 대체됐기 때문이다. 훈련 비용·기간·처리량·원화 지급 가능일·거절 이유 단언은 유지했다.

- **Claude 수정 1~3 (비판자 시제품 F1~F3, `src/ui/main.ts`·`style.css`):**
  - **F1 누른 자리 유지:** 배정·예약 버튼이 칸 안에서 있던 높이를 기억해 예정 표시를 그 높이에 둔다. 다시 그린 뒤 그 칸이 아래로 밀렸으면(위쪽 내용이 늘었으면) 그만큼 스크롤한다. 위쪽 내용이 줄면 스크롤하지 않는다.
  - **F2 알림을 보이는 영역의 끝으로:** 알림 높이를 `--toast-h`로 알려 `scroll-padding-bottom`에 쓴다. 초점 대안을 고를 때도 알림 위까지만 보이는 영역으로 본다. 본문 아래 여백을 늘려 마지막 내용이 알림 밑에 갇히지 않게 했다.
  - **F3 하루 진행 뒤 읽던 자리 유지:** 화면에 보이던 첫 계약 카드의 제목 높이를 기억했다가, 다시 그린 뒤 같은 높이로 맞춘다.
  - 비판자 시제품의 마지막 CSS 한 줄(`scroll-margin`)은 넣지 않았다. 실패한 Shift+Tab 시도(P14-03)의 흔적이다. 도달할 수 없는 분기 하나도 지웠다.
- **Claude 수정 4 — 휴대폰의 ‘금액은 확정 기준’ (Claude 지시서에서 생긴 문제):**
  - 지시서 MF-2는 ‘보이는 글자로 남기되 줄을 늘리지 않게’라고 했다. Sol은 이 표시를 ‘하루 진행 ▶’ 버튼 안 위쪽에 흰 글자로 넣었다. 그래서 버튼 이름이 ‘금액은 확정 기준 / 하루 진행 ▶’처럼 읽혔다. 같은 상자 안의 글자는 한 묶음으로 보이기 때문이다(공통 영역 원리, Palmer 1992).
  - 버튼 밖, 같은 칸 왼쪽에 두 줄로 옮겼다. 위 칸의 ‘거래 현금 (USD)’·‘운영 현금 (KRW)’ 이름표와 같은 열·같은 글자 크기다.
  - 결과(Chromium): 막대 높이 그대로(320px 138, 360px 135, 390·412px 120). 표시와 버튼의 겹침 0. 가로 넘침 0. 태블릿·노트북 배치는 바뀌지 않는다(700px 이하에만 적용).
- **시험:** `main-testkit`에 `window.scrollBy`, 배정·예약 칸의 위치, 아래쪽 알림, 계약 카드, ‘다시 그린 직후’ 갈고리를 더했다. 시험 7개를 더했다.
  - 예정 표시가 누른 높이에 남고, 위쪽이 늘면 늘어난 만큼만 스크롤한다.
  - 위쪽이 줄면 스크롤하지 않는다.
  - 하루 진행 뒤 계약 제목이 아래(+40)·위(−25)로 가면 그만큼 되돌린다. 그대로면 스크롤하지 않는다.
  - 알림이 있으면 `--toast-h`가 그 높이, 없어지면 `0px`이다.
  - 대안 초점의 가운데가 알림에 가려지면 하루 진행으로 옮긴다.
  - 변형 8종(알림 경계 제거, 늘 때 스크롤 제거, 줄 때도 스크롤, 하루 진행 보정 제거, 아래로만 보정, `--toast-h` 고정, 높이 기억 제거, 보이는 카드 판정 제거)을 하나씩 넣어 모두 실패로 검출했다.
  - 비판자 시제품은 `closest?.`·`scrollBy?.` 같은 선택 호출로 시험 환경을 피했다. 시험 도구를 넓혔으므로 이 선택 호출을 지웠다.

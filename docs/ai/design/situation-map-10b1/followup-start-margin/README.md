# 상황실 자유 탐색 시작 영역 여백 시제품 (세션 B, 2026-10-16)

TASK-0061-R3 실측의 참고 1번(1024 자유 탐색에서 하이퐁·부산 이름표가 가장자리에 걸림)을 다음 Sol 지시서에 넣기 전에 쟀다. 개발 브랜치 `ef7374f`를 빌드(빌드 표시 `dev`)했다. 상태는 R1~R3과 같다(‘M1 항만 지연 사례’ 8일, 자유 탐색). 바꾼 것은 쪽에서 SVG `viewBox`뿐이다. 코드는 바꾸지 않았다.

## 결과(이름표가 지도 칸 `.situation-stage` 밖으로 나간 양, CSS px)

| 시작 영역 여백(`explorationBox`) | 1024 터치 | 1180 터치 | 1366 마우스 | 지도 글자 상자 높이(중앙값) |
|---|---|---|---|---|
| 15%(지금) | **하이퐁 17**, 부산 48 | 부산 23 | 0 | 30px |
| 20% | 부산 18 | 0 | 0 | 27px |
| **25%** | **0** | **0** | **0** | 26px |
| 항로 거점 이름표까지 담기 | 부산 121 | 부산 127 | 0 | 31~35px |

- 표는 이번 시나리오와 1장 예정 거점(평택·하이퐁·부산)만 셌다. 그보다 먼 예정 거점(요코하마·싱가포르·자카르타)은 어느 여백에서도 칸 밖이다. 자유 탐색은 이번 항로를 먼저 보이는 화면이니 그것이 맞다.
- ‘하이퐁’은 이번 항로의 도착 거점이고, 15%에서만 잘린다.
- **고칠 점(세션 B 정정):** R3 보고에서 권한 ‘20%’는 하이퐁만 풀고 1024의 부산은 18px 남긴다.

## 권고

- `explorationBox`의 여백을 15% → **25%**로 바꾼다. 코드 한 곳의 `1.3`을 `1.5`로 바꾸면 된다.
- 지도 글자는 30 → 26px(상자 높이)로 줄지만, 경로 지도 하한 11px보다 충분히 크다.
- 브리핑 상자(`briefingBox`, 15%)는 바꾸지 않는다. 최소 560×400 지도 단위라 이름표가 이미 들어간다.
- 시험: 기존 `explorationBox` 시험의 기대값 계산만 바뀐다. 다른 크기·결정성 영향은 없다.

## 재현

`mpad.js`는 저장소 밖 `kb/blib.js`를 쓴다. 각 여백에서 `viewBox`를 다시 쓰고, 거점 이름표 `<g class="port">`의 사각형을 지도 칸 사각형과 비교한다. 원자료는 `margin.jsonl`이다.

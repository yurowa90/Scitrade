## 3. 결함

### 결함 1(확정): 지도를 누르면 초점이 대화상자 밖으로 빠져 Escape가 듣지 않는다

- **재현** (`raw/escape.jsonl`)
  1. 1024 터치에서 상황실을 연다.
  2. ‘자유 탐색’을 고른다.
  3. 또렷한 항만 점이나 거점을 누른다.
  4. 선택 칸은 바뀌지만 `document.activeElement`가 `BODY`다.
  5. 이 상태에서 Escape를 누르면 대화상자가 닫히지 않는다.
  6. Tab을 누르면 첫 단추가 아니라 ‘내 화물·선박’ 토글로 간다.
- **원인**
  - `openSituation`의 클릭 처리는 항만·표시를 고르면 `redraw(undefined)`로 다시 그린다. 그래서 초점을 받은 요소가 사라진다.
  - Escape·Tab 처리는 `root`의 `keydown`에만 걸려 있다. 초점이 `body`에 있으면 처리가 불리지 않는다.
- **고칠 방향(택1)**
  - 고른 뒤 초점을 선택 칸 제목(`tabindex="-1"`)으로 옮긴다.
  - 또는 `root`에 `tabindex="-1"`을 주고 다시 그린 뒤 `root`에 초점을 둔다. `keydown`을 열려 있는 동안 `document`에 거는 방식도 된다.
- **시험:** jsdom 시험으로 잡을 수 있다(항만 클릭 → `activeElement`가 대화상자 안인지, Escape로 닫히는지).

### 결함 2(코드·명세 근거): 낭독 영역을 다시 그릴 때마다 새로 만들어 알림이 들리지 않을 수 있다

- **관찰**
  - 토글을 바꿀 때마다 `#situation-live`가 새 노드다(`sameNode:false`, 이전 노드 `isConnected:false`). 새 노드가 붙은 직후 글이 들어간다.
  - 브리핑 `role="status"` 카드도 ‘다음 사건’마다 새 노드다.
  - 모든 갱신이 `root.innerHTML = …`이기 때문이다.
- **근거**
  - 낭독 영역은 내용이 바뀌기 전에 이미 문서에 있어야 보조기기가 변화를 알아챈다.
  - 막 삽입된 낭독 영역의 처음 내용은 알리지 않는 화면 낭독기가 많다(MDN ‘ARIA live regions’). 특히 iOS VoiceOver에서 놓치기 쉽다.
  - Chromium만 있는 이 환경에서는 실제 낭독 여부를 재지 못했다.
- **고칠 방향**
  - `#situation-live`를 다시 그리는 범위 밖(대화상자 루트의 고정 자식)에 두고 글만 바꾼다.
  - 또는 배경 앱의 `#live-status`를 쓴다. 이것은 `#app` 밖 `body` 직속이라 `inert`가 아니다.
  - 브리핑 카드는 `role="status"`를 빼고, 사건 문장을 같은 고정 낭독 영역으로 보낸다. 사건 제목으로 초점이 이미 가므로 중복이기도 하다.
- **시험:** 노드 동일성은 jsdom으로 잡을 수 있다(토글 전후 `#situation-live`가 같은 노드).

## 4. 판단거리(결함 아님)

1. **항만 점이 4.8 CSS px다.**
   - 손가락으로 정확히 누르기 어렵다. 홍콩처럼 게임 거점과 겹치는 곳에서는 점 중심을 눌러도, 6px 비켜 눌러도 거점 표시가 잡혔다(`raw/escape.jsonl`).
   - 같은 정보가 ‘표로 보기’ 항만 표에 있으므로 WCAG 2.5.8(최소 대상 크기 24px)의 ‘같은 기능의 대안’ 예외에 든다.
   - 다만 iPad 사용성에서는 누르는 판정 반지름을 키우는 것을 권한다. 예: 투명 원 r=12 지도 단위, 겹치면 가장 가까운 것.
2. **자유 탐색의 지도 배율이 작다.**
   - 지도 전체(1092×1230 단위)를 칸에 맞춰 배율 0.54다. 1366에서 지도가 칸 폭 1,056px 중 588px만 쓴다. 지도 글자(거점 이름·경위도)는 상자 높이 11~14px다.
   - 반대로 브리핑은 배율 1.34(1024)·1.66(1366)이라 이름표가 크다.
   - 권고: 자유 탐색의 시작 영역을 항로 범위(모형의 760×640 단위 정도)로 둔다. 전체 보기는 단추나 확대·축소로 준다.
3. **브리핑 카드 문단이 잘린다.** 공지 본문이 길면 카드 안 문단만 따로 스크롤된다. 첫 줄 몇 줄만 보이고 ‘시나리오에 고정된…’에서 끊긴다. 카드 높이 상한을 조금 올리거나, 본문 아래에 ‘전문 보기’를 두는 쪽을 권한다.
4. **400%에서 머리 줄이 화면 대부분(161/192px, 256폭에서 243/192px)을 차지한다.** 내용에는 닿으므로 결함은 아니다. 좁은 높이(`max-height:550px`)에서 머리 줄 단추를 두 줄 묶음 대신 줄이는 방법을 다음 판에서 고려한다.

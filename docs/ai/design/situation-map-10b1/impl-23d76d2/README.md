## 2. 결함 1·2 다시 보기

### 결함 1: 지도를 누른 뒤 초점 — **일부 남음**

| 경우 | 누른 뒤 초점 | Escape | 원자료 |
|---|---|---|---|
| 점 하나를 누름(옅은 점에서 15px 비켜 누름) | 선택 정보 제목 `#situation-selection-h` | 닫히고 ‘상황실’ 단추로 돌아옴 | `raw/m61r2x_js.jsonl` defect1 |
| 점이 여럿인 곳을 누름 → 목록(44px 단추 6개) → 하나 고름 | 선택 정보 제목 | — | 같은 파일 nearby |
| **점·표시가 22px 안에 없는 곳(바다·빈 땅)을 누름** | **`BODY`** | **닫히지 않음** | `raw/sea-tap.jsonl`(1024 터치·1366 마우스 모두) |
| R1 재현 절차 그대로(같은 곳을 두 번 누름) | 첫 번째는 선택 정보 제목, 두 번째는 **`BODY`** | **닫히지 않음** | `raw/m61er2_js.jsonl`, `raw/retap.jsonl` |

- **원인**
  - 지도(SVG·그림)는 초점을 받지 않는다. 그래서 누르는 순간 브라우저가 초점을 `body`로 옮긴다.
  - 클릭 처리는 22px 안에 점이 없으면 `if (!near.length) return;`로 끝난다. 다시 그리지도 않고 초점을 되돌리지도 않는다.
  - 같은 곳을 두 번 누르는 경우도 같은 원인이다. 첫 번째 누름으로 선택 칸이 나타나 지도 칸 높이가 줄고, 점 위치가 바뀌어 두 번째 누름이 빈 곳이 된다.
  - Escape·Tab 수신기는 고정 루트에 있지만, 초점이 `body`면 루트의 `keydown`이 불리지 않는다.
- **고칠 방향**
  - 가장 작은 수정은 대화상자 루트에 `tabindex="-1"`(테두리 없음)을 주는 것이다. 초점을 받지 않는 자식을 누르면 브라우저가 가장 가까운 초점 가능한 조상, 곧 루트에 초점을 준다.
  - 또는 빈 곳 클릭에서도 이전 초점을 되돌린다.
  - 또는 열려 있는 동안 `keydown`을 `document`에서 받는다.
- **시험:** jsdom에서 지도 빈 곳 클릭 → `activeElement`가 루트 안인지, Escape로 닫히는지로 잡을 수 있다.

## 4. 작은 결함 1건(초점 순서)

- **증상**
  - 선택 정보 제목에 초점이 있을 때 Shift+Tab을 누르면 바로 앞 조작이 아니라 마지막 토글(‘국가 지표’)로 간다(`raw/m61r2x_js.jsonl` nearby, `shiftTabFromSelection`).
  - 앞으로 가는 Tab은 목록 첫 단추로 간다.
- **원인:** Tab 수신기가 ‘초점이 단추·입력·summary 목록 밖에 있으면 Shift+Tab을 마지막으로 보낸다’로 되어 있다. 대화상자 제목에는 맞지만, 중간에 있는 선택 정보 제목(`tabindex="-1"`)에도 걸린다.
- **고칠 방향:** 이 조건을 대화상자 제목에만 적용한다.
- **영향:** WCAG 2.4.3(초점 순서)에 가깝다. 다만 키보드로 지도를 고른 뒤 뒤로 가는 경우에만 생긴다.

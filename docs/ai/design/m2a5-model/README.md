## 1. 결론

1. **결정 묶음 문구 그대로(주선 F1~F6만, 묶음당 5건, 6 m³당 1pt, 최소 2pt)로는 D03 나의 목표를 이룰 수 없다.** 탐색한 F만 24묶음 모두에서 고용이 늘 손해다(가장 좋은 고용 변형도 분석값 중앙 −3,811 USD, 이득 시드 0/20). 기준 직원 유휴가 75~83%다. 임금 0원 직원을 더해도 분석값이 +300(14/20)만 는다. 병목이 직원이 아니다.
2. **명세 기본값(SPEC_P: F+H 12틀 한 풀에서 6건)도 ‘뚜렷한 이득’ 상황이 없다.** 고용 변형이 −83 ~ −1,904 USD이고 이득 시드가 1~10/20이다. 한 풀에서 뽑는 72묶음 모두 판정 2를 못 넘었다. 묶음마다 H 수가 0~6건으로 흔들려 직원 수요가 꾸준하지 않기 때문이다.
3. **작업 포함 주선(H)을 묶음마다 정해진 수만큼 내면(나눠 뽑기) 네 판정을 모두 넘는다.** 1단계 72묶음 중 38개, 2단계 144묶음 중 127개가 통과했다. 성격이 다른 후보 3개를 낸다(8절).
   - **후보 A**(벗어남 최소): 일반 3 + H 3, H는 명세 그대로(3 m³·12pt). 2pt 직원 고용은 거의 늘 이득, 3pt 직원은 창고 확장 없이는 손해(처리 한도 6pt).
   - **후보 B**(사용자 예시에 가장 가까움): 일반 2 + H 4, H 9 m³·12pt. 용량(보관·선복)을 늘린 뒤에만 고용이 이득. 고용만 하면 크게 손해, 투자만 해도 손해.
   - **후보 C**(중간): 일반 3 + H 3, H 6 m³·12pt. 2pt 직원은 대체로 이득, 3pt 직원은 SE와 함께일 때만 이득. 고용 판단이 가장 갈린다(시드별 1위 정책 중 고용 10·비고용 10). 다만 판정 3의 여유는 가장 작다.
4. **세 후보 모두 H의 pt당 기여이익이 좁은 띠 안에서만 성립한다.** A는 62~70 USD, C는 66~70 USD, B는 70 USD(명세 값)에서만 넘는다. 서비스 대금 −200 USD면 셋 다 고용이 늘 손해가 된다. 엔진 재측정 때 가장 먼저 다시 맞출 손잡이다(8.5).
5. 세 후보 모두 표본 밖 시드 1021~1040에서도 네 판정을 넘었다(8.4).
6. 함께 찾은 것: 늦은 인도를 받는 ‘적극’ 정책이 ‘보통’보다 18~19/20 시드에서 낫다(정액 감액 50 USD가 작다). 선복 계약(DK-21)이 혼자 뚜렷한 이득인 묶음은 H가 크고 10pt인 일부뿐이고, 그런 묶음에서는 고용이 거의 늘 손해다. 환전 없이 하면 모든 정책이 48~71일에 실패한다. 경고 뒤에만 환전해도 실패는 없다(8.6).

### 4.3 하루 처리 (SPEC 13절)

1. 명령: 환전 → 영입 → 투자 → 놓친 편 다시 예약 → 대기 업무 배정 → 견적 수락(수락마다 배정).
2. 진행: 창고 처리 한도를 ‘예약 출항일 → 납기 → 계약 번호’ 순서로 나눈다. 진행 = min(직원, 남은 양, 창고 남은 양).
3. 출항(준비 미완료면 불참·운임 − 50 USD 환급) → 도착(관세는 규칙 2 지급) → 인도(늦으면 50 USD 감액).
4. 수금 → 밀린 지급(통화별 발생 순서, 못 갚으면 멈춤) → 임차료·선복 요금 → 급여(같은 통화 미지급이 있으면 줄을 섬).
5. D04: 가장 오래된 미지급의 나이가 14일인 날 마감에 남으면 실패, 실행 끝.
6. 만료. 견적 묶음은 시드로 미리 만들고 공개일부터 보인다. 플레이어 행동은 견적을 바꾸지 않는다.

## 5. 정책

정책 이름은 `수락|환전|고용|투자`다. 예: `N|fx7|90k@30|SE`.

| 축 | 값 | 뜻 |
|---|---|---|
| 수락 | `C` 신중 | 기본 단위만, 기여이익 100 USD 이상, 정시 편만, 앞 14일 원화 부족분만큼 USD를 남김 |
| | `N` 보통 | 가장 큰 수량부터, 기여이익 양수, 정시 편만. 기여이익 큰 순서로 탐욕 수락(비교 실행기 `MAX_CONTRIBUTION`, `src/engine/sim/policies.ts:91`) |
| | `A` 적극 | N + 늦은 편도 받음(감액 뒤 기여이익 양수) |
| 환전 | `fx7` | 앞 7일 원화 지출 + 원화 미지급 − 원화 현금을 100 USD 단위로 올려 미리 환전(SPEC 17.3) |
| | `react` | 원화 미지급(경고)이 생긴 뒤에만, 밀린 돈 + 오늘 낼 돈만큼 |
| | `none` | 환전하지 않음 |
| 고용 | `90k@d` | 바름(EMP06, 2pt, 90,000원). 물보리가 d−3일 조사(1pt), d−2~d−1일 의뢰(3pt), d일 고용(계약금 450,000원), d+1일부터 근무·급여 |
| | `110k@d` | 현돌(EMP04, 3pt, 110,000원). 계약금 550,000원 |
| | d | 8·30·50일, 또는 고용 없음(`nohire`) |
| 투자 | `S1` | 1일 두 노선 선복 계약(9일 편부터) |
| | `E7` | 7일 창고 확장(8일부터) |
| | `SE` / `SE22` | 둘 다(1·7일) / 둘 다 22일 |
| 진단 | `FREE2@8` | 임금·계약금 0원, 영입 절차 없는 2pt 직원(직원의 그림자 가치). 판정 3에서는 뺀다 |
| | `90k@22+110k@36` | 두 명 고용 |

- 수락 검사: 자금(현금 − 예약 − 미지급, `src/engine/reservations.ts:54-68`) → 보관 → 다음 3개 출항편마다 정시·선복·직원 예측. 직원 예측은 지금 업무 + 새 업무만으로 날마다 모의 진행해, 예약한 모든 업무가 출항 전에 끝나는지 본다. 실제 진행과 같은 함수를 쓴다(놓친 출항 0건).
- 수락한 업무는 그날 빈 직원이 없으면 대기하고, 직원이 비는 날 우선순위대로 배정한다(4.3).
- 전체 표의 정책 185개 = 수락 3 × 환전 2 × 투자 4 × 고용 7(168) + react 4 + 진단·늦은 투자 13. 탐색은 보통·fx7 중심 29개만 쓴다.

- 엔진 재측정에서 판정이 어긋나면 먼저 H 대금(또는 H 준비 pt)만 이 띠 안에서 옮긴다. 다른 값은 그대로 둔다.

### 8.6 함께 찾은 것

- **환전(D01·D04):** 환전 없는 84개 정책 모두 20/20 실패한다. 실패일은 고용 없음 69~71일, 8일 고용 48~52일, 30일 고용 57~60일, 50일 고용 65~67일이다. 경고 뒤에만 환전(`react`)하면 원화 미지급 17~24일이 생기지만 실패는 0이다. 14일 유예 안에 회복할 수 있다.
- **수락 규칙:** ‘적극’(늦은 편도 받음)이 ‘보통’보다 세 후보 모두 +1,648 ~ +2,338 USD, 18~19/20 시드에서 낫다. 늦은 인도 감액이 지연 일수와 무관하게 50 USD 한 번이기 때문이다(`data/scenarios.json:337-341`, `src/engine/engine.ts:1000`). 판정 3은 넘지만 ‘늦게라도 다 받는다’가 거의 늘 맞다. 재협상(M2a-6b)·거래처 관계(M3) 전에 감액 규칙을 볼지 확인이 필요하다. ‘신중’은 실패가 없는 대신 −1,528 ~ −1,932 USD다.
- **투자만:** 세 후보에서 선복 계약·창고 확장 단독은 늘 손해다(−438 ~ −1,145). ‘확장이 성공을 보장하지 않는다’(CL-06)는 남는다.
- **선복 계약 단독(SPEC Q4):** 탐색 전체에서 선복 계약만으로 뚜렷한 이득(+300 이상·15/20 이상)이 난 묶음은 H가 크고(6~9 m³) 10pt인 일부뿐이다. 예: 일반 3 + H 3, H 9 m³·10pt, 일반 3 m³/pt는 +1,040(16/20). 일반 3 + H 3, H 6 m³·10pt, 선복 편당 15 USD는 +581(15/20). 그런 묶음에서는 고용이 거의 늘 손해였다(가장 좋은 칸이 SE + 2pt 30일 +361, 15/20). 이 공간에서는 ‘선복 계약이 혼자 이득’과 ‘고용이 이득인 상황’이 서로 당긴다.
- **두 명 고용:** 세 후보 모두 −5,273 ~ −6,035 USD(0/20). ‘늘 이득은 아니다’가 남는다.

## 9. 엔진과 다른 점(단순화)

1. **정책이 엔진 비교 실행기와 다르다.** 지금 실행기는 수락 때 빈 직원이 있어야 하고(`src/engine/sim/policies.ts:102-111`, 바쁜 직원 배정은 `src/engine/engine.ts:481`에서 거절), 준비 pt를 고정값으로 본다(`policies.ts:104`). 이 모형은 수락·예약을 먼저 하고 직원은 비는 날 배정한다. 12pt 업무를 쓰려면 엔진 실행기도 이렇게 바꿔야 한다(SPEC 17.3에 더할 것).
2. **영입:** 물보리만 조사·의뢰를 맡고, 시작 3일 전부터 그 날짜를 넘기는 준비 업무를 새로 맡지 않는다. 엔진에서는 명령을 따로 넣는다. pt 값은 자료와 같다.
3. **직원 예측:** 앞으로 들어올 견적과 아직 고용하지 않은 직원은 넣지 않는다. 실제 진행과 같은 함수라 이 모형 안에서는 놓친 출항이 0건이다.
4. **빠진 것:** 현지 활동·훈련·경험치(처리량은 고정, LEGACY_FIXED), 항만 사건, 계약 취소, KRW→USD 환전, 사건(M2a-6a), 재협상·위임.
5. **장부:** 분개를 만들지 않고 통화별 현금·채권·재고·선급운임·진행원가·미지급만 센다. 손익 보고 행·불변 조건 검사는 없다. 검산(4.1·SPEC 18절)은 같은 값을 냈다.
6. **견적 검토:** 하루에 한 번, 기여이익 큰 순서로 본다. 직접 무역은 같은 묶음·같은 상품의 매입·판매 짝만 만든다.
7. **분석값:** 90일에 진행 중인 화물은 원가로 센다. 판매가로 세지 않는다.
8. **거절 이유:** 모형만의 분류다. 엔진 거절 문장과 일대일이 아니다. 여러 편이 있으면 ‘가장 늦은 정시 편’에서 막힌 이유를 쓴다.

# TASK-0012 장면 시안 비교 결과와 사용자 선택

- 작성: Claude, 2026-10-06. 기준 문서: [TASK-0012-scene-brief.md](TASK-0012-scene-brief.md) (시안보다 먼저 고정, 커밋 `d8638f5`).
- 시안 파일: [TASK-0012-mockups/](TASK-0012-mockups/) `A.html`(패널형), `B.html`(도시 장면형), `C.html`(기록장 중심형). 각 파일은 2일 상태의 가짜 게임 화면을 담은 자체 완결 HTML이다. **숫자·문구는 시안용이며 구현 기준이 아니다.** 시안 안의 엔진 흉내 코드도 옮겨 쓰지 않는다(지시서는 실제 엔진 함수를 직접 부른다).

## 1. 방법

1. 시안 3개를 각각 다른 작성자가 만들었다(같은 기준 문서, 같은 게임 토큰·L2 배치).
2. 시안마다 점검자가 1366×657·1180×820·1024×768에서 한 바퀴(부산 현지 열기 → 활동 → 직원 → 오늘 할 일에 넣기 → 하루 진행 → 결과)를 돌며 측정했다.
3. 심사자 3명이 관점 하나씩 맡아 C1~C8로 채점했다. 학습(C1~C3), 흐름·배치(C4·C6·C8), 구현(C5·C7)이다. 심사자는 점검 보고·스크린숏·시안 코드를 읽고 Chromium으로 직접 다시 쟀다.

## 2. 점수

| 시안 | 학습 C1+C2+C3 (/50) | 흐름·배치 C4+C6+C8 (/30) | 구현 C5+C7 (/20) | 합계 | 탈락(C5) |
|---|---|---|---|---|---|
| C 기록장 중심형 | 44 | 26 | 13 | **83** | 없음 |
| A 패널형 | 35 | 24 | 19 | 78 | 없음 |
| B 도시 장면형 | 41 | 22 | 12 | 75 | 없음 |

- C와 A는 5점 차이라 동점 규칙(5점 이내면 C1이 높은 쪽)을 적용했다. C1은 C 22점, A 16점이므로 순위는 같다.
- **한계:** 관점마다 심사자가 1명이라 심사자 간 일치도를 잴 수 없다. 5점 차이는 오차 범위 안으로 본다. 학생 반응이 아니라 화면 검토·측정이다. 학습 점수는 ‘학습 증거가 화면에서 읽힐 가능성’이지 학습 효과가 아니다.

## 3. 시안별 핵심 판단 (심사자 보고 요약)

**C 기록장 중심형**
- 강점(학습): 활동 전 빈 4칸 틀이 선행 조직자 역할을 한다. 칸마다 안내 질문(‘누가 무엇을 말했나 / 몇 명·어디·언제 확인했나 / 넓혀 읽으면 안 되는 것 / 다음에 확인할 것’)이 있고, 자료의 주제 제목(‘한 상인의 포장·보관 요구’)을 결과 제목으로 쓴다. 출처 줄 ‘출처 윤서(1명) · 아직 확인하지 않은 기록’과 ‘✕ 넓혀 읽지 않기’ 표시가 학습 증거 1·2를 받친다. 결과의 ‘바뀌지 않은 것’ 파란 띠가 학습 증거 4를 받친다.
- 강점(흐름): 무역 화면을 스스로 가로채지 않는다. 키보드로 ‘하루 진행 ▶’까지 Shift+Tab 8번, 화면 이동 0px.
- 약점:
  - 화면 전체를 덮는 시트가 main.ts의 전체 다시 그리기와 맞지 않는다(inert·초점 대체·전역 스크롤·Esc 처리 재작업). 대기 목록을 따로 복제하고, 부분 그리기 캐시와 2초 잉크 애니메이션을 쓴다.
  - ‘빈 쪽’·‘이 쪽을 채우려면’ 문구가 수집 욕구를 자극한다. 탈락 사유는 아니지만 C5(‘다음 후보 n개’ 계수기 금지)의 취지에 가깝게 어긋난다.
  - 500ms 두 번 누름 막기가 없다(150ms 두 번 누르면 4일로 넘어간다).
  - 닫힌 패널이 오른쪽 칸에서 동료를 101~108px, 장소 목록을 펼치면 최대 556px 민다.
  - 결과에 ‘쓴 것’이 없어 학습 증거 3이 결과 시점에 안 보인다. 미리 보기의 ‘첫 완료 경험치 +10’이 초록 보상 칩처럼 보인다.

**A 패널형**
- 강점(구현): main.ts의 전체 다시 그리기 안에 패널 함수 하나를 더하는 구조다. 기존 경로(tryCommand → 대기 → 누른 자리 예정 표시 → 알림)를 그대로 쓴다. 500ms 막기를 옮겨 왔다. 문구가 객체 하나에 모여 `src/ui/culture.ts`로 옮기기 쉽다. 엔진 함수 이름·모양을 그대로 쓴다.
- 강점(학습): 기다리는 업무 경고의 결과 문장(‘— 아직 아무에게도 배정하지 않았습니다’, 다른 사람이 없으면 ‘이 활동을 하면 오늘 이 업무를 맡을 사람이 없습니다’)과 결과의 ‘쓴 것’ 줄.
- 약점:
  - 실제 게임에 넣으면 패널이 약 2,900px 아래(1366px)에서 시작한다.
  - 직원을 누른 직후 미리 보기가 화면 밖(0% 보임)이다. 결과는 하루 진행 때 패널이 화면에 있어야만 보인다(키보드로는 약 1,250px 아래).
  - ‘범위’·‘말하지 않는 것’에 읽기 단서가 없고, 부제 ‘…부산 사람을 만나고’가 가벼운 일반화 단서다(자료 검사기는 알게 된 점에서 ‘부산 사람’을 금지한다).
  - 고정된 1001px 이상 배치를 고친다(다시 측정 필요).

**B 도시 장면형**
- 강점: 직원을 누르면 미리 보기가 바로 드러난다. 머리 문장 ‘날짜는 위쪽 ‘하루 진행 ▶’으로만 넘어갑니다’. 학습 증거 3이 결과에 잘 보인다.
- 약점:
  - 말풍선이 ‘알게 된 점’만 가장 눈에 띄는 곳에 한 번 더 보여, 훑어 읽는 학생은 범위 없이 주장만 읽는다.
  - 하루 진행 뒤 시트가 저절로 열리고 초점을 옮겨 T2의 반복 ‘하루 진행’을 끊는다.
  - 엔진에 없는 ‘기록장에 넣기’ 단계, 벡터 장면·인물 그림(픽셀아트는 M5 결정과 어긋남), 스크롤 잠금이 필요하다.

## 4. 사용자 선택 (2026-10-06)

1. **C+A 혼합안** (Claude 권장안): C의 학습 장치를 A의 구조에 담는다.
   - C에서: 4칸 기록 틀과 안내 질문, 주제 제목, 출처 줄, 움직이지 않는 ‘넓혀 읽지 않기’ 표시, ‘바뀌지 않은 것’ 띠.
   - A에서: 칸 안에 그리는 패널 구조(덮는 시트 없음), 500ms 두 번 누름 막기, 기다리는 업무 경고의 결과 문장, 결과의 ‘쓴 것’ 줄, 한 객체에 모은 문구.
   - B에서: 직원을 고르는 순간 미리 보기가 화면에 드러남, 머리 문장.
   - 고칠 것: ‘빈 쪽’·‘채우려면’ 같은 수집 유도 문구와 애니메이션 제거, 경험치 +10을 보상 배지가 아닌 다른 기록 항목과 같은 모양으로, ‘바뀌지 않는 것’을 경험치보다 눈에 띄게, 미리 보기 첫 줄 ‘이 쪽에 드는 것: 직원 1명의 하루 업무 · 20,000원 · 1일’ 형식, ‘부산 사람’ 같은 집단 표현의 부제 쓰지 않기.
2. **하루 진행 뒤 결과 표시: 읽던 자리 유지 + 알림** (Claude 권장안).
   - TASK-0014의 ‘하루 진행 뒤 읽던 자리 유지’ 규칙을 그대로 둔다. 초점은 ‘하루 진행 ▶’에 남는다.
   - 알림에 ‘결과 보기’를 두어 한 번 누르면 결과 카드로 이동한다.
   - 다음에 ‘부산 현지’를 열 때 새 기록을 맨 위에 둔다.
   - 학습 심사자는 결과를 저절로 펼쳐 학습 증거 1·2를 건너뛸 수 없게 하자고 권했다. 사용자는 무역 흐름(T2)을 지키는 쪽을 골랐다. 대신 결과를 건너뛰는 학생이 얼마나 되는지를 사용성 시험·2차 확인의 관찰 항목으로 둔다.

## 5. 혼합안의 지위

- 혼합안은 직접 잰 시안이 아니다. 두 시안의 장점이 그대로 더해진다는 보장은 없다.
- 그래서 TASK-0012 지시서는 C1~C8을 완료 조건으로 다시 쓰고, 1024·1180·1366px 배치 측정을 포함한다. 검수 때 같은 기준으로 다시 채점한다.
- 배치 자리는 지시서를 쓰기 전에 실제 3판 배치에서 측정해 정한다(시안 A의 ‘2,900px 아래’ 문제).

# 영역 repo: Scitrade 저장소 현재 상태와 비전 격차

## 요약

대상은 작업 트리 ccr-21863e28-zmusty(로컬 HEAD cf034bb)이며 읽기만 했다. 과제 문구의 ${WT} 변수가 풀리지 않아 같은 브랜치의 스크래치패드 워크트리(wtccr)로 해석했다.

[현재 상태] 결정적 하루 처리 엔진이 있다(openDay/commitDay, Math.random·현재 시각 미사용, 저장 형식 판본 6, 규칙 판본 3종). 구현된 범위는 M1, M2a 일부(복수 계약·운송 주선·예약·영입·성장·문화), M2a-5 엔진(반복 견적·시세표·창고·고정비·환전·지급 불이행)이다. 문서 기록상 시험은 45개 파일·1,257개, 검사기 회귀 시험은 97개다. M2b·M3·M4·M5는 미착수이고 그림도 미제작이다. 허브는 1장 진행률을 20~30%로 추정한다. 상용 척도 평가는 2.3점(목표 8점)이다.

[품목 사용 실태] 설계서와 goods.json은 8품목을 둔다. 하지만 시나리오 로더는 시나리오가 참조한 품목만 적재한다.
- 회사가 직접 사고파는 품목: 의류·화장품 2종뿐이다(시세 지수·시세표 6행·직접 무역).
- 운송 주선 화물(고객 소유): 가구·자동차 부품·전자제품이 더해진다.
- 아무 시나리오도 쓰지 않는 품목: 커피·냉동 수산물·태양광 모듈 3종. 태양광은 평택 전환 때 '한국→베트남 근거가 약해' 자동차 부품으로 바뀌었다.
- 사사로운 의미에서 이미 좁혀진 셈이다. 다만 사건 EV03(커피)·EV04(냉동)과 교과 연결 SOC07의 'P0: 커피 공급 차질'은 쓰이지 않는 품목에 묶여 있다. 그래서 설계와 구현 사이에 충돌이 있다.

[좁힐 때 바뀌는 것]
- 시장 난수 소비가 바뀐다. 묶음마다 22회이고 품목 수와 시세표 행 수에 비례한다. 그러면 인수 명세 P0-M2A5-01·02 등의 고정값과 시장 견적 ID 69곳을 다시 써야 한다.
- 검사기 하드코딩(goods 8, 시세표 6행)을 고쳐야 한다.
- 비교 실행기 J1~J7(특히 J7 직접 무역 비중 25% 하한, J4 여유 1~2%)을 다시 재야 한다.
- 데이터 판본이 바뀌어 기존 저장은 거절된다(데이터 판본은 정확히 같아야 하고, 규칙 판본 사이 자동 이관은 없다).
- 동료(60종) 자료에는 품목 결합이 없어 영향이 없다.

[재사용 가치] 결정성, 검사기, 비교 실행기 20시드, 출처·DESIGN 표시 체계 덕분에 품목 축소안을 정량 비교할 수 있다.

[주의] '보통 회사들도 많이 넣지 않는다'는 사용자 전제는 저장소 자료로 확인할 수 없다. 외부 근거가 필요하다.

그러면 기존 골든 값·인수 명세가 깨지지 않는다. 축소안 효과는 같은 시드에서 나란히 잴 수 있다. [370][372][377] 겹침: 기존 관찰과 겹치지 않는다(엔진 공학 관점).
- RP-N04 사건·교과 연결의 고아화: 자료에서 확인한 것:

어느 쪽이든 curriculum_links의 P0 표시를 함께 고친다. [357][366][367] 판본: 교과 연결은 2022-33 고시 기준이며 후속 개정 대조는 일부만 되어 있다. 겹침: DK4-O04(도시 상태가 가격 원인)와 일부 겹친다. 교과 연결 대조(W2-0b)를 다시 해야 한다.

- 품목별 수요 계절(근거가 있는 경우만)

그러면 '같은 품목을 깊게 아는 것'이 실제 이득과 위험이 된다. Victoria 3식 시장 깊이는 회사 밖 환경으로만 둔다. [356][360][377] 판본: Victoria 3 시장 규칙은 이번 조사에서 확인하지 않았다(저장소 한정). 겹침: DK4-O06(계절성은 근거가 있을 때만), DK4-O04와 겹친다.

냉동을 택하면 storage_class를 엔진에 올려야 한다. [361][365][374] 겹침: G3-03(HS/보관 조건 표시), DK4-O10(냉장 슬롯 검사)과 겹친다.

0.5.x 저장에는 '취급 품목 개편 전 저장' 거절 문구를 둔다. 학생 저장을 이관하려 하지 말고 '같은 시드로 다시 시작'을 안내한다. [373][374] 겹침: 기존 관찰과 겹치지 않는다. 부산→평택 전환(TASK-0015)의 절차를 재사용한다.

PARTY_KO 하드코딩은 market_rules.counterparties로 일원화한다. 검사기 회귀 시험(97개)에 '쓰이지 않는 품목 경고'를 더한다. [376][379][381][382] 겹침: 기존 관찰과 겹치지 않는다.

동료 이야기에서 품목(예: 의류 검수)을 경험한 활동으로 언급하는 정도는 허용한다. [359][368][369] 겹침: DK4-O09(직원 성장 이력), DK-14(정보는 잠그지 않음)와 겹친다.

효과는 정해진 규칙표와 지연으로 정의하고, 원작 공식을 현실 법칙처럼 쓰지 않는다. [357][360] 판본: Democracy 4 정책 그물의 실제 구조는 이번 조사 범위 밖이라 확인하지 않았다. 겹침: DK4-O12, G3-07, G3-08과 겹친다.

## 들여오지 않을 것

- 설계서의 8품목을 '실제 무역상사의 대표 품목 구성'처럼 설명하는 것: 설계서가 스스로 '제안값, 산업 통계나 사용자 확정 수치가 아님'이라 밝힌다. goods.json 수치도 합성값이다.
- '보통 회사들은 품목을 많이 넣지 않는다'를 저장소 근거로 확정하는 것: 저장소에는 실제 무역상사 품목 수에 관한 자료가 없다. 외부 공식 통계로 따로 확인해야 한다.
- 품목 축소 결과를 본 뒤 J4·J7 같은 판정 기준을 옮기는 것: Q14에서 이미 결과를 본 뒤 기준을 바꾼 이력이 있다. 허브도 이를 자기 평가 편향의 위험으로 적었다.
- 태양광 모듈을 한국→베트남 수출 품목으로 되살리는 것: 평택 전환 때 근거가 약해 제외한 결정이 있다.
- 동물·신수 종이나 출신 국가에 품목 보너스를 고정하는 것: 국가 고정 능력 금지 원칙이 있고, 동료 특성은 아직 선언만 있다.
- 실제 선사·서비스 이름(근거표의 장금상선 등)을 게임 안 품목·노선 설명에 쓰는 것: 실명은 sources.json과 근거 블록에만 두고 화면은 가상 선사로 한다는 결정이 있다.
- 커피 사건을 이유로 산지 국가 전체를 같은 기후·생산 조건으로 단정하는 것: 교과 연결 SOC07이 이를 명시적으로 금지한다.

## 출처끼리 어긋나는 점

- 설계서(2절)와 구현 계획 M3 행은 8품목을 전제한다. 실제 시나리오는 5품목만 적재하고 커피·냉동 수산물·태양광은 쓰지 않는다.
- 교과 연결 SOC07은 커피를 'P0' 연결로 표시하고 EV03도 stage P0다. 그런데 P0 시나리오 어디에도 커피 거래가 없어 연결이 실행될 수 없다.
- DECISIONS 124행 M2a 첫 단계 표에는 OFFER_FWD_02가 '태양광 모듈 100개'로 남아 있다. 현재 market_offers.json은 자동차 부품 200상자다. 1002행 재설계 결정이 이를 대체했지만 옛 표는 고쳐지지 않았다.
- RESEARCH_APPLICATION DK-01(2026-10-09)은 '견적은 시작 때 한 번 생기고 3일에 만료'라 적었다. 현재 엔진은 M2a-5 운영 시나리오에서 7일마다 새 묶음을 만든다(engine.ts 856~862행). 문서가 낡았다.
- 인수 명세 개수 표기가 문서마다 다르다. IMPLEMENTATION_PLAN 88행은 26건, STATUS 30행은 45개(거래 37 + 캐릭터 8)다. 실제 파일은 acceptance_cases.json 38건 + character_acceptance_cases.json 8건 = 46건이다.
- STATUS·IMPLEMENTATION_PLAN은 '데이터 JSON 23개'라 적었다. 현재 data/ 폴더에는 market_rules.json을 포함해 24개 파일이 있다.

## 빈칸

- 과제 문구의 작업 트리 변수 ${WT}가 풀리지 않았다. 브랜치 ccr-21863e28-zmusty의 로컬 워크트리(HEAD cf034bb)로 해석했고, GitHub 원격 브랜치에 같은 커밋이 푸시되어 있는지는 미확인이다. URL은 요청 형식에 맞췄으나 원격 내용과의 일치는 미확인이다.
- 시험 수(45개 파일·1,257개)와 검사기 시험 97개는 문서 기록이다. 이번 조사에서 npm test나 validate_data.py를 실행하지 않았다.
- 품목 축소가 J1~J7에 주는 영향은 측정하지 않았다(추정 금지). 비교 실행기로 재야 한다.
- '실제 무역상사는 취급 품목이 좁다'는 사용자 전제는 저장소에 근거가 없어 미확인이다. 무역협회·관세청 등 공식 통계로 확인해야 한다.
- 저장소에는 Democracy 4·Victoria 3·거상 관련 자료가 없다. 사용자 방향의 원작 근거는 이 클러스터에서 다루지 않았다.
- 교과 연결 47개 가운데 품목 단어(커피·의류·전자·상품)를 포함한 6개만 검색했다. 품목 축소의 전체 교과 영향은 정밀 대조하지 않았다.
- DESIGN_v0.4는 목차와 2·7·9·19.2절만 읽었다. 23~28절(도시·문화·주식·동료)은 목차 수준만 확인했다.

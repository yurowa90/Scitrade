# 평택판 기기 점검 측정 (세션 B, 2026-10-12)

세션 C의 요청(허브 전달, 2026-10-12)으로 쟀다. 1차 사용성 시험 빌드가 3판에서 평택판으로 바뀌어(사용자 결정 2026-10-12), `docs/USABILITY_TEST_M2A.md` 8절 기기 점검 단계와 4절 진행자 주의를 고칠 값이 필요하다.

## 측정 방법

- **대상:** 배포된 평택판(https://scitrade-pyeongtaek-test.netlify.app). `/version.txt`는 `5d59ff3`, `tree: clean`이다.
- **사본:** 배포 사이트의 `index.html`·JS·CSS·글꼴 378개·지도 그림·`version.txt`와 Netlify가 끼워 넣는 배지 스크립트(`/.netlify/scripts/hud?variant=public`)를 TLS 검증을 그대로 둔 `curl`로 내려받았다. 글꼴과 지도 그림은 저장소 `5d59ff3`의 `public/`과 바이트까지 같다(라이선스 글 파일만 배포에 없음). 이 사본을 Chromium에서 열었다. 그래서 빌드 표시도 배포본 그대로다.
- **도구:** Chromium 141, Playwright. 프로필 7개는 TASK-0024·0035와 같다. 스크립트는 `pt.js`(①③④⑤), `ptzoom.js`(②), `ptother.js`(배지의 Tab 정지점)다. 저장소 밖 측정기 `kb/blib.js`를 쓴다. 원자료는 `pt7-5d59ff3.jsonl`, `zoom-5d59ff3.json`이다.
- **한계:**
  - Chromium만 쟀다. iPad Safari의 실제 동작(당겨서 새로고침, 떠날 때 확인 창, 배지)은 재지 않았다. 사용자 실기기 확인(D18-1)에서 본다.
  - 브라우저 확대는 ‘CSS 뷰포트 = 창 ÷ 확대, 기기 배율 = 확대’로 흉내 냈다. 1280px 창 높이는 690px로 가정했다(높이는 한 열 판정에 영향이 없다).
  - ⑤는 1일 상태에서 쟀다. 문서가 말하는 T5(13일 무렵)와 날짜가 다르다.

- 배지는 화면에 고정된 iframe이다. 페이지를 맨 아래까지 내리면 그 자리에는 앱 내용이 없다.
- **배지는 Tab 정지점이다.** 1일 첫 화면 정지점 40개 가운데 마지막이 배지(`IFRAME#nl-badge-frame`)다. 숨기면 39개다.
- **숨기는 절차:** 배지를 누르면 350×302px 안내 칸이 오른쪽에 열린다(외부 사이트로 가는 링크와 입력 칸이 있다). 그 안의 ‘Hide this badge’를 누르면 배지 iframe이 사라지고, 기기 저장소에 `nl-hud:public:v1=hidden`이 남는다. 새로고침해도 다시 나오지 않는다(7개 프로필 모두).
- 이 값은 앱의 ‘처음부터 → 저장’과 다른 칸이라 참가자 사이에 지워지지 않는다. 브라우저의 사이트 데이터를 지우면 배지가 다시 나온다.

**문서에 대한 의견:** 2단계(‘숨기지 않으면 오른쪽 아래 내용이나 아래쪽 확인 알림의 일부를 가린다’)는 평택판에서도 맞다. 확인 알림을 가리는 것은 1024·1133px iPad와 한 열 화면뿐이다. 두 가지를 더하기를 권한다. 숨기는 동안 열리는 안내 칸에 외부 링크가 있으니 진행자가 참가자 전에 숨긴다. 숨기지 않으면 Tab 마지막 정지점이 배지다.

## ② 한 열 전환 폭, 확대 비율, 위쪽 막대 (8절 4·5단계)

- **한 열 전환:** CSS 폭 1000px 이하에서 한 열, 1001px 이상에서 세 열이다(999·1000 한 열, 1001·1002 세 열).
- **브라우저 확대(Chrome 단계 100·110·125·150·175·200%):**

| 창 폭 | 100% | 110% | 125% | 150% | 175% | 200% |
|---|---|---|---|---|---|---|
| 1280 | 세 열 | 세 열 | 세 열(CSS 1024) | **한 열**(853) | 한 열 | 한 열 |
| 1366 | 세 열 | 세 열 | 세 열(1092) | **한 열**(910) | 한 열 | 한 열 |

  - 1280px는 133%(CSS 962)에서 이미 한 열이지만, Chrome 확대 단계에는 125%와 150% 사이가 없다. 그래서 문서의 ‘150% 이상이면 한 열’은 Chrome 단계 기준으로 맞다.
- **위쪽 고정 막대(`position: sticky`):**
  - 100%에서 높이 72.3px(마우스)·79px(터치). 문서의 ‘72~79px’은 맞다.
  - 확대하면 화면에서 차지하는 실제 높이가 는다(마우스 기준). 110% 79.5px, 125% 90.4px, 150% 108.5px.
  - 175% 이상에서는 막대가 두 줄로 접혀 CSS 128px, 실제 224~258px이 된다.
  - 맨 위에서는 머리말 아래(위 끝 77.5px, 터치 86.8px)에 있다가, 내리면 화면 맨 위에 붙는다.

**문서에 대한 의견:** 5단계 수치는 그대로 맞다. ‘확대 125%까지는 세 열이 유지되지만 막대가 실제로 90px 정도로 커진다’를 한 줄 더하면, 확대를 바꾼 기기를 진행자가 알아보기 쉽다.

## ③ 당겨서 새로고침, 떠날 때 확인 창 (8절 7단계)

- **당겨서 새로고침:** `html`·`body` 모두 `overscroll-behavior-y: none`(Chromium 계산값).
- **떠날 때 확인 창(`beforeunload`):** 평택판은 **묻는다.** 7개 프로필 모두 같다.

| 상태 | 확인 창 |
|---|---|
| 1일 처음 화면(아무것도 안 함) | 없음 |
| 견적 수락 뒤(오늘 할 일에 명령이 있음) | 뜸 |
| 수락 → 하루 진행 뒤, 아직 저장 안 함 | 뜸 |
| 수락 → 하루 진행 → 저장 직후 | 없음 |

  - `src/ui/main.ts`의 `beforeunload` 처리가 ‘저장하지 않은 일이 있을 때’만 막는다. 탭 닫기로 쟀다. 뒤로 가기·크롬북 ‘뒤로’ 키는 같은 이벤트를 쓰지만 따로 재지 않았다.
  - iPad Safari는 `beforeunload` 확인 창을 띄우지 않는 경우가 많다고 알려져 있다(측정 안 함).

**문서에 대한 의견(고쳐야 함):** 7단계의 ‘이 빌드는 떠나기 전에 묻지 않는다’는 3판 기준이라 평택판에서는 틀리다. 다음처럼 바꾸기를 권한다. ‘노트북·크롬북(Chrome)은 저장하지 않은 진행이 있으면 떠나기 전에 확인 창을 띄운다. 참가자가 확인 창을 보면 취소를 누르게 한다. iPad Safari에서는 뜨지 않을 수 있으니 시험 전에 한 번 확인한다.’

## ⑤ 진행자 주의용 (4절 ‘가로 세 열 배치에서 볼 것’)

**화장품 수락 직후 ‘오늘 할 일’ 제목의 위치(화면 아래 끝 기준):**

| l1366 | cb1366t | ipadAirL | ipadminiL | ipadmini6L | l1920 | t1000 |
|---|---|---|---|---|---|---|
| +331 | +319 | +133 | +120 | +209 | +84 | +111 |

- 모든 프로필에서 화면 밖(아래)이다. 3판 문서의 ‘약 360~640px 아래’보다 가깝다(84~331px).
- 수락하면 화면이 계약 카드 쪽으로 움직인다(수락 뒤 scrollY 1,851~2,098). 위 값은 그 상태 기준이다.
- 평택판은 막대에 ‘오늘 할 일 N건’ 단추(TASK-0024)가 있어, 그것을 누르면 바로 간다. 문서는 이 단추를 말하지 않는다.

**T5 동료 카드를 눌렀을 때:** 7개 프로필 모두 **화면 이동 0px**이다. 누른 카드는 제자리에 남고(위치 차 0~1px), 초점은 ‘○○ 성장·훈련 상세’ 단추로 간다. 3판 문서의 ‘약 900px 움직여 누른 카드가 화면 밖으로 나간다’는 TASK-0024에서 고쳐져 평택판에는 맞지 않다(1일 상태에서 잼).

**Tab 순서(1일 첫 화면, 배지 숨기기 전):** 정지점 40개.
- 세 열 6개 프로필: 건너뛰기 2 → 머리말 6 → 막대 2 → 거래·계약 9 → 동료 16 → 오늘 할 일 1 → 지도 2 → 기록 1 → 배지 1.
- 한 열(t1000): 거래·계약 다음이 오늘 할 일 → 동료 → 지도 → 기록 → 배지(보이는 순서).
- 세 열에서는 거래·계약을 따라 약 2,000px 내려갔다가 동료에서 맨 위로 돌아오고, 다시 2,500~2,700px로 내려간다. 한 바퀴의 스크롤 이동 합은 6,000~6,900px다.

**문서에 대한 의견(고쳐야 함):**
- ‘지도(맨 아래) → 동료 → 거래·계약 순서로 화면이 크게 오간다’는 3판 순서다. 평택판은 ‘거래·계약 → 동료 → 오늘 할 일 → 지도’ 순서이고, 거래·계약 끝에서 동료로 갈 때 맨 위로 크게 올라간다.
- ‘오늘 할 일’ 거리는 ‘약 80~330px 아래’로 바꾸고, 막대의 ‘오늘 할 일 N건’ 단추를 쓰는지도 관찰 항목에 더한다.
- T5의 900px 이동 주의는 지운다.

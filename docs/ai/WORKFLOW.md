# 코드 세션 작업 지침

이 파일은 이 게임 프로젝트의 구현 범위를 정리한 작업 지침이다. 사용자 지시와 실제 저장소의 상위 지침이 우선한다.

## 시작

README의 읽기 순서를 따른다. 현재 세션의 구현 단계를 명시하고, 기존 저장소가 있으면 상태·의존성·테스트를 확인한다. 현재 브랜치의 실제 구현은 STATUS.md와 코드로 확인한다. 자료 작성 당시의 미구현 설명이나 참고 연구의 단계명을 현재 구현 상태로 간주하지 않는다.

## 상태와 시간

- 경제 상태의 소유자는 UI와 분리된 단일 엔진이다. DOM·React·Phaser 상태에 별도 현금·재고를 두지 않는다.
- 일자 시작의 정보 공개와 입력, 실행·결산의 경계를 유지한다. 화면 열기·대화 다시 읽기는 시간을 진행시키지 않는다.
- 같은 상태·명령·시드·버전은 같은 결과를 낸다. 모듈별 난수 흐름을 분리하고 미래 사건은 공개 정보에 섞지 않는다.
- 명령과 사건은 고유 ID를 가진다. 중복 실행으로 돈·화물·보상이 생기지 않게 한다.

## 돈·물류·사람

- 화폐는 통화와 정수 최소 단위로 저장한다. JSON의 USD amount는 달러 표시값이므로 로더에서 cents로 한 번만 변환한다. KRW는 원 정수다.
- 고객 화물과 회사 재고를 구분한다. 상품 대금과 운송주선 매출을 합치지 않는다.
- 인도·매출·채권·수금, 현금·영업손익·투자평가를 구분한다.
- 같은 돈·직원·창고·운송 용량을 중복 예약하지 않는다.
- 지역 지식·인물 친밀·거래 신뢰를 구분한다. 출입 반복 보상과 국가 전체 호감도 자동 상승은 만들지 않는다.
- 직원의 현지 활동에는 위치·소요 시간·업무 공백을 반영한다. 지도 선택이 물리적 이동이 되지 않는다.

## 자료·범위

- `DESIGN` fixture는 실측 자료가 아니다. `null`인 HS 코드·계수를 0이나 임의 실측값으로 대체하지 않는다.
- 구조화 콘텐츠의 `command_template`은 설계용 명령 제안이다. 실행 엔진의 구현 계약을 먼저 고정한다.
- 원문의 관찰, 설계 해석, 미확인 사항을 구분한다. 원작 외형이나 자산을 복제하지 않는다.
- 통계 수집·최신 기준 확인은 별도 작업으로 기록한다. 실제 API 수집을 하지 않았다면 했다고 쓰지 않는다.
- P1 주식과 P2 IPO는 M1에 끼워 넣지 않는다. IPO 신주·구주·희석·회사 현금은 검산 후 구현한다.

## 완료 보고

작업 하나마다 입력·출력·사용자 행동·완료 조건을 적는다. 의미 있는 경제·상태 위험을 검증하고, 표현만 바뀐 저위험 수정에 불필요한 테스트를 늘리지 않는다. 실제 실행한 검증과 아직 안 한 플레이테스트·현실 보정을 구분한다.

## v0.4 캐릭터·조직 규칙

- 캐릭터 카드 정의와 실제 고용된 직원 상태를 분리한다. P1 원안6종은 자동 고용하지 않는다.
- M1에서는 기존 거래 처리량을 유지한다. CHARACTER_WEIGHTED 모드에서만 능력·시너지를 계산한다.
- 경험치·강화 보상은 직원별 사건ID로 한 번만 처리하며 최종 능력은 원값·레벨·강화로 재계산한다.
- 조직 소속·편성안 저장은 시간 예약이 아니다. 업무·교육·강화 확정 시 직원 시간표를 하나의 예약 체계로 검증한다.
- 시너지는 업무별10%까지, 시설의 남은 처리 용량은 마지막에 적용한다. 가격·관세·선박 속도·물리적 적재 용량에 곱하지 않는다.
- 캐릭터 고유 특성의 평가점수 +5는 P1 검토 후보이며 P0에서 적용하지 않는다.
- 직원ID는 기존 EMP01~06을 보존하고 이름은 동물·신수 별칭으로 표시한다. 모티프를 실제 국가 국민성이나 전통 신화의 확정 설명으로 쓰지 않는다.

## Claude·Codex 공동 작업과 상태 관리

- AGENTS.md와 CLAUDE.md는 이 공통 규칙과 STATUS.md를 안내하는 진입 파일이다. 도구별로 다른 경제 규칙·진행 현황을 만들지 않는다.
- 작업 시작 때 실제 파일·Git 상태·현재 구현을 읽는다. 다른 세션의 미완료 변경은 덮어쓰지 않는다.
- 한 번에 구현할 단계를 정하고 입력·출력·완료 조건을 명시한다. 첫 단계는 M1의 정상·취소·지연 거래다.
- 작업 끝에는 STATUS.md에 실제 변경과 실행한 검증, 남은 위험과 다음 단계를 기록한다. 실행하지 않은 인수 기준을 통과로 표시하지 않는다.
- 문서·데이터를 변경하면 `python3 tools/build_package.py --manifest-only` 후 `python3 tools/validate_data.py`로 관련 파일 해시를 갱신·확인한다.
- 배포 묶음은 `python3 tools/build_package.py`로 만든다. 생성된 ZIP·임시 파일·원본 광고 영상·원작 자산은 Git에 추가하지 않는다.
